# GraspLink를 쉽게 이해하기

GraspLink는 HCR-12A 로봇 팔과 2F-85 그리퍼가 움직이는 모습을 보여 주는 시뮬레이터다. 화면의 로봇 모양과 충돌 계산용 모양은 따로 관리한다. 지금 지원하는 로봇이나 물리 동작은 실제 장비의 안전과 성능을 보장하지 않는다.

## 로봇이 움직이는 순서

```text
사용자 명령
→ SimRobotController가 관절 목표를 계산
→ RobotKinematics가 링크와 공구 끝의 위치를 계산
→ 화면 모델과 충돌용 모양을 갱신
→ Jolt가 상자 같은 물체의 충돌과 움직임을 계산
```

`SimRobotController`는 관절 상태와 이동 명령을 관리한다. `RobotKinematics`는 관절각으로 로봇 자세를 계산한다. 변환 어댑터는 그 자세를 화면 모양과 충돌용 모양에 각각 적용한다. `ViewerApp`은 이 모듈들을 만들고 실행 순서와 종료 순서를 관리한다.

위치는 로봇 기준 좌표(`Robot base`)로 계산한다. 장면 전체에서 로봇을 옮기는 값은 `World` 좌표다. 화면에 보이는 상세 메시와 충돌 계산에 쓰는 단순한 모양(`collision proxy`)도 서로 다른 자료다.

## DLS 역기구학을 쓰는 이유

TCP는 공구 끝의 작업 위치와 방향이다. 사용자가 TCP 목표를 주면 역기구학(IK)이 그 목표를 만들 관절각을 찾는다. 정방향 기구학(FK)은 반대로 관절각에서 TCP 위치를 계산한다.

해석 IK는 특정 로봇의 관절 배치와 치수에 맞춰 수식을 미리 만든다. 다른 팔 구조에 같은 수식을 바로 쓸 수는 없다. Damped Least Squares(DLS)는 현재 관절각에서 FK를 계산하고, 각 관절을 조금 움직였을 때 TCP가 바뀌는 정도(야코비안)를 이용해 관절각을 조금씩 고친다. 관절 수가 달라져도 직렬 회전 관절 모델이면 같은 계산 절차를 재사용할 수 있어 이 프로젝트에 맞다. damping은 팔이 펴지는 등 움직이기 어려운 자세에서 관절 변화량이 갑자기 커지는 일을 줄인다.

현재는 모델 자료가 코드에 정의되어 있으며 HCR-12A 직렬 회전 관절만 사용한다. 자유도 수를 담는 자료형과 IK 계산은 가변 길이를 지원하지만, 임의 URDF 파일, 직선 관절, 가지가 갈라지는 팔, 듀얼 암을 자동으로 불러오는 기능은 없다. DLS도 모든 목표의 해를 찾거나 충돌을 피한다고 보장하지 않는다. 즉, DLS는 다양한 로봇을 위한 유연한 방법이지만 유일한 IK 방법은 아니다.

## MoveJ, MoveL과 물리

`MoveJ`는 관절각 사이를 이동한다. 경로가 막히면 현재 구현은 요청을 거부한다. `MoveL`은 TCP가 위치상 직선을 따라가도록 중간 자세를 만들고, 각 자세의 IK와 관절 경로를 확인한다. 요청을 받았다는 것, 계획을 끝냈다는 것, 목표에 도착했다는 것은 서로 다른 상태다. 충돌 검사도 경로 표본마다 하므로 표본 사이 모든 점이 안전하다는 수학적 증명은 아니다.

화면 갱신 간격과 관계없이 시뮬레이션은 4 ms씩 진행한다. 이는 계산에 쓰는 시간 간격이며 실제 기기가 250회/초로 움직인다는 보장은 아니다. 경로를 계획하는 동안에는 물리 갱신을 잠시 멈추고, 계획이 끝나면 시뮬레이션을 이어 간다.

물리 역할도 구분한다. 바닥은 움직이지 않는 `Static`, 로봇 팔은 코드가 목표를 정하는 `Kinematic`, 상자는 충돌 결과에 따라 움직이는 `Dynamic` 물체다. 그리퍼는 손끝 접촉으로 닫힘을 멈추고, 양쪽 손끝이 같은 물체를 잡으면 constraint로 연결한다. 실제 마찰에 따른 파지력, 관절 토크와 로봇 동역학은 계산하지 않는다.
