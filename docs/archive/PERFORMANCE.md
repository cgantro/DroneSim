# 성능 기록

아래 숫자는 기록에 적힌 이전 Release 실행 파일에서 측정했다. 이번 단순화로 `--profile-ticks`, `--pick-place-stress`, `--seed` 옵션을 제거했기 때문에 현재 실행 파일에서는 같은 측정을 다시 시작할 수 없다. 결과는 과거 기록으로만 읽는다.

이번 리팩터링 뒤 고정 틱 성능은 **NOT RUN**이다. 제거한 계측 옵션을 다시 넣지 않고는 현재 Viewer의 같은 성능 수치를 얻을 수 없다.

## 4 ms 고정 틱

2026-10-20에 MSVC 19.50 Release 빌드로 정지 장면을 10,000 tick씩 세 번 실행했다. tick 계산 시간은 p50 **0.739–0.744 ms**, p95 **0.797–0.830 ms**, p99 **0.883–0.928 ms**였다. 30,000회 중 계산이 4 ms를 넘은 횟수는 0회였다.

실제 tick 시작 간격 p95는 **4.675–4.772 ms**, 최댓값은 **10.741–14.386 ms**였다. 계산이 대체로 4 ms 안에 끝났다는 뜻이지, 실제 250 Hz 주기를 보장한다는 뜻은 아니다. 로봇 이동과 경로 계획은 이 장면에 포함하지 않았다. 원시 출력과 실행 파일 정보는 [측정 자료](../benchmarks/results/fixed_tick_release_2026-10-20.json)에 있다.

## 픽앤플레이스와 알고리즘 기록

같은 Release 실행 파일에서 seed 1, 2, 3으로 각 50회 실행해 총 150회 성공했다. 미션 시간은 p50 **1,478 ms**, p95 **1,963 ms**, p99 **2,561 ms**, 최댓값 **2,592 ms**였다. 이 결과는 고정된 세 seed의 표본이지 일반적인 성공 확률이 아니다. 원시 기록은 [요약 파일](../benchmarks/results/pick_place_release_2026-10-20.json)에 있다.

2026-10-19에는 2026-10-15 빌드의 Debug 실행 파일로 50회 모두 성공했다(210.76초). 예전 `--pick-place-stress` 모드로 만든 기록이라 현재 실행 파일에서 재현할 수 없고 Release 결과와 직접 비교할 수도 없다.

이전 DLS IK 벤치마크는 solve당 **4.354 μs**, 동기 `LinearPathPlanner`는 path당 **46.676 μs**였다. `JoltMoveJCollisionPath` 결과는 우회 경로를 사용하던 이전 구현에서 나온 값이므로 현재 직접 경로 검사와 비교할 수 없다. 상세 값과 빌드 hash는 [벤치마크 기록](../benchmarks/results/robotics_benchmarks_release_2026-10-20.json)에서 확인한다.

측정 전 기준선이 없어 최적화 전후 개선율은 계산하지 않았다. 정지 장면 측정만으로 로봇 동작 중 성능이나 실제 시간 기준 250 Hz를 주장하지 않는다.
