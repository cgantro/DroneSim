# 구조 안내

## 데이터 흐름

지상통제 프로그램과 JSON 시나리오는 같은 드론 모의 코어에 명령을 보냅니다. 그래픽 프로그램은 코어가 갱신한 상태를 읽어 두 시점으로 그립니다.

```text
지상통제 ─ UDP ─┐
                ├─ 명령 검사 → 드론·카메라 모의 → 상태·시험 결과
시나리오 ───────┘                         ├─ 관찰자 화면
                                          └─ EO 카메라 화면
```

게임패드 입력도 드론 상태를 직접 바꾸지 않습니다. GLFW 축 값을 월드 좌표 속도 명령으로 바꾼 뒤 고정 Tick에서 SimulationCore에 적용합니다. 지상통제 명령이 들어오면 해당 실행에서는 게임패드 입력을 멈춥니다.

## 모의 Tick

드론 위치는 미터, 속도는 초당 미터, 방향각은 라디안으로 저장합니다. 모의 좌표는 Z축이 위쪽이고, 화면 좌표는 Y축이 위쪽입니다. 그릴 때 두 좌표계의 축을 바꿉니다.

모의는 1/60초 간격으로 한 단계씩 진행합니다. 화면이 잠깐 늦어져도 한 번에 따라잡는 시간은 100ms로 제한합니다. 현재 드론은 명령한 속도와 위치만 계산하며, 바람·모터 추력·공기 저항은 반영하지 않습니다.

## UDP 명령

시뮬레이터는 화면 반복문에서 non-blocking UDP 소켓을 확인합니다. 소켓이 데이터를 기다리며 화면이나 모의를 멈추지 않습니다. 명령은 다음 고정 Tick 직전에 적용합니다.

메시지에는 형식 버전, 메시지 종류, 내용 길이, 명령 ID와 순번이 있습니다. 수신할 때 허용 크기와 필수 값, 순번을 확인합니다. 같은 명령을 다시 받으면 재적용하지 않고 마지막 응답을 돌려줍니다. 이전 순번은 거부합니다. 외부 명령은 한 번에 하나씩 처리하며, 명령 응답에 드론·카메라 상태와 적용 Tick을 담습니다.

지상통제 프로그램은 같은 명령을 400ms 간격으로 다시 보내며 최대 4초 동안 응답을 기다립니다. 응답이 없으면 시간 초과를 표시합니다. 통신은 IPv4 UDP이며, 암호화·인증이나 여러 지상국의 동시 제어는 지원하지 않습니다.

## 카메라와 화면

카메라 상태는 Active, Disabled, Fault로 나뉩니다. Active일 때만 모의 Tick마다 프레임 번호가 증가합니다. Disabled나 Fault에서는 오른쪽 화면에 새 영상을 그리지 않습니다. 복구하면 다음 Tick부터 다시 프레임을 셉니다.

오른쪽 화면은 OpenGL 장면을 기체의 시점으로 다시 그린 결과입니다. 화면을 그린 뒤 오른쪽 영역의 RGB 픽셀을 읽고, 위에서 아래로 읽는 영상 순서에 맞춰 정리해 모의 Tick과 함께 메모리에 둡니다. 파일 저장과 영상 분석은 아직 연결하지 않았습니다. 지면·건물·드론은 코드에서 만든 단순 도형입니다.

## 시나리오와 장애 재현

시나리오 명령은 Tick 번호에 맞춰 반복 재생합니다. `delay_ticks`, `drop`, `duplicate` 값으로 명령 전달 지연·손실·중복을 재현하고, `camera_events`로 센서 끄기·고장·복구를 예약합니다. 결과에는 최종 상태, 예상값 비교, 장애 이벤트 기록이 들어갑니다.

이 장애는 시나리오 안에서 결정적으로 재현하는 시험 조건입니다. 실제 UDP 패킷이 네트워크에서 유실되는 현상을 강제로 만들지는 않습니다.

## 자원과 실행

앱이 UDP 소켓, 창, 렌더러, 카메라와 GPU 자원을 소유합니다. 별도 수신 스레드는 두지 않았습니다. 창을 닫으면 GPU 자원을 창의 OpenGL 실행 환경보다 먼저 해제하고, UDP 소켓도 함께 닫습니다.
