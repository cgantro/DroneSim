# 구조 안내

## 데이터 흐름

지상통제 프로그램과 JSON 시나리오는 같은 드론 모의 코어에 명령을 보냅니다. 그래픽 프로그램은 코어가 갱신한 상태를 읽어 두 시점으로 그립니다. 입력 기록은 명령과 적용 Tick을 메모리에 보관하고, 재생할 때 모의를 초기화한 뒤 같은 Tick에 다시 적용합니다.

```text
지상통제 ─ UDP ─┐
                ├─ 명령 검사 → 드론·카메라 모의 → 상태·시험 결과
시나리오 ───────┘                         ├─ 관찰자 화면
                                          └─ EO 카메라 화면
```

게임패드 입력도 드론 상태를 직접 바꾸지 않습니다. GLFW 축 값을 월드 좌표 속도 명령으로 바꾼 뒤 고정 Tick에서 SimulationCore에 적용합니다. 지상통제 명령이 들어오면 해당 실행에서는 게임패드 입력을 멈춥니다.

## 모의 Tick

드론 위치는 미터, 속도는 초당 미터, 방향각은 라디안으로 저장합니다. 모의 좌표는 Z축이 위쪽이고, 화면 좌표는 Y축이 위쪽입니다. 그릴 때 두 좌표계의 축을 바꿉니다.

모의는 1/60초 간격으로 한 단계씩 진행합니다. 화면이 늦어진 뒤에도 한 번에 따라잡는 시간은 100ms, 최대 6 Tick으로 제한합니다. 그보다 오래 멈췄다면 초과한 시간은 버립니다. 화면이 밀린 시간을 무한정 따라가며 멈추는 일을 막지만, 모의 시간은 실제 시계보다 늦어질 수 있습니다. 현재 드론은 명령한 속도와 위치만 계산하며, 바람·모터 추력·공기 저항은 반영하지 않습니다.

### 속도에서 위치를 구하는 법

속도는 위치 변화량을 시간으로 나눈 값입니다. 한 Tick 동안 속도가 거의 일정하다고 보고, 현재 위치를 `pₖ`, 다음 위치를 `pₖ₊₁`, 속도를 `vₖ`, Tick 간격을 `Δt`라고 두면 다음과 같습니다.

```text
vₖ ≈ (pₖ₊₁ - pₖ) / Δt
pₖ₊₁ = pₖ + vₖ × Δt
```

코드에서는 이를 매 Tick 적용합니다. Tick 간격은 1/60초이므로, 초당 5m로 이동하는 명령은 한 Tick에 약 0.083m 이동합니다. 이 계산은 미분 방정식을 작은 시간 간격으로 근사하는 전진 오일러 방식입니다. 계산량이 적고 동작을 따라가기 쉽지만, 가속도나 바람처럼 속도를 바꾸는 힘은 모델에 넣지 않았습니다.

경유점 명령은 현재 위치에서 목표점까지의 방향을 구하고, 그 방향으로 초당 최대 5m 이동하도록 속도를 정합니다. 남은 거리가 한 Tick 이동 거리나 5cm 허용 오차보다 짧으면 목표 위치에 맞춰 멈춰 지나치지 않게 합니다. 방향각도 같은 방식으로 `현재 방향각 + 회전 속도 × Tick 간격`만큼 바뀝니다.

## UDP 명령

시뮬레이터는 화면 반복문에서 non-blocking UDP 소켓을 확인합니다. 소켓이 데이터를 기다리며 화면이나 모의를 멈추지 않습니다. 명령은 다음 고정 Tick 직전에 적용합니다.

메시지에는 형식 버전, 메시지 종류, 내용 길이, 명령 ID와 순번이 있습니다. 수신할 때 허용 크기와 필수 값, 순번을 확인합니다. 같은 명령을 다시 받으면 재적용하지 않고 마지막 응답을 돌려줍니다. 이전 순번은 거부합니다. 외부 명령은 한 번에 하나씩 처리하며, 명령 응답에 드론·카메라 상태와 적용 Tick을 담습니다.

지상통제 창은 클라이언트 UDP 소켓 하나를 소유하고 창이 열려 있는 동안 재사용합니다. 버튼에서 만든 명령은 통신 코드로 보내며, 같은 명령을 400ms 간격으로 다시 보내고 최대 4초 동안 응답을 기다립니다. 기다리는 동안 화면은 계속 동작하지만 명령 버튼은 잠깐 비활성화됩니다. 한 요청만 소켓을 사용하게 해 동시 접근을 막고, 창을 닫을 때 진행 중인 요청이 끝난 뒤 소켓을 정리합니다. 응답이 없으면 화면에 시간 초과를 표시합니다. 통신은 IPv4 UDP이며, 암호화·인증이나 여러 지상국의 동시 제어는 지원하지 않습니다. 자동 시험은 재전송과 서버의 명령 처리를 확인하고, 창의 비행·카메라·기록 버튼으로 명령을 보내 실제 시뮬레이터 상태가 바뀌고 기록을 재생하는지도 확인합니다.

입력 기록은 지상통제 창의 시작·정지·재생 명령으로 다룹니다. 기록 중에는 허용된 게임패드 입력과 지상통제 비행 명령, 그리고 적용 Tick을 보관합니다. 재생은 현재 드론 상태를 초기화한 뒤 각 명령을 원래 Tick에 적용합니다. 기록 자료는 시뮬레이터 메모리에만 있으며 파일로 저장하지 않습니다. 재생은 기록된 명령만 되풀이하며 센서 상태나 외부 환경을 별도로 저장하지 않습니다.

## 카메라와 화면

카메라 상태는 Active, Disabled, Fault로 나뉩니다. Active일 때만 모의 Tick마다 프레임 번호가 증가합니다. Disabled나 Fault에서는 오른쪽 화면에 새 영상을 그리지 않습니다. 복구하면 다음 Tick부터 다시 프레임을 셉니다.

오른쪽 화면은 OpenGL 장면을 기체의 시점으로 다시 그린 결과입니다. 화면을 그린 뒤 오른쪽 영역의 RGB 픽셀을 읽고, 위에서 아래로 읽는 영상 순서에 맞춰 정리해 모의 Tick과 함께 메모리에 둡니다. 새 영상이 생기면 OpenCV가 회색 영상으로 바꾼 뒤 평균 밝기·대비·선명도를 계산합니다. 지면·건물·드론은 코드에서 만든 단순 도형입니다.

화면 앱은 다음 프레임을 읽을 때 같은 픽셀 버퍼를 다시 씁니다. 현재는 같은 스레드에서 분석을 끝낸 뒤에만 버퍼를 재사용하며, OpenCV 입력 영상은 픽셀을 복사하지 않고 잠시 빌려 씁니다. OpenCV 영상은 원본 주소만 기억하므로 원본 프레임이 살아 있고 픽셀 저장 공간이 바뀌지 않을 때만 사용할 수 있습니다.

분석기는 RGB를 회색 영상으로 바꾸고 평균 픽셀 값으로 밝기를, 표준편차로 대비를 계산합니다. 이어 회색 영상에서 라플라시안을 구하고 그 분산을 선명도 추정값으로 사용합니다. 라플라시안 분산은 경계와 세부 묘사가 많을수록 커지는 경향이 있지만, 노이즈도 같은 값을 키웁니다. 그래서 이 값만으로 초점이나 전체 화질을 판정할 수는 없습니다. 분석기는 회색 영상과 라플라시안 작업 공간을 보관해 다음 프레임에서도 재사용합니다.

분석을 별도 스레드로 옮겨 촬영과 동시에 진행하려면 프레임 버퍼의 소유권도 함께 넘겨야 합니다. 이때 `std::move`로 프레임을 분석 쪽에 전달하면 픽셀을 복사하지 않을 수 있습니다. 촬영 쪽은 다음 영상을 담을 별도 버퍼가 필요합니다. 현재는 별도 분석 스레드나 버퍼 풀이 없으므로 동기 방식으로 유지합니다.

## 시나리오와 장애 재현

시나리오 명령은 Tick 번호에 맞춰 반복 재생합니다. `delay_ticks`, `drop`, `duplicate` 값으로 명령 전달 지연·손실·중복을 재현하고, `camera_events`로 센서 끄기·고장·복구를 예약합니다. 결과에는 최종 상태, 예상값 비교, 장애 이벤트 기록이 들어갑니다.

이 장애는 시나리오 안에서 결정적으로 재현하는 시험 조건입니다. 실제 UDP 패킷이 네트워크에서 유실되는 현상을 강제로 만들지는 않습니다.

## 자원과 실행

시뮬레이터는 서버 UDP 소켓, 창, 렌더러, 카메라와 GPU 자원을 소유합니다. 지상통제 창은 별도의 클라이언트 UDP 소켓을 소유합니다. 시뮬레이터에는 별도 수신 스레드를 두지 않았습니다. 창을 닫으면 진행 중인 지상통제 요청을 마친 뒤 소켓을 닫고, 시뮬레이터에서는 GPU 자원을 창의 OpenGL 실행 환경보다 먼저 해제합니다.
