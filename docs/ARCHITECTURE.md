# 구조 안내

## 전체 흐름

현재 화면의 자동 시연이 드론 명령을 보냅니다. 모의 코어는 명령을 확인하고 1/60초마다 드론 상태를 갱신합니다. 화면은 그 상태를 읽어 관찰 시점과 기체 탑재 카메라 시점을 각각 그립니다. 지상통제 연결은 다음 구현 단계입니다.

```text
명령 → 드론 모의 코어 → 위치·속도·방향 → 화면 그리기
                              ├ 관찰자 화면
                              └ 탑재 카메라 화면
```

## 모의 시간

드론 모형은 위치를 미터, 속도를 초당 미터, 방향을 라디안으로 저장합니다. 현재 좌표에서는 Z축이 위쪽입니다. 화면 그래픽은 Y축을 위쪽으로 쓰므로, 화면에 그릴 때 좌표를 바꿉니다.

렌더링 프레임은 컴퓨터 성능에 따라 간격이 달라집니다. 드론 상태는 고정된 1/60초 단위로만 바꿔 두 실행의 계산 순서를 맞춥니다. 한 프레임이 늦어져도 모의를 한 번에 최대 100ms까지만 따라잡습니다.

현재 운동 모형은 명령한 속도를 제한한 뒤 위치에 더하는 단순한 계산입니다. 공기 저항, 바람, 모터 추력, PID 제어는 계산하지 않으므로 실제 비행을 예측하는 데 쓰면 안 됩니다.

## 화면과 카메라

화면은 왼쪽에 드론 주변을 바라보는 시점, 오른쪽에 기체 앞쪽에서 진행 방향을 바라보는 70도 시야각의 RGB 화면을 표시합니다. 두 화면은 같은 모의 상태와 주변 도형을 사용합니다.

현재 드론·건물·지면은 코드에서 만든 단순 상자입니다. GLB 모델 읽기, 영상 파일 기록, 센서 활성·고장 상태는 아직 연결하지 않았습니다. 오른쪽 화면은 OpenGL로 그린 카메라 시점이며 별도 영상처리 경로는 아닙니다.

## 객체 수명

앱이 창과 렌더러, 카메라, GPU Mesh·Shader·Material을 소유합니다. GPU 자원은 창의 OpenGL 실행 환경을 필요로 하므로 앱이 닫힐 때 GPU 자원을 먼저 해제하고 창을 마지막에 닫습니다.

## 다음 연결

지상통제와 게임패드는 드론 위치를 직접 바꾸지 않고 같은 명령 입력 경로를 사용해야 합니다. UDP 연결이 추가되면 수신 스레드는 메시지만 검증하고, 실제 명령은 다음 모의 Tick에서 적용해 시뮬레이션 상태의 소유자를 하나로 유지합니다.
