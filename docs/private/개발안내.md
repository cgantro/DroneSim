## 지금 만드는 프로그램

AeroSimLab은 가상 드론의 비행, 화면, 카메라 픽셀 처리, 지상통제 명령을 시험합니다. 화면 앱은 Jolt 강체 물리와 모터·로터 모델을 사용하고, 화면 없는 시나리오는 운동학 모델을 기본으로 사용합니다. 강체 계산은 공개 시뮬레이터의 설정을 바탕으로 하며 실제 비행으로 검증하지 않았습니다.

## 어디서 시작할까

처음 코드를 볼 때는 화면에 보이는 동작 하나를 고르고, 입력이 계산을 거쳐 화면이나 응답으로 나오는 길을 따라가면 됩니다.

1. **비행 동작:** 속도·위치·비행 상태가 한 번의 고정된 시간 간격마다 어떻게 바뀌는지 봅니다.
2. **화면:** 계산된 위치와 자세를 주변 화면 및 기체 카메라 화면에 옮기는 과정을 봅니다.
3. **조종 입력:** 게임패드나 지상통제 명령이 비행 동작으로 바뀌는 과정을 봅니다.
4. **카메라 분석:** 화면에서 만든 RGB 픽셀을 밝기·대비·선명도 값으로 요약하는 과정을 봅니다.

코드도 이 역할에 따라 나뉘어 있습니다. 비행 계산, 화면 그리기, 명령 통신, 게임패드 입력, 카메라 데이터와 분석이 각각 묶여 있습니다. 처음부터 모든 코드를 읽기보다 수정하려는 동작의 입력과 결과를 먼저 찾으세요.

## 폴더 구성

| 경로 | 역할 |
| --- | --- |
| `apps/simulator/` | 그래픽 시뮬레이터와 웹 셸. 웹 셸 파일은 `web/` 아래 둡니다. |
| `apps/headless/` | 화면 없이 시나리오를 실행하는 프로그램 |
| `apps/ground_control/` | 지상통제 프로그램과 UDP 클라이언트 |
| `modules/simulation_core/` | 드론·카메라 모델과 시나리오 실행 |
| `modules/graphics/` | 카메라, 셰이더, 메시와 화면 그리기 |
| `modules/terrain/` | 지형 격자 파일을 읽고 위도·경도를 지역 좌표로 바꿈 |
| `modules/communication/`, `modules/manual_control/` | 통신과 수동 조종 입력 |
| `modules/sensor/`, `modules/vision/` | 카메라 프레임과 영상 지표 |
| `assets/shaders/` | 화면 셰이더 |
| `assets/maps/` | 북한산 SRTM 높이 격자와 자료 출처 |
| `assets/models/drones/` | 향후 드론 형상·제원 자료 위치. 현재 모델 자산은 없음 |
| `scenarios/flight/`, `scenarios/fault-injection/` | 단일 드론 정상 비행과 장애 시나리오 |
| `scenarios/multi-drone/` | 향후 협동 시나리오 위치. 현재 실행 가능한 시나리오는 없음 |
| `tests/` | 모듈별 단위 시험과 시나리오 통합 시험 |

시나리오 파일을 옮기면 CMake의 CTest 경로도 함께 갱신합니다. 지형은 구현됐지만 도로·건물·작은 장애물 정보는 포함하지 않습니다. 실제 기체 형상과 다중 드론 동작은 아직 구현되지 않았습니다.

## 지금까지 정리한 내용

- 프로젝트의 중심을 로봇 팔에서 가상 드론과 지상통제 시험으로 옮겼습니다.
- 모의 계산은 초당 60번 고정된 간격으로 진행합니다. 화면 그리기와 계산 간격은 분리했습니다.
- 주변을 보는 화면과 드론 카메라 화면을 함께 표시합니다.
- 지상통제 창과 UDP 통신으로 이륙·이동·착륙·카메라 명령을 보냅니다.
- 통신 지연·손실과 카메라 고장 상황을 JSON 시나리오로 재현합니다.
- RGB 화면의 밝기·대비·선명도를 계산합니다. 이 값은 간단한 지표이며 실제 영상 품질 판정은 아닙니다.
- 지상통제 창을 자동으로 누르던 PowerShell 시험을 제거했습니다. 따라서 창과 시뮬레이터를 함께 확인하는 자동 시험은 현재 없습니다.
- 사용 안내와 내부 개발 안내를 나누고, 기본 빌드 선택을 Release 하나로 줄였습니다.

## 확인 상태

2026년 10월 22일 Release 구성에서 전체 빌드가 끝났고 CTest 39개가 통과했습니다. 여기에는 실제 높이 격자의 충돌 시험과 Viewer 시작 시험이 포함됩니다. 이 수치는 해당 날짜의 실행 결과이며 이후 변경을 검증하지는 않습니다.

별도 확인에서는 실제 시뮬레이터를 숨김 시험 모드로 실행하고 지상통제 클라이언트로 이륙 명령을 보냈습니다. 응답은 `applied`, 왕복 시간은 14 ms였습니다. 화면 자원은 실행 위치에서 읽으므로 시뮬레이터를 빌드 결과가 있는 폴더에서 시작해야 합니다.

창의 버튼을 자동으로 누르는 시험은 없습니다. 자동 UDP 시험은 실제 시뮬레이터 대신 같은 메시지 규칙을 쓰는 로컬 응답기를 사용합니다. 따라서 화면 버튼과 실제 시뮬레이터 프로세스까지 이어지는 전체 흐름은 자동으로 확인하지 않습니다. 이전에 제기된 창 프로그램만의 시간 초과 문제도 아직 재현하지 못했습니다.

## 성능 기록

보관된 측정 한 건은 Windows Release, 1280×720 화면, Intel Core i5-13600KF, NVIDIA GeForce RTX 3060 Ti에서 수행했습니다. 숨김 창에서 5초씩 세 번 측정했으며, 단순한 도형과 드론 한 대를 사용했습니다.

| 항목 | 당시 측정값 |
| --- | ---: |
| 비행 계산 한 번의 시간 p95 | 약 0.4~0.5 µs |
| 카메라 영상 분석 시간 p95 | 약 1.31~1.34 ms |
| 숨김 창 그리기 속도 | 약 394~398 FPS |

숨김 창의 FPS는 사용자가 보는 실제 화면 속도가 아닙니다. 이 기록만으로 이전 로봇 프로그램보다 빨라졌다고 비교할 수도 없습니다. 조건이 같은 새 측정 결과가 생기기 전까지는 기준 자료로만 취급합니다.

## 아직 구현되지 않은 목표와 범위 밖인 일

- 건물·시설 자료와 지도 기반 경로·가시성·장애물 판정
- 출처가 있는 제원과 참조 데이터로 검증하는 실제 기체에 가까운 드론 모델
- 여러 드론의 임무 분담·상태 공유·충돌 위험 처리와 통신 장애 시나리오
- 실제 드론 제어와 비행 안전성 입증
- 실제 EO 영상 입력·저장과 AI 추론
- 실제 게임패드 조합 전체와 외부 네트워크 환경
- 지상통제 창 버튼 조작의 자동 시험

기능을 더하기 전에는 이 목록과 기존 동작을 확인해, 이미 구현된 것으로 오해하지 않게 안내를 고칩니다.
