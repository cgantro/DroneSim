# 개발 이어가기

이 글은 현재 작업 상태와 다음에 볼 곳을 정리한 내부 메모입니다. 내부 문서는 공개 사용자 안내의 필수 조건이 아닙니다.

## 지금 만드는 프로그램

AeroSimLab은 가상 드론의 비행, 화면, 카메라 픽셀 처리, 지상통제 명령을 시험합니다. 드론의 위치와 속도를 단순한 규칙으로 계산합니다. 실제 공기역학·모터·센서 동작을 재현하는 비행 물리 엔진은 아닙니다.

## 어디서 시작할까

처음 코드를 볼 때는 화면에 보이는 동작 하나를 고르고, 입력이 계산을 거쳐 화면이나 응답으로 나오는 길을 따라가면 됩니다.

1. **비행 동작:** 속도·위치·비행 상태가 한 번의 고정된 시간 간격마다 어떻게 바뀌는지 봅니다.
2. **화면:** 계산된 위치와 자세를 주변 화면 및 기체 카메라 화면에 옮기는 과정을 봅니다.
3. **조종 입력:** 게임패드나 지상통제 명령이 비행 동작으로 바뀌는 과정을 봅니다.
4. **카메라 분석:** 화면에서 만든 RGB 픽셀을 밝기·대비·선명도 값으로 요약하는 과정을 봅니다.

코드도 이 역할에 따라 나뉘어 있습니다. 비행 계산, 화면 그리기, 명령 통신, 게임패드 입력, 카메라 데이터와 분석이 각각 묶여 있습니다. 처음부터 모든 코드를 읽기보다 수정하려는 동작의 입력과 결과를 먼저 찾으세요.

## 지금까지 정리한 내용

- 프로젝트의 중심을 로봇 팔에서 가상 드론과 지상통제 시험으로 옮겼습니다.
- 모의 계산은 초당 60번 고정된 간격으로 진행합니다. 화면 그리기와 계산 간격은 분리했습니다.
- 주변을 보는 화면과 드론 카메라 화면을 함께 표시합니다.
- 지상통제 창과 UDP 통신으로 이륙·이동·착륙·카메라 명령을 보냅니다.
- 통신 지연·손실과 카메라 고장 상황을 JSON 시나리오로 재현합니다.
- RGB 화면의 밝기·대비·선명도를 계산합니다. 이 값은 간단한 지표이며 실제 영상 품질 판정은 아닙니다.
- 지상통제 창을 자동으로 누르던 PowerShell 시험을 제거했습니다. 따라서 창과 시뮬레이터를 함께 확인하는 자동 시험은 현재 없습니다.
- 사용 안내와 내부 개발 안내를 나누고, 기본 빌드 선택을 Release 하나로 줄였습니다.

## 확인 상태

PowerShell 기반 화면 시험을 제거하기 전에는 Release 빌드와 자동 시험 22개가 통과한 기록이 있습니다. 시험 제거 뒤 전체 빌드와 시험을 다시 실행하지 않았으므로 현재 통과 여부는 확인되지 않았습니다. 이 기록을 현재 코드의 검증 완료로 보면 안 됩니다.

다음 확인은 Visual Studio에서 `Ninja Release`를 구성하고 빌드한 뒤, CTest 핵심 시험과 화면 시작 시험을 실행하는 것입니다. 화면 버튼을 함께 누르는 시험은 삭제되어 있으므로 수동으로 확인해야 합니다.

## 성능 기록

보관된 측정 한 건은 Windows Release, 1280×720 화면, Intel Core i5-13600KF, NVIDIA GeForce RTX 3060 Ti에서 수행했습니다. 숨김 창에서 5초씩 세 번 측정했으며, 단순한 도형과 드론 한 대를 사용했습니다.

| 항목 | 당시 측정값 |
| --- | ---: |
| 비행 계산 한 번의 시간 p95 | 약 0.4~0.5 µs |
| 카메라 영상 분석 시간 p95 | 약 1.31~1.34 ms |
| 숨김 창 그리기 속도 | 약 394~398 FPS |

숨김 창의 FPS는 사용자가 보는 실제 화면 속도가 아닙니다. 이 기록만으로 이전 로봇 프로그램보다 빨라졌다고 비교할 수도 없습니다. 조건이 같은 새 측정 결과가 생기기 전까지는 기준 자료로만 취급합니다.

## 현재 범위 밖인 일

- 실제 드론의 공기역학과 모터 동작
- 실제 EO 영상 입력·저장과 AI 추론
- 실제 게임패드 조합 전체와 외부 네트워크 환경
- 지상통제 창 버튼 조작의 자동 시험

기능을 더하기 전에는 이 목록과 기존 동작을 확인해, 이미 구현된 것으로 오해하지 않게 안내를 고칩니다.
