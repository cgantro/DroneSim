# 개발 문제 해결 안내

이 문서는 개발 환경에서 구성, 빌드, 시나리오, 그래픽, UDP 문제를 좁히는 순서를 정리합니다. 문제를 발견하면 재현 입력과 최초 오류를 보존하고, 로그에 없는 원인을 추정해 확정된 기록처럼 쓰지 않습니다.

## CMake 구성 실패

1. `CMakePresets.json`의 `ninja-release`와 실제 출력 디렉터리 `build-ninja-release/`를 확인합니다.
2. `VCPKG_ROOT` 또는 `CMAKE_TOOLCHAIN_FILE`이 vcpkg toolchain을 가리키는지 확인합니다.
3. 의존성 다운로드 실패는 네트워크, vcpkg baseline 및 manifest를 확인합니다. manifest의 기본 OpenCV 요구 버전은 4.14.0 이상입니다.
4. 캐시가 다른 툴체인 또는 생성기에서 만들어졌다면 기존 사용자 산출물을 먼저 보존하고, 해당 빌드 폴더 안에서만 구성 캐시를 새로 만듭니다. 저장소 전체나 다른 작업 폴더를 삭제하지 않습니다.

## 컴파일 또는 링크 실패

- 첫 오류를 기준으로 확인하고, 연쇄적으로 출력된 후속 오류만으로 원인을 판단하지 않습니다.
- Windows에서는 MSVC의 UTF-8 옵션과 C++20 지원을 확인합니다.
- OpenCV `core`와 `imgproc`가 필요합니다. Windows 지상통제 GUI는 Winsock과 Windows UI 라이브러리도 사용합니다.
- 새 소스를 추가하거나 이동했다면 관련 타깃의 CMake 소스 목록을 확인합니다.

## CTest 실패

- 실행한 구성·커밋·명령·실패 시험 이름을 함께 남깁니다.
- `ctest --test-dir <빌드 폴더> --output-on-failure` 출력에서 첫 assertion과 fixture 경로를 확인합니다.
- 시나리오 파일 경로를 바꿨다면 CMake의 등록 경로를 같이 갱신합니다.
- 그래픽 smoke test가 환경 의존적으로 실패하면 OpenGL 컨텍스트, 화면 세션, 실행 작업 폴더를 각각 확인합니다. headless 시나리오 시험과 화면 시험을 같은 문제로 취급하지 않습니다.

## Headless 시나리오가 실패

- 종료 코드 `2`는 파일 읽기·JSON 형식·실행 오류이고, `1`은 시나리오가 실행됐지만 기대 결과를 만족하지 못한 경우입니다.
- 출력 JSON의 `issues` 및 `events`를 먼저 확인합니다.
- 명령 적용 Tick과 60Hz 계산 순서를 확인합니다. 해당 Tick에서 명령 적용 후 한 번 진행됩니다.
- 현재 모델은 초기 상태가 원점 지상 상태입니다. 시나리오 JSON의 초기 위치 입력을 지원한다고 가정하지 않습니다.
- 큰 부동소수점 기대값에는 시나리오의 위치 허용 오차를 명시합니다.

## UDP 응답 시간 초과

1. 서버가 바인딩한 주소/포트와 클라이언트 대상 주소/포트를 확인합니다.
2. UDP 소켓 오류, 방화벽, 포트 충돌 및 응답의 peer 주소를 확인합니다.
3. 요청과 응답의 command ID 및 sequence가 같은지 확인합니다.
4. 재시도 중복이 서버 시퀀스 가드에서 안전하게 처리되는지 로그와 응답 상태로 확인합니다.
5. 응답이 없다는 이유만으로 요청이 서버에 도달하지 않았다고 단정하지 않습니다. 프로토콜은 인증·암호화·전달 보증이 없습니다.

현재 클라이언트의 기본 timeout은 API 기본값 4초, 재시도 간격은 400ms입니다. 시나리오의 명령 지연 주입은 별도 가상 Tick 단위이며 UDP wall-clock timeout과 같은 값이 아닙니다.

## 그래픽 및 카메라 프레임 문제

- 셰이더 경로와 작업 디렉터리를 확인하고, OpenGL 초기화 메시지를 확인합니다.
- 성능 측정이나 화면 시험을 수동으로 실행할 때는 빌드 결과 폴더를 작업 위치로 지정합니다. 모델·셰이더·지도 경로가 실행 위치를 기준으로 해석되므로, 다른 위치에서 실행하면 자료를 못 찾았다는 오류가 뜰 수 있습니다.
- OpenGL 화면 캡처 해상도는 화면 레이아웃과 창 크기에 영향을 받습니다.
- 카메라 상태가 `Fault`라면 `Recover` 처리 여부를 확인합니다. `Enable`만으로 fault가 풀리지 않습니다.
- RGB 지표가 바뀌면 프레임 버퍼 크기, 채널·stride, 픽셀 수명을 추적하고 센서 메타데이터 Tick과 픽셀 Readback 시점을 구분합니다.

## 기록 작성 형식

개발 문제나 수정 사항을 남길 때 아래 항목을 사용합니다. 재현하지 못한 보고는 “미재현”으로 기록하고, 원인이 확인되지 않은 경우 해결책을 확정하지 않습니다.

| 항목 | 기록할 내용 |
| --- | --- |
| 시각과 버전 | 날짜, 브랜치, 짧은 커밋 ID, 빌드 구성 |
| 환경 | OS, 컴파일러, 그래픽 장치 또는 네트워크 구성 |
| 재현 | 실행 명령, 입력 시나리오, 반복 횟수 |
| 실제/기대 | 관찰된 결과와 기대 결과 |
| 원인·수정 | 근거가 있는 원인, 바꾼 파일/동작 |
| 확인 | 실제 실행한 빌드·시험·수동 확인 및 결과 |
| 남은 점 | 미재현 조건, 검증하지 않은 범위 |

과거 확인 내역은 [개발 기록](개발기록.md)에 출처와 함께 모읍니다. 검증하지 않은 절차를 해결 완료로 표시하지 않습니다.
