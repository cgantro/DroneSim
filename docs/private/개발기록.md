# AeroSimLab 개발 기록

이 문서는 현재 브랜치에서 확인할 수 있는 주요 개발 단계와 보관된 검증 자료의 색인입니다. 모든 세부 변경은 Git 커밋에 남아 있으므로 전체 변경 이력을 반복 복사하지 않고, 중요한 단계와 조사 가능한 원본 위치를 연결합니다. Git 이력의 메시지나 과거 기록만으로 현재 동작을 보증하지 않습니다.

## 현재 기준으로 보관된 확인 기록

- 최신 Release 전체 CTest 60개가 통과합니다. 단일 강체 비행과 10분 호버링, 여러 Entity의 독립 명령·공유 Jolt 단계·Body 제거·드론 간 접촉·위치 공유 장애·역할별 공동 임무, 입력 기록·재생의 Tick 경계를 확인했습니다. 다른 빌드 설정이나 실제 비행, GUI·UDP 전체 기록·재생 경로를 보증하지는 않습니다.
- 같은 안내에는 시뮬레이터 숨김 시험 모드와 별도 지상통제 클라이언트로 이륙 명령을 보낸 수동 확인 기록이 있으며, 응답 `applied`, 왕복 14ms로 적혀 있습니다. 창 버튼부터 실제 시뮬레이터까지 자동화된 종단 간 시험은 아니라고 기록되어 있습니다.
- Git 이력에는 창 UI 자동화 PowerShell 시험을 제거한 기록이 있습니다. 현재 자동 UDP 클라이언트 시험은 로컬 응답기 기반이며, 실제 UI 조작을 자동으로 검증하지 않습니다.
- 성능 자료는 [MVP Release 결과](../../benchmarks/results/aerosimlab-mvp-release.json)에 있습니다. Windows 10 x64, MSVC Release, i5-13600KF, RTX 3060 Ti/OpenGL 3.3, 1280×720, 숨김 창 조건의 측정 기록입니다. 2026-10-21 기준 재검증 3회는 약 394~405 render FPS, Tick p95 약 0.4~0.5µs, OpenCV 지표 분석 p95 약 1.31~1.34ms를 기록합니다. 화면을 숨긴 상태이며 측정 커밋·환경·부하에 따른 결과이므로 일반 사용자 화면 성능이나 다른 기기 성능으로 일반화하지 않습니다.
- 2026-10-22 같은 Release 코드와 물리 경로에서 화면 형상만 단순 상자와 X500 메시로 바꿔 각각 3회 측정했습니다. 메시 쪽 render FPS는 397.6~399.4, 상자 쪽은 388.8~398.0으로 범위가 거의 겹칩니다. Tick p95도 메시 53.5~59.4µs, 상자 53.6~54.7µs로 비슷합니다. 차이가 반복 측정 편차 안에 있어 모델이 빨라지거나 느려졌다고 결론내리지 않았습니다. 두 조건 모두 GLB를 시작할 때 읽었으므로 메모리 비교는 하지 않았습니다. 자세한 표본과 조건은 같은 결과 파일에 추가했습니다.
- 2026-10-22 `b4680460`에서 Jolt 업데이트 구간을 따로 재도록 계측을 추가했습니다. Windows Release, 숨김 1280×720 화면, X500 메시, 5초씩 세 번 실행한 결과 Jolt 계산 p95는 38.8~42.2µs, 전체 Tick p95는 52.3~57.2µs였습니다. 각 실행에서 298개 Tick을 기록했고, 화면 출력은 약 397~400 FPS였습니다. 일반 실행에서는 시계 측정을 하지 않으며, 이 숫자는 성능 개선 전후 비교가 아니라 현재 환경의 기준 측정입니다. 세 실행의 p50·p95·p99와 메모리·CPU 표본은 [MVP Release 결과](../../benchmarks/results/aerosimlab-mvp-release.json)에 보관했습니다.
- 여러 드론은 같은 Jolt 세계를 공유해야 합니다. 드론별로 세계를 진행하면 드론 수만큼 시뮬레이션 시간이 더 흐르고 서로 충돌할 수도 없습니다. `ad40a519`에서 1·2·4·8대의 실행 비용을 계측했습니다. Release 강체 모의에서 드론 수마다 120 Tick을 준비 단계로 진행하고, 300 Tick 표본을 세 번 모았습니다. 전체 Tick p95는 각각 약 3.8, 4.4~4.5, 5.7, 8.4µs였고 Jolt 단계 p95는 2.7, 2.9~3.0, 3.4, 4.5~4.6µs였습니다. 1대와 8대의 p50은 전체 Tick 3.7→8.3µs, Jolt 단계 2.6→4.5µs였습니다. 이 결과는 렌더링·센서·통신을 제외한 현재 구현의 기준값이며, 성능 개선을 입증하는 전후 비교는 아닙니다. 실행 조건과 각 표본은 [MVP Release 결과](../../benchmarks/results/aerosimlab-mvp-release.json)에 저장했습니다.

### 아직 결론이 나지 않은 항목

- 지상통제 창에서 실제 시뮬레이터까지 명령이 오갈 때의 시간 초과 원인은 확정되지 않았습니다. 창 버튼 자동 시험도 현재 없습니다.
- 셰이더를 실행 파일의 위치와 관계없이 찾도록 바뀌었는지는 확인되지 않았습니다. 현재는 빌드 결과 폴더에서 실행하는 방법을 안내합니다.
- UDP는 전달을 보장하지 않습니다. 응답 시간 초과만으로 명령이 적용되지 않았다고 판단할 수 없습니다.

북한산 SRTM 지형과 OpenStreetMap 건물 외곽선 17개는 화면과 충돌에 연결했습니다. 건물 높이는 원본 자료에 없어 3m 시연용 상자를 사용합니다. 국토교통부 GIS 건물 통합 자료를 높이 후보로 찾았지만 실제 높이 필드와 건물별 대응은 아직 확인하지 못했습니다. 실기체 기준 물리 검증과 임무 간 순서·경로 재계획도 남아 있습니다. 시나리오의 위치 공유는 단순한 한 방향 연결이며 실제 전파 지연·손실률·대역폭은 계산하지 않습니다. 접촉 시각과 충격량을 이용한 위험 판정도 미구현입니다. 구현 상태는 [MVP 명세](../../SPEC.md)에서 확인합니다.

## 기록을 계속 쌓는 방법

현재 상태는 `GOAL.md`와 `SPEC.md`, 실행 절차는 공개 사용 안내, 모듈 구조는 [기술 설계](기술설계.md), 재현 방법은 [개발 문제 해결](문제해결.md)에 기록합니다. 측정 원본은 `benchmarks/`에 두고 이 문서에는 조건과 해석을 요약합니다. 새 결과를 추가할 때는 커밋 ID, 환경, 명령, 부하, 반복 횟수와 원자료 경로를 남깁니다.

모든 개발 흔적을 문서에 복사하는 대신 전체 세부 이력은 Git 로그와 원자료를 기준으로 확인합니다. 오래된 프로젝트 방향이나 과거 실험은 현재 구현·요구사항에 섞지 않습니다.
