# AeroSimLab 개발 기록

이 문서는 현재 브랜치에서 확인할 수 있는 주요 개발 단계와 보관된 검증 자료의 색인입니다. 모든 세부 변경은 Git 커밋에 남아 있으므로 전체 변경 이력을 반복 복사하지 않고, 중요한 단계와 조사 가능한 원본 위치를 연결합니다. Git 이력의 메시지나 과거 기록만으로 현재 동작을 보증하지 않습니다.

## 주요 단계

| 시기 | 기록된 작업 | 근거와 해석 |
| --- | --- | --- |
| 2026-08-24~09-05 | OpenGL 창·셰이더·버퍼·메시·카메라 기초와 모듈 분리 | 초기 렌더링 커밋과 설계 문서가 Git 이력에 있습니다. 현재 `modules/graphics/`에 남은 그래픽 기반의 출발점입니다. |
| 2026-09-16~10-21 | 시뮬레이션·모델 로딩·제어·경로 계획·물리 및 대량 검증/성능 기록 | Git에는 다양한 시뮬레이션과 벤치마크 변경이 기록되어 있습니다. 이는 현재 AeroSimLab의 동작으로 간주하지 않으며, 현재 브랜치의 소스와 자산만 현재 기준으로 삼습니다. |
| 2026-10-22 | 프로젝트를 AeroSimLab 기준으로 정리하고 고정 Tick 드론 코어, JSON 시나리오, UDP 지상통제, 카메라 픽셀 흐름을 문서화 | 현재 브랜치의 `GOAL.md`, `SPEC.md`, 소스, 시나리오 및 상위 커밋에서 확인됩니다. |
| 2026-10-22 | 시나리오와 웹 셸 파일을 역할별 폴더로 이동하고 경로를 CMake에 반영 | `scenarios/flight/`, `scenarios/fault-injection/`, `apps/simulator/web/`의 현재 구조와 CMake 등록을 확인했습니다. |
| 2026-10-22 | 실제와 같은 지도·기체 모델 및 다중 드론 협동을 확장 목표로 추가 | `GOAL.md`, `SPEC.md`에 목표와 미구현 상태가 기록되어 있습니다. `assets/maps/`, `assets/models/drones/`, `scenarios/multi-drone/`은 준비 폴더이며 구현 자산은 없습니다. |

## 현재 기준으로 보관된 확인 기록

- 저장소 내부 안내에는 2026-10-22 Debug 구성의 전체 빌드와 CTest 22개 통과 기록이 있습니다. 이 작업에서 다시 실행한 검증이 아니며, 현재 수정 내용의 통과를 뜻하지 않습니다.
- 같은 안내에는 시뮬레이터 숨김 시험 모드와 별도 지상통제 클라이언트로 이륙 명령을 보낸 수동 확인 기록이 있으며, 응답 `applied`, 왕복 14ms로 적혀 있습니다. 창 버튼부터 실제 시뮬레이터까지 자동화된 종단 간 시험은 아니라고 기록되어 있습니다.
- Git 이력에는 창 UI 자동화 PowerShell 시험을 제거한 기록이 있습니다. 현재 자동 UDP 클라이언트 시험은 로컬 응답기 기반이며, 실제 UI 조작을 자동으로 검증하지 않습니다.
- 성능 자료는 [MVP Release 결과](../../benchmarks/results/aerosimlab-mvp-release.json)에 있습니다. Windows 10 x64, MSVC Release, i5-13600KF, RTX 3060 Ti/OpenGL 3.3, 1280×720, 숨김 창 조건의 측정 기록입니다. 2026-10-21 기준 재검증 3회는 약 394~405 render FPS, Tick p95 약 0.4~0.5µs, OpenCV 지표 분석 p95 약 1.31~1.34ms를 기록합니다. 화면을 숨긴 상태이며 측정 커밋·환경·부하에 따른 결과이므로 일반 사용자 화면 성능이나 다른 기기 성능으로 일반화하지 않습니다.
- 더 오래된 수정 전 측정치, 서로 다른 부하의 샘플, 빌드 로그는 `benchmarks/archive/` 및 `logs/archive/`에 보존되어 있습니다. 결과 비교는 같은 조건을 확인한 경우에만 합니다.

## 확인된 문제와 한계 기록

| 항목 | 현재 기록 |
| --- | --- |
| UI부터 실제 앱까지 UDP 종단 간 자동화 | 별도 CLI 수동 확인 기록은 있으나 GUI 버튼 연동 자동 시험은 없음. 자동 클라이언트 시험은 로컬 응답기 사용. |
| 창 프로그램 응답 시간 초과 | 내부 개발 안내에서 이전 제보의 재현 여부를 확인하지 못했다고 기록. 원인 확정 및 해결 완료로 표시하지 않음. |
| 명령 timeout 후 안전 동작 | 명령 유효기간 후 hover 전환은 후속 요구. 현재 서버 동작으로 문서화하지 않음. |
| 초기 위치 시나리오 입력 | 미구현. 모든 JSON 시험은 고정 초기 상태에서 시작. |
| 카메라 및 RGB | 상태 메타데이터는 코어 기능. 실제 카메라 입력은 없으며 OpenGL 픽셀 Readback과 실제 EO 장비 검증은 별개. |
| 지도·실제 기체에 가까운 운동 모델·다중 드론 | 목표 및 수용 기준만 정의됨. 코드·시험·자산은 미구현. |

## 기록을 계속 쌓는 방법

현재 상태는 `GOAL.md`와 `SPEC.md`, 실행 절차는 공개 사용 안내, 모듈 구조는 [기술 설계](기술설계.md), 재현 방법은 [개발 문제 해결](문제해결.md)에 기록합니다. 측정 원본은 `benchmarks/`에 두고 이 문서에는 조건과 해석을 요약합니다. 새 결과를 추가할 때는 커밋 ID, 환경, 명령, 부하, 반복 횟수와 원자료 경로를 남깁니다.

모든 개발 흔적을 문서에 복사하는 대신 전체 세부 이력은 Git 로그와 원자료를 기준으로 확인합니다. 오래된 프로젝트 방향이나 과거 실험은 현재 구현·요구사항에 섞지 않습니다.
