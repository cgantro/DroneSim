# 검증과 측정

## 자동 시험

Windows MSVC Release 빌드에서 CTest **20개가 모두 통과했습니다.** 시험은 드론 비행과 재현성, 카메라 상태와 RGB 행 순서, OpenCV 프레임 공유와 밝기·대비·선명도 계산, JSON 장애 시나리오, UDP 메시지와 지상통제 명령 왕복, 조작 창의 카메라 고장·복구 버튼, 화면에서 카메라 픽셀을 읽는지 확인합니다.

Visual Studio에서 프로젝트 폴더를 열고 `Ninja Release` 구성을 선택하면 빌드할 수 있습니다. 시험은 Visual Studio의 테스트 창에서 실행합니다. 정상 비행과 장애 시나리오는 화면 없이 실행되는 별도 시험 프로그램으로 확인했습니다. Windows 시뮬레이터는 콘솔 없는 GUI 프로그램으로 빌드하며, 일반 실행 오류는 대화상자에 표시합니다.

장애 시나리오는 이륙 명령 중복, 경유점 명령 지연, 착륙 명령 손실, 카메라 고장과 복구를 재현합니다. 결과에는 마지막 드론·카메라 상태와 이벤트 기록이 포함됩니다.

## Release 측정

측정 기능은 Visual Studio의 실행 설정에서 `--benchmark`를 지정해 시작합니다. 결과 JSON은 Visual Studio 디버그 출력 창에 표시됩니다. 측정은 2026년 10월 21일, Windows x64와 MSVC Release에서 수행했습니다. CPU는 13th Gen Intel Core i5-13600KF이고 그래픽카드는 NVIDIA GeForce RTX 3060 Ti입니다. 1280×720 OpenGL 창을 화면에 표시하지 않고 VSync를 끈 채 매번 5초 동안 실행했습니다.

| 재측정 | 모의 Tick | Tick p50 / p95 / p99 | 16.67ms 초과 | 숨김 그리기 속도 | 메모리 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1회 | 298 | 0.3 / 0.5 / 0.9µs | 0 | 402.2 FPS | 63.6MB |
| 2회 | 298 | 0.3 / 0.5 / 0.7µs | 0 | 404.7 FPS | 63.6MB |
| 3회 | 297 | 0.3 / 0.5 / 1.0µs | 0 | 403.2 FPS | 63.6MB |

OpenCV의 회색 변환과 선명도 계산을 포함해 같은 컴퓨터와 화면 크기에서 5초씩 세 번 측정했습니다. 매번 모의는 298 Tick, 화면 그리기는 약 2,000회였고, 새 RGB 영상 약 290개를 분석했습니다.

| 실행 | 분석 시간 p50 / p95 / p99 | 밝기 / 대비 / 선명도 평균 | 숨김 그리기 속도 | 메모리 |
| --- | ---: | ---: | ---: | ---: |
| 1회 | 1,182.6 / 1,341.1 / 1,796.9µs | 166.48 / 72.26 / 79.68 | 398.2 FPS | 69.8MB |
| 2회 | 1,182.3 / 1,312.2 / 1,594.6µs | 166.48 / 72.26 / 79.68 | 394.2 FPS | 69.8MB |
| 3회 | 1,172.9 / 1,317.8 / 1,958.2µs | 166.48 / 72.26 / 79.68 | 394.7 FPS | 69.8MB |

분석 시간 평균은 p50 약 1,179µs, p95 약 1,324µs, p99 약 1,783µs입니다. 밝기는 픽셀 평균, 대비는 밝기 표준편차, 선명도는 회색 영상 라플라시안 응답의 분산입니다. 선명도 값은 장면의 경계와 노이즈에 영향을 받으므로 초점이나 전체 영상 품질을 판정하는 점수로 볼 수 없습니다. 이전 분석 버전보다 처리 단계가 늘었고 코드 버전도 달라졌으므로, FPS 변화만으로 새 계산의 성능 영향을 단정하지 않습니다. 원본 측정값과 실행 정보는 같은 [Release 결과 JSON](../benchmarks/results/aerosimlab-mvp-release.json)에 보관했습니다.

Tick 지연은 드론과 카메라의 모의 갱신 함수만 잰 값입니다. 숨김 그리기 속도는 실제 화면에 표시할 때의 FPS가 아닙니다. CPU 비율은 프로세스 CPU 시간을 측정 시간으로 나눈 값입니다. 여러 코어를 쓰면 100%를 넘을 수 있습니다.

첫 측정에서는 숨김 그리기 속도가 26~39 FPS였지만, 같은 날 재측정한 결과는 약 403 FPS였습니다. 두 기록의 차이를 설명할 GPU·OpenGL 정보와 코드 버전이 첫 측정에는 없어 원인을 확정할 수 없습니다. 따라서 두 값을 성능 향상이나 회귀의 근거로 비교하지 않습니다. 재측정부터 화면 크기와 GPU·OpenGL 정보를 함께 출력하도록 바꿨습니다.

측정 원본과 재측정값은 [Release 결과 JSON](../benchmarks/results/aerosimlab-mvp-release.json)에 보관했습니다. 이후 성능 변화는 같은 실행 파일 설정과 같은 환경에서 다시 측정해야 합니다. 이전 GraspLink 측정과 입력·환경이 달라 직접 비교할 수 없습니다.

## WebAssembly 확인

Emscripten 4.0.19로 화면 프로그램과 헤드리스 실행 파일을 빌드했습니다. Node.js에서 정상 비행과 장애 주입 시나리오를 모두 실행해 `passed: true`를 확인했습니다. 정상 비행은 300 Tick 뒤 착륙했고, 장애 시나리오는 카메라 고장·복구와 명령 지연·손실을 재현했습니다. 브라우저에서 화면 프로그램과 관련 파일을 모두 내려받았지만, 화면 표시와 입력 조작은 확인하지 못했습니다.

## 확인하지 않은 항목

- 실제 모니터에 표시되는 FPS와 GPU 사용량
- 브라우저에서 화면을 띄우고 입력을 조작하는 시험
- 다른 PC, Debug 빌드, 장시간 실행과 반복 종료
- 실행 중 네트워크가 끊긴 뒤 같은 연결이 자동으로 복구되는 동작과 실제 패킷 손실·지연
- 영상 파일 저장과 여러 조건에서 반복한 OpenCV 분석 성능 비교
- 실제 드론 기체의 비행 성능과 공기역학
