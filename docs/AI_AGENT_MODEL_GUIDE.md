# Codex 모델 선택 안내

## 기본 원칙

가능하면 **Luna로 시작하고, 어려운 판단이 필요한 경우에만 Sol로 올린다.**

## GPT-6 Luna

다음 작업에 사용한다.

- 코드 읽기와 파일 탐색
- 문서 정리
- 단순 구현과 boilerplate 작성
- 테스트 추가와 TODO 구현
- 명확한 빌드 오류 수정
- 작은 리팩터링과 반복 작업

## GPT-6.1 Sol

다음 작업에 사용한다.

- 설계와 아키텍처 변경
- 원인을 알 수 없는 버그 조사
- 여러 모듈을 함께 수정하는 작업과 큰 리팩터링
- 성능 병목과 race condition 분석
- C++ lifetime과 ownership 판단
- networking
- Physics, IK, 제어 알고리즘
- 반복적인 테스트, 수정, 재검증이 필요한 작업

## 운영 규칙

1. 먼저 Luna로 코드를 탐색한다.
2. 문제가 명확하면 Luna로 구현한다.
3. 구조 판단이나 복잡한 추론이 필요하면 Sol로 전환한다.
4. Sol이 설계를 정한 뒤 반복 구현은 Luna에 맡긴다.
5. 한 번에 너무 큰 작업을 주지 않는다.

기본 작업 흐름:

```text
Luna: 탐색
→ Sol: 판단
→ Luna: 구현
```

사용 가능한 모델이나 agent routing이 없는 환경에서는 이 가이드를 작업 난이도 판단 기준으로 삼고, 현재 사용 가능한 도구 안에서 진행한다.
