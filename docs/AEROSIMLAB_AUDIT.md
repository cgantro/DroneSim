# AeroSimLab 전환 전 코드 감사

## 확인한 현재 상태

저장소는 아직 GraspLink이며, C++17로 빌드합니다. 화면 실행 경로는 HCR-12A 로봇과 2F-85 그리퍼, 집기·놓기 시연을 중심으로 구성되어 있습니다.

화면과 장면을 만드는 코드, GLB 읽기, 고정 간격 갱신, 로그 기록은 재사용할 수 있습니다. 드론 상태, EO 카메라 센서, 지상통제 프로그램, UDP 메시지, JSON 시나리오 실행 기능은 아직 없습니다.

현재 CMake 의존성에는 OpenGL·GLFW, Flecs, GLM, Eigen, Jolt, TinyGLTF, TinyXML2, ImGui, GoogleTest, Google Benchmark, Tracy가 있습니다. OpenCV와 ONNX Runtime은 아직 연결되어 있지 않습니다. 웹용 Emscripten 설정과 패키지 생성용 Python 스크립트도 있습니다.

조사한 C++ 파일은 앱·모듈·시험·벤치마크 전체 151개, 약 23,451줄입니다. Windows Release 빌드와 23개 CTest 항목이 통과했습니다. 기존 성능 자료는 HCR-12A와 그리퍼 기준이므로 새 드론 모델의 기준값으로 사용할 수 없습니다.

## 코드 분류

| 분류 | 현재 코드 | 전환 방향 |
| --- | --- | --- |
| 유지 | OpenGL 렌더링, 카메라, GLB 읽기, 장면 구성, 로그 기록 | 드론과 EO 카메라를 표시하는 데 재사용합니다. |
| 정리 | Viewer 실행부, 장면 갱신, Flecs 연결, 모델·자원 수명 관리 | 화면 그리기와 모의 갱신을 분리하고, 앱 객체가 지나치게 많은 책임을 갖지 않도록 줄입니다. |
| 교체 | 로봇 관절·IK·경로 계획·집기 시연·로봇 GUI·URDF 처리 | 단순 드론 운동 모델, 시나리오 실행, EO 센서 상태, 명령·Telemetry 처리로 바꿉니다. |
| 제거 검토 | Jolt 물리, Eigen, TinyXML2, 로봇·그리퍼 전용 자산과 벤치마크 | 새 요구사항에서 쓰이지 않으면 의존성과 실행 경로에서 제거합니다. 화면에 보이는 지형·건물·드론 자산은 별도로 준비해야 합니다. |

## 구조에서 확인한 위험

- Viewer 앱 한 곳이 창·화면·장면·물리·로봇 제어·집기 임무·GUI의 수명을 함께 관리합니다. 교체 대상과 재사용 대상을 분리하는 첫 작업이 필요합니다.
- 고정 시간 갱신은 로봇 제어 모듈 안에 있습니다. 이를 모의 시계와 독립된 Simulation Core로 옮겨 화면이 없어도 실행할 수 있게 해야 합니다.
- 비동기 로그 기록기는 이미 스레드를 사용합니다. 새 통신·센서 처리를 추가할 때 기존 갱신 스레드와 소유권을 명확히 해야 합니다.
- GLB와 URDF는 로봇 링크와 충돌 형상을 읽기 위해 결합되어 있습니다. 드론 전환에서는 URDF·로봇 충돌 처리를 이어갈 이유가 확인되지 않았습니다.
- Jolt는 물리 계산뿐 아니라 로봇 충돌 검사와 집기 동작에도 연결되어 있습니다. 제거 전에는 해당 참조 경로를 단계별로 끊어야 합니다.
- 테스트 23개 중 Viewer 스모크 검사는 4·6·7축 로봇을 확인합니다. 전환 뒤에는 모의 시간, 드론 상태 전이, 시나리오 재현, 메시지 검증, 센서 상태를 확인하는 핵심 시험으로 교체해야 합니다.

## 전환 순서

1. C++20 빌드와 새 이름을 적용하고, 기존 실행을 깨뜨리지 않은 상태에서 빌드 기준을 확인합니다.
2. 로봇 전용 시험·벤치마크와 참조를 목록으로 고정한 뒤 기능 단위로 제거합니다.
3. 화면과 분리된 고정 간격 Simulation Core, 드론 상태와 운동 모델, JSON 시나리오 실행을 구현합니다.
4. OpenGL 화면과 탑재 카메라를 연결하고, 화면에서 RGB 프레임을 얻는 경로를 검증합니다.
5. 별도 지상통제 프로그램과 UDP 명령·Telemetry를 연결한 뒤 지연·손실·중복 시험을 추가합니다. 이 지점까지를 MVP로 봅니다.
6. 같은 시나리오를 반복 실행해 상태와 결과가 재현되는지 확인하고, 새 기능의 처리 시간과 자원 사용량을 측정합니다.
7. OpenCV, ONNX Runtime, 게임패드는 MVP 검증 뒤에 별도 단계로 다룹니다.

## 미확인 항목

이번 감사에서는 레이스 검출기 실행, 장시간 안정성, 패킷 장애 시험, 화면 프레임 획득, 새 드론 모델 성능 측정을 하지 않았습니다. 기존 물리 코드를 남길지 여부도 드론 요구사항에 충돌·강체 동역학이 추가되지 않는 한 제거하는 쪽이 단순합니다.
