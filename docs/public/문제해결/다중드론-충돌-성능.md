# 드론 수가 늘 때 충돌 계산이 느려진 문제

## 증상과 원인

드론이 서로 멀리 떨어져 있어도 매 Tick마다 모든 드론 쌍을 검사했습니다. 드론 수가 두 배가 되면 비교할 쌍은 대략 네 배로 늘어납니다. 충돌하지 않을 드론까지 회전 상자 검사를 하는 일이 다중 드론 성능을 깎았습니다.

## 수정

먼저 드론 위치를 X축으로 정렬하고, 충돌 모양이 닿을 수 있는 거리 안에 있는 드론만 기존 상자 겹침 검사로 넘깁니다. 상자 검사로 실제 충돌을 결정하는 과정은 유지했습니다. 드론이 한곳에 몰리면 후보가 다시 많아지므로 효과가 줄어듭니다.

## 측정 결과

Windows Release에서 분리 배치한 AirSim 강체 모드의 Tick p95 중앙값은 64대에서 493.9µs에서 137.7µs로 줄었습니다. 32대는 159.7µs에서 69.1µs, 128대는 1,617.2µs에서 282.9µs였습니다. 128대 기준선은 한 번만 측정했으므로 반복 결과와 같은 신뢰도로 볼 수 없습니다.

가까이 겹쳐 출발하는 32대에서는 물리 계산 p95가 약 1.3ms였습니다. 별도 계측에서 접촉 정보를 찾는 시간이 물리 구간 p95의 약 99%를 차지했습니다. 이는 드론이 모인 상태에서는 후보를 줄이는 효과가 작아진다는 점을 보여 줍니다.

## 측정 한계

분리 배치는 호버링 중심이고, 밀집 배치는 충돌 뒤 드론이 흩어집니다. 지속 편대나 실제 충돌 밀도를 재현한 시험은 아닙니다. 계측을 켠 측정값은 계측 없는 실행과 직접 비교하지 않습니다. 반복 수와 원본 표는 [기술 검토](../기술검토.md)와 [측정 원본](../../../benchmarks/results/aerosimlab-scaling-after-broadphase-release-2026-10-23.json)에서 확인할 수 있습니다.
