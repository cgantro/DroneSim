# 접근 위반 오류, 원인 미확인

## 보고된 증상

Visual Studio에서 시뮬레이터가 `0xC0000005` 접근 위반으로 종료됐다는 보고가 있었습니다. 주소만으로는 어느 코드가 잘못된 메모리를 읽었는지 알 수 없습니다.

## 현재 확인 상태

이 오류의 호출 스택, 덤프, 재현 순서가 저장소에 남아 있지 않아 원인을 확정하거나 수정 완료로 기록할 근거가 없습니다. 물리 입력의 잘못된 수치를 거르는 수정도 별도로 있지만, 이 접근 위반과 관련 있다는 증거는 없습니다.

## 원인 추적에 필요한 자료

오류가 다시 발생해 Visual Studio가 멈추면 다음 자료를 남깁니다.

1. 예외 창에 표시된 오류 코드, 읽기·쓰기 구분, 메모리 주소와 현재 코드 위치를 복사합니다.
2. **디버그 > 창 > 호출 스택**을 열어 전체 내용을 복사합니다. 현재 줄만으로 원인을 판단하지 말고, 그 줄까지 이어진 호출 경로도 함께 봅니다. [호출 스택 보는 방법](https://learn.microsoft.com/en-us/visualstudio/debugger/how-to-use-the-call-stack-window?view=visualstudio)
3. 디버거가 멈춘 상태에서 **디버그 > 덤프 파일로 저장**을 선택합니다. 가능하면 힙 정보를 포함한 덤프를 저장합니다. 힙 덤프에는 당시 프로그램 메모리가 들어가므로 공개 저장소에 올리지 말고 개인적으로 전달합니다. [덤프 파일 저장 안내](https://learn.microsoft.com/en-us/visualstudio/debugger/using-dump-files?view=visualstudio)
4. 오류 직전의 입력, 프로그램 상태, 화면과 재현 순서를 함께 적습니다.
5. 같은 순서로 다시 발생하는지 확인합니다.

이 자료를 바탕으로 객체 수명, 인덱스 범위, 비동기 작업 종료 순서를 확인합니다. 호출 스택과 재현 조건을 확보하기 전에는 원인을 확정하거나 수정 완료로 기록하지 않습니다.
