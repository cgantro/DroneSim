# 접근 위반 오류의 원인을 찾지 못한 문제

## 증상

시뮬레이터가 `0xC0000005` 접근 위반으로 종료됐다는 보고가 있었습니다. 예외 주소만으로는 잘못된 메모리를 읽은 함수나 그 값을 만든 코드를 알 수 없어서, 덤프와 당시 실행 파일의 기호를 찾아 호출 경로를 복원하려 했습니다.

## 덤프에서 확인한 사실

Windows 오류 기록에는 2026년 10월 22일 접근 위반 두 건이 남아 있었습니다. 오류 위치는 `0x57f69`, `0x57f79`였습니다. 다음 날에는 `0xC0000409` 예외가 다섯 건 기록됐습니다. 두 건의 위치는 `0x1a2d51`이었고, 오후에 발생한 세 건은 모두 `0x3070c1`에서 멈췄습니다.

사용자 계정의 CrashDumps 폴더에서 기존 네 개와 추가 세 개의 미니덤프를 WinDbg로 확인했습니다.

- 두 접근 위반은 `0xffffffffffffffff` 주소를 읽으려 했습니다.
- 두 `0xC0000409` 예외는 스택 보호값 손상 감지(`FAST_FAIL_STACK_COOKIE_CHECK_FAILURE`)로 확인됐습니다.
- 접근 위반 덤프에는 충돌 지점 뒤의 유효한 호출 주소가 남지 않아, 그보다 앞선 호출 경로를 이어서 볼 수 없었습니다.

추가로 오후에 저장된 덤프 세 개를 WinDbg에서 확인했습니다. 세 덤프 모두 `0xC0000409`와 `FAST_FAIL_STACK_COOKIE_CHECK_FAILURE`였고, 예외 위치도 프로그램 기준 `+0x3070c1`로 같았습니다. 가장 최근 덤프에서 프로그램은 시작한 지 약 3초 뒤에 멈췄습니다. 이는 오류가 시작 직후에도 발생했음을 보여 주지만, 접근 위반 두 건과 같은 원인이라는 증거는 아닙니다.

접근 위반 덤프 하나에서는 디버거가 `std::clamp<int>` 이름을 표시했지만, 덤프와 함께 보관된 실행 파일·기호가 맞지 않았습니다. 이 이름만으로 프로젝트의 특정 호출 지점을 지목할 수 없어 원인 근거에서는 제외했습니다. 오후의 스택 보호 실패 덤프도 현재 빌드의 기호와 일치하지 않아 호출 경로를 복원하지 못했습니다.

이 기록은 잘못된 주소 접근과 스택 보호 실패가 있었다는 점을 확인해 줍니다. 두 접근 위반과 다섯 스택 보호 실패가 같은 메모리 손상에서 시작됐다고 보여 주지는 않습니다.

## 원인을 확정하지 못한 이유

덤프를 만들 당시의 실행 파일과 일치하는 디버그 기호를 확보하지 못했습니다. 현재 실행 파일과 기호는 덤프가 만들어진 뒤 다시 빌드한 것이므로, 덤프의 주소를 현재 소스 줄이나 함수 이름으로 바꾸면 잘못된 연결이 될 수 있습니다. 접근 위반 덤프의 호출 경로는 손상되어 있고, 새 스택 보호 실패 덤프도 일치하는 기호가 없어 손상을 시작한 코드를 찾지 못했습니다.

물리 입력의 비정상 수치를 거르는 수정이 별도로 있지만, 이 접근 위반과 관련 있다는 증거는 없습니다. 따라서 현재 상태는 "오류 형태는 확인했지만 원인과 수정은 미확정"입니다.

## 다시 발생했을 때 필요한 자료

Visual Studio가 예외에서 멈추면 오류 코드와 메모리 주소, 전체 호출 스택, 당시 입력과 재현 순서를 남깁니다. 같은 시점의 실행 파일과 디버그 기호를 함께 보관하고, 가능하면 힙 정보를 포함한 덤프도 저장합니다. 다시 발생하면 접근 위반과 스택 보호 실패를 각각 기록해 서로 다른 사건을 같은 원인으로 묶지 않습니다. 덤프에는 프로그램 메모리가 포함될 수 있으므로 공개 저장소에 올리지 말고 개인적으로 전달합니다.

호출 스택은 [Visual Studio 호출 스택 안내](https://learn.microsoft.com/en-us/visualstudio/debugger/how-to-use-the-call-stack-window?view=vs-2022), 덤프 저장은 [덤프 파일 안내](https://learn.microsoft.com/en-us/visualstudio/debugger/using-dump-files?view=visualstudio)에서 확인할 수 있습니다. `0xC0000409`의 스택 보호 예외 값은 [Windows SDK 정의](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/winnt.h)에 있습니다.
