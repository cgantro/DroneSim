# 물리값을 AirSim으로 넘길 때 표현 범위를 확인하지 않던 문제

## 문제와 기대 동작

시뮬레이터는 위치와 기체 제원을 `double`로 다루지만, AirSim 내부의 벡터와 기체 파라미터 일부는 `float`입니다. 입력이 `double`에서 유한하다는 사실만으로는 변환 결과도 유효하다고 보장할 수 없습니다. `float`의 최대 범위를 넘는 위치나 질량은 변환 뒤 무한대가 될 수 있고, 너무 작은 양수 질량은 0으로 반올림될 수 있습니다.

물리 월드는 이런 값을 받기 전에 거부하고, 거부 과정에서 현재 강체 상태도 바꾸지 않아야 합니다.

이 문제는 정상 비행 중 발생한 고장이나 과거 접근 위반의 원인으로 확인된 사례가 아닙니다. 코드와 시험 범위를 비교하면서 찾은 AirSim 입력 경계의 검증 누락입니다.

## 원인을 확인한 과정

기체 생성은 질량·관성·크기가 유한한지와 양수인지를 확인했습니다. 위치·속도·바람도 유한한지 확인했습니다. 그러나 이 검사는 `double` 범위만 확인하므로, AirSim에 전달하기 전 `float`으로 바뀌는 값의 허용 범위까지 검사하지 못했습니다.

이전 강체 엔진인 Jolt를 사용하던 때에는 질량·힘·시간의 `float` 범위와 큰 자세값을 다루는 경계 시험이 있었습니다. AirSim으로 교체한 뒤에는 값 변환 코드가 새로 작성됐지만, 해당 경계 시험은 현재 경로에 다시 연결되지 않았습니다. 당시 시험 통과 기록만으로 현재 AirSim 변환도 안전하다고 볼 수 없었습니다.

상태를 직접 바꾸는 경로에도 순서 문제가 있었습니다. 강체가 한 번 진행된 뒤 새 상태를 넣으면 모터와 AirSim 모델을 먼저 초기화하고, 그 다음에 값을 AirSim 형식으로 바꿨습니다. 변환에 실패하면 요청은 거부되더라도 기존 강체는 이미 초기화된 상태일 수 있었습니다.

경계 입력을 검토할 때는 “입력값이 유한한가?”와 “목표 자료형으로 바꾼 뒤에도 유효한가?”를 분리해야 합니다. 예를 들어 아주 큰 유한한 `double`은 첫 조건을 통과해도 `float` 변환 뒤 무한대가 될 수 있습니다. 매우 작은 양수도 변환 후 0이 되면 질량이나 크기처럼 0을 허용하지 않는 물리량의 의미를 잃습니다. 검증 누락은 이런 변환 경계에서 발생했습니다.

## 수정한 내용

AirSim에 숫자를 전달하는 공통 변환 단계에서 먼저 값이 유한하고 `float` 범위 안인지 확인합니다. 범위를 벗어나면 물리 계산을 진행하기 전에 입력 오류로 처리합니다. 질량·관성·기체 크기·모터 제원처럼 반드시 양수여야 하는 값은 변환 뒤에도 0보다 큰지 확인하므로, 너무 작은 값이 0으로 바뀌는 경우도 거부합니다.

위치와 속도, 바람, 각속도, 자세 성분과 충돌 깊이도 같은 범위 확인을 거칩니다. 기존의 NaN·무한대 검사와 값의 의미에 따른 양수 검사는 유지합니다. 공통 변환 검사는 각 값이 AirSim의 자료형에 들어가는지 확인하고, 도메인 검사는 그 값이 물리적으로 필요한 조건을 만족하는지 확인합니다.

강체 상태를 바꿀 때는 AirSim 형식 변환을 먼저 끝낸 뒤 모델 초기화와 상태 변경을 시작하도록 순서를 바꿨습니다. 입력이 거부되면 이전 강체 상태가 그대로 남습니다.

이 순서는 입력 검증의 정확도와 별개의 불변 조건입니다. 모든 값의 허용 범위를 검사하더라도 변환 도중 오류가 난 뒤 일부 상태만 먼저 바뀌면 호출자는 실패한 요청 이후의 상태를 예측하기 어렵습니다. 먼저 변환 가능한 새 값 묶음을 완성하고, 그 뒤에만 기존 모델을 교체해야 거부가 원자적으로 동작합니다.

## 검증 결과

기존 물리 시험 묶음에 다음 경계 확인을 더했습니다. CTest 항목 수는 늘리지 않았습니다.

| 입력 | 기대 결과 | 확인 내용 |
| --- | --- | --- |
| `float` 최대값의 두 배인 바람 속도 | 거부 | 잘못된 바람이 AirSim에 전달되지 않음 |
| `float` 최대값의 두 배인 위치 | 거부 | 이미 진행된 강체의 위치가 요청 거부 뒤에도 유지됨 |
| `float` 최대값의 두 배인 질량 | 거부 | 생성 단계에서 표현할 수 없는 제원을 차단 |
| `float` 변환 뒤 0이 되는 양수 질량 | 거부 | 물리 모델에서 질량 0이 되는 경우를 차단 |

Windows Release 빌드 뒤 전체 CTest 20개를 실행했고 모두 통과했습니다. 이 확인은 입력 범위와 거부 시 상태 보존을 검증합니다. AirSim 물리 모델의 정확성이나 모든 극단값에서의 수치 안정성을 증명하지는 않습니다.

## 남은 한계

이 수정은 자료형 변환에서 무한대나 0이 생기는 경우를 막습니다. `float` 범위 안에 있지만 실제 드론 규모와 맞지 않는 값까지 모두 거부하는 물리적 상한은 아직 별도로 정하지 않았습니다. 예를 들어 매우 큰 위치나 풍속은 자료형에는 들어가더라도 이 시뮬레이션의 운용 범위에는 맞지 않을 수 있습니다.

또한 이 검증은 AirSim 호출 경계에서 수치를 표현할 수 있는지 확인하는 시험입니다. 실제 바람에서 기체가 어떻게 움직이는지, 입력 가능한 풍속을 어느 수준으로 제한해야 하는지, 극단값에서 제어기가 안정적인지는 다른 시험 문제입니다. 해당 경계 시험은 정상 비행의 물리 정확도를 대신하지 않습니다.

따라서 AirSim의 각 입력에 대해 실제 단위와 장면 크기에 맞는 허용 범위를 정하려면 기체 제원과 지원할 운용 조건을 더 확인해야 합니다. 이 수치 경계 문제와 이전 접근 위반 사이의 인과 관계도 확인되지 않았으므로, 크래시 원인으로 설명하지 않습니다.
