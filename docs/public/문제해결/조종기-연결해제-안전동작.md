# 게임패드 연결이 끊기면 정지 명령이 사라질 수 있던 문제

## 증상과 재현 조건

비행 중인 게임패드가 연결 해제되면 마지막으로 들어온 조종 입력을 정리하고, 현재 비행 상태에 맞는 동작을 한 번 예약해야 합니다. 처음 구현에서는 연결이 끊긴 순간 정지 또는 착륙 명령을 만들더라도 다음 화면 갱신에서 그 명령이 지워질 수 있었습니다.

이 문제는 장치를 뽑은 직후 명령을 예약하는 프레임과 다음 프레임 사이에 고정 시뮬레이션 Tick이 끼지 않는 경우에 드러납니다. 게임패드가 없는 상태는 이후 매 프레임 계속 확인되므로, 연결 해제 처리를 매번 반복하는 구조가 문제였습니다.

## 원인

이전 경로는 게임패드가 없는 매 프레임에도 연결 해제 처리를 다시 수행했습니다. 첫 호출에서 `Stop` 또는 `Land`를 대기열에 넣은 다음 호출이 다시 대기 중인 동작을 초기화하면, 시뮬레이션이 명령을 적용하기 전에 안전 명령이 사라집니다.

연결 해제는 상태가 “연결됨”에서 “끊김”으로 바뀌는 순간에만 처리해야 합니다. 이미 끊긴 상태에서 다시 호출되면 아무것도 바꾸지 않아야 합니다. 이 전환과 실제 비행 모드에 따른 명령 선택이 분리되어 있지 않았던 것이 원인이었습니다.

## 수정한 동작

연결 상태가 이미 끊겨 있으면 후속 호출을 바로 끝내도록 바꿨습니다. 실제 연결이 끊긴 순간에는 대기 중인 게임패드 입력을 지우고, 조종 주체와 비행 상태를 확인해 다음처럼 처리합니다.

| 끊기기 전 상태 | 처리 |
| --- | --- |
| 이륙 중 | 착륙 명령을 한 번 예약 |
| 호버링 또는 비행 중 | 속도 목표를 멈추는 명령을 한 번 예약 |
| 지상통제 또는 기록 재생이 입력을 소유 | 게임패드 안전 명령을 끼워 넣지 않고 대기 입력만 정리 |
| 지상 상태, 착륙 중 등 위 조건 외 상태 | 대기 중인 게임패드 동작을 정리하고 추가 명령은 보내지 않음 |

여기서 `Stop`은 비행 제어에 정지 목표를 보내는 동작입니다. 모터 전원을 끊거나 실제 기체의 비상 정지 장치를 작동하는 기능이 아닙니다.

## 확인 결과와 현재 시험 범위

과거에는 연결된 상태에서 끊겼을 때, 이미 끊긴 상태에서 다시 처리할 때, 이륙·비행·지상통제 상태에서 선택하는 동작을 직접 비교하는 시험이 있었습니다. 당시에는 연결 전환에 따른 정책을 확인했고 실제 Xbox 장치를 비행 중 분리하는 시험은 하지 않았습니다.

현재 시험을 핵심 시나리오로 줄인 뒤에는 해당 연결 해제 정책을 직접 호출하는 시험이 제거됐습니다. 현재 게임패드 자동 시험은 스틱 데드존과 기체 방향에 따른 이동 좌표 변환만 확인합니다. 따라서 현 코드에 정책이 있다는 사실과 현재 자동 회귀 시험으로 그 정책을 보장한다는 주장은 구분해야 합니다.

실제 Xbox USB 케이블을 비행 중 뽑는 장치 확인도 현재 기록에는 없습니다. 운영체제와 장치 드라이버가 연결 해제를 GLFW에 전달하는 시점, 프레임과 고정 Tick의 상대 순서까지 포함한 검증은 미완료입니다.

## 재발 방지 기준

- 상태 전환 이벤트는 매 프레임 반복되는 “현재 끊김” 상태와 구분합니다.
- 대기 중인 안전 명령은 다음 시뮬레이션 Tick이 적용할 때까지 보존되어야 합니다.
- 입력 차단 중에는 게임패드 해제 처리가 다른 입력 주체의 명령을 덮어쓰지 않아야 합니다.
- 자동 시험이 복구되기 전까지는 연결 해제 안전 동작을 회귀 검증했다고 표현하지 않습니다.
