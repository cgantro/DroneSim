# 기록을 다시 재생하면 EO 화면이 새 프레임으로 바뀌지 않던 문제

## 증상

기록을 시작하거나 재생하면 시뮬레이션 Tick이 0부터 다시 진행됩니다. 그런데 EO 화면의 프레임이 이전 세션에 머물거나, 새 영상이 바로 표시되지 않는 경로가 있었습니다. 상태는 초기화됐지만 화면 픽셀을 만드는 비동기 읽기 작업은 별도로 진행 중일 수 있었습니다.

## 원인

EO 화면은 OpenGL이 그린 픽셀을 GPU 버퍼에 요청하고, 준비가 끝난 프레임을 나중에 CPU로 가져옵니다. 이 흐름은 프레임 번호가 계속 커진다고 가정해 마지막으로 요청한 시뮬레이션 Tick을 저장합니다.

기록 재생을 시작할 때 시뮬레이션 Tick은 0으로 돌아갔지만 마지막 요청 Tick은 이전 실행의 큰 값으로 남았습니다. 새 카메라 Tick이 그 값보다 작으면 중복 프레임 방지 조건에 걸려 읽기 요청을 건너뜁니다. 이전 GPU 읽기가 아직 진행 중이면 새 실행의 픽셀과 이전 실행의 픽셀이 섞일 수도 있습니다.

## 수정한 내용

시뮬레이션을 초기화하기 전에 진행 중인 EO 픽셀 읽기를 끝내고 결과를 회수하도록 했습니다. 그 뒤 마지막 요청 Tick을 0으로 되돌리고, CPU 쪽에 보관한 EO 프레임도 비웁니다. 새 실행의 첫 프레임은 새 Tick 번호를 기준으로 다시 요청됩니다.

이 순서는 기록 시작·재생처럼 시뮬레이션 시간을 초기화하는 경로에서 사용합니다. 픽셀 버퍼 수명은 GPU 작업이 끝나기 전에 재사용하지 않도록 유지합니다.

## 검증 결과와 현재 범위

수정 이력에는 재생 전후 화면 프레임 번호가 어긋나는 확인을 반복해 10회 연속 통과한 결과와, 당시 Release 전체 시험 20개 통과 기록이 있습니다. 현재 숨김 시뮬레이터 통합 시험은 UDP를 통한 기록 시작·비행 명령·기록 종료·재생 요청을 확인합니다.

현재 자동 시험은 실제 OpenGL 픽셀 읽기 대기열을 재생 전후로 비우는지, 새 세션의 픽셀 Tick이 EO 패널에 표시되는지 직접 확인하지 않습니다. 이 문제는 과거 확인 기록과 현재 회귀 시험의 범위를 구분해 해석해야 합니다.

## 남은 한계

- 비동기 GPU 읽기 준비 여부와 OpenGL 화면 교체는 서로 다른 시점일 수 있습니다.
- 숨김 화면에서 기록한 상태 시험만으로 실제 패널에 새 영상이 보이는지 보증할 수 없습니다.
- Tick 번호를 0으로 되돌리는 다른 경로가 추가되면, 이전 픽셀 요청과 새 세션 상태가 분리되는지 다시 확인해야 합니다.
