# 게임패드 연결이 끊기면 정지 명령이 사라질 수 있던 문제

## 증상: 연결 해제 직후 예약한 안전 동작이 적용되지 않을 수 있었다

비행 중 게임패드 연결이 끊기면 더 이상 들어오지 않는 입력을 정리하고, 기체 상태에 맞는 동작을 한 번 예약해야 합니다. 처음 구현에서는 연결이 끊긴 순간 정지나 착륙 명령을 만들었더라도 시뮬레이션이 그 명령을 읽기 전에 다음 화면 갱신이 오면 대기 명령이 지워질 수 있었습니다.

이 문제는 매 화면 프레임마다 시뮬레이션 Tick이 실행되는 것은 아니라는 점에서 드러납니다. 게임패드 상태는 화면 갱신 때 확인되지만, 실제 비행 상태는 고정 Tick에서만 진행합니다. 연결 해제 이벤트가 생긴 뒤 다음 Tick이 오기 전에 여러 화면 프레임이 처리될 수 있습니다.

## 원인: 연결이 끊긴 상태를 매번 새 연결 해제처럼 처리했다

이전 흐름은 게임패드가 연결되지 않은 동안에도 매 프레임 연결 해제 처리를 다시 호출했습니다. 첫 호출에서 마지막 게임패드 입력을 비우고 안전 명령을 대기열에 넣었는데, 후속 호출이 같은 입력 정리 절차를 반복하면 시뮬레이션이 읽기 전에 그 명령이 사라졌습니다.

상태를 볼 때는 “이번 프레임에도 연결이 안 됨”과 “방금 연결됨에서 끊김으로 바뀜”을 구분해야 합니다. 안전 동작은 두 번째 전환에서 한 번만 예약해야 합니다. 연결이 이미 끊겨 있다는 이유로 매번 명령을 다시 만들면 대기열의 수명과 고정 Tick의 순서가 서로 맞지 않습니다.

## 수정: 연결 전환을 한 번 처리하고 비행 상태별 동작을 선택

이미 끊긴 상태에서 다시 호출되면 아무것도 바꾸지 않도록 했습니다. 실제 연결이 끊긴 순간에는 게임패드가 남긴 대기 입력을 비운 뒤, 입력 소유권과 비행 모드를 확인합니다.

| 연결 해제 직전 상태 | 예약하는 동작 | 이유와 범위 |
| --- | --- | --- |
| 이륙 중 | 착륙 요청 | 이륙 동작을 계속 밀어 올리지 않도록 합니다. |
| 호버링 또는 비행 중 | 정지 목표 | 이동 목표를 멈추도록 제어기에 요청합니다. |
| 지상통제가 입력을 소유 | 새 안전 비행 명령은 넣지 않음 | 지상통제가 활성 상태면 게임패드의 정지·착륙 명령을 보내지 않습니다. |
| 지상 상태, 착륙 중 등 나머지 상태 | 대기 입력만 정리 | 추가 비행 동작이 필요한 상태가 아닙니다. |

여기서 정지는 속도 목표를 멈추는 비행 명령입니다. 모터 전원을 차단하거나 실제 기체의 비상 정지 장치를 작동하지 않습니다. 따라서 이 동작을 실기체용 안전장치와 같은 의미로 설명하면 안 됩니다.

연결 해제는 화면 갱신 때 감지하고 예약한 명령은 다음 고정 Tick에서 적용합니다. 따라서 감지한 순간과 기체 상태가 바뀌는 시점 사이에 간격이 있습니다. 지상통제가 입력을 맡은 동안에는 게임패드의 정지·착륙 명령을 보내지 않습니다. 이때 기체 동작은 지상통제의 후속 명령에 따릅니다.

## 확인 결과: 정책을 확인한 시험과 장치 시험은 다르다

과거 자동 시험은 연결된 상태에서 끊기는 전환, 이미 끊긴 상태에서 다시 호출되는 경우, 이륙·비행 상태에서 선택되는 명령, 지상통제가 입력을 소유한 경우를 확인했습니다. 이미 끊긴 상태에서 다시 호출하면 처리 결과가 바뀌지 않아, 한 번 예약한 동작을 반복 호출이 지우지 않는지도 확인했습니다. 이 시험들은 게임패드 명령 변환과 연결 해제 정책을 코드 수준에서 검증했습니다.

현재 자동 시험은 이 정책 함수를 직접 호출해 연결이 이미 끊긴 경우, 이륙 중, 호버링·비행 중, 지상·착륙 중, 다른 입력이 조종권을 가진 경우에 선택되는 결과를 확인합니다. 이 검사는 기존 게임패드 시험 안에 포함해 별도 시험 항목을 늘리지 않았습니다. 다만 시뮬레이터 앱의 입력 대기열이 다음 고정 Tick까지 명령을 보존하는지, GLFW가 실제 장치의 분리를 감지하는지까지 검증하지는 않습니다.

또한 실제 Xbox 컨트롤러를 비행 중 USB에서 분리해 운영체제와 창 입력 계층을 거쳐 안전 명령이 예약되는지 확인한 기록은 없습니다. 실제 장치가 끊기는 시각, 창이 이를 알아차리는 시각, 다음 고정 Tick 시각의 순서는 하드웨어 시험으로 별도 확인해야 합니다.

현재 코드를 다시 대조한 결과, 지상통제가 활성화된 동안 남아 있는 축 입력은 그 상태에서는 소비되지 않습니다. 다만 연결 해제 시 그 값을 지우지 않으므로, 지상통제 종료와 재개 사이의 대기 입력 수명은 직접 검증된 정책으로 설명할 수 없습니다. 이 경로를 안전 동작으로 의존하려면 입력 소유권을 넘길 때 오래된 축 값이 제거되는지도 별도 회귀 확인이 필요합니다.

## 재발 방지와 현재 한계

- 연결 해제 처리는 연결 상태 자체가 아니라 연결됨에서 끊김으로 바뀌는 순간에 한 번 실행합니다.
- 대기 중인 안전 명령은 다음 시뮬레이션 Tick이 적용할 때까지 보존되어야 합니다.
- 지상통제가 입력을 소유할 때 게임패드 해제 처리가 다른 입력을 덮어쓰지 않는지 확인합니다.
- 단위 시험은 연결 해제 정책 함수가 고르는 동작을 확인합니다. 앱의 입력 대기열 처리와 실제 장치 분리 동작은 별도 확인 대상입니다.
