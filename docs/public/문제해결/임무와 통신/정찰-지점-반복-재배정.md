# 로터 고장 뒤 정찰 지점이 반복 배정된 문제

## 증상

M02 정찰 중 추종 드론 한 대의 로터를 고장 내면 해당 드론은 안전 착륙했지만, 남은 편대가 재집결 단계로 넘어가지 못했습니다. 자동 시험은 정해 둔 최대 Tick까지 진행됐는데도 임무가 M02에 머물렀습니다.

## 처음 의심한 부분

실패한 드론은 리더와 통신 경로가 없었고, 다른 드론의 위치에 따라 중계 경로가 달라질 수 있었습니다. 링크 거리를 늘려 시험했지만 같은 증상이 남았습니다. 통신 설정만으로 설명되지 않는다는 점을 확인하고, 임무 배정 상태를 살펴봤습니다.

## 원인 확인

실패 당시 기록에서 고장 기체는 안전 착륙 상태였고, 정찰 지점은 다시 배정 대기열에 남아 있었습니다. 다른 드론은 이륙 준비 상태로 돌아가 있었지만, 기록된 배정 버전만으로 같은 지점의 반복 횟수를 단정할 수는 없었습니다.

코드 흐름을 따라가 보니 원인이 드러났습니다. 고장 기체의 임무 권한이 풀리면 리더는 그 기체의 정찰 지점을 재배정 대기열에 넣습니다. 다른 드론에 지점을 전달해 대기열에서 꺼낸 뒤에도, 고장 기체의 만료 시각이 그대로 남아 있었습니다. 고장 상태는 계속 권한을 넘길 수 있는 상태로 판정됐고, 다음 Tick에 같은 지점을 다시 대기열에 넣었습니다. 새 담당자에게 경로가 반복 전달되며 이륙과 경로 설정도 다시 시작됐습니다.

## 수정

정찰 지점을 대기열에 넣을 때 이전 담당자의 임무 만료 시각을 0으로 초기화했습니다. 0은 더 이상 유효한 임무 권한이 없다는 뜻입니다. 이 값을 확인해 이미 넘긴 지점을 같은 기체가 다시 등록하지 않게 했습니다. 새 담당자에게는 새 임무 권한과 만료 시각을 부여합니다.

## 결과와 검증

Windows Release 전체 빌드를 마쳤고 CTest 35개가 모두 통과했습니다. 통합 시험은 M02 중 추종 드론 한 대의 로터 고장을 넣어 다음 흐름을 확인합니다.

1. 고장 기체가 안전하게 착륙합니다.
2. 고장 기체의 정찰 지점이 다른 드론에 한 번 배정됩니다.
3. 나머지 세 대가 재집결하고 출발 지점으로 복귀해 착륙합니다.

리더 고장, 통신 장애와 기체 고장이 함께 발생하는 상황, 실제 무선 장비의 동작은 이 시험 범위에 포함하지 않았습니다.

## 재발 방지

재배정 시험은 새 담당자가 목표를 받았는지만 확인하지 않습니다. 같은 목표가 한 번만 배정되는지, 이전 담당자의 권한이 해제된 뒤 다시 대기열에 들어오지 않는지도 확인합니다.
