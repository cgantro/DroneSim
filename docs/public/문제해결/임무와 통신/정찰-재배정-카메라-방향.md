# 재배정된 드론이 점검면을 등지고 촬영을 놓친 문제

## 증상

네 대가 점검 구역을 나눠 맡는 통신 장애 시나리오에서, 원래 담당 드론의 연결이 끊기면 미완료 구역을 다른 드론에 넘깁니다. 구역에 도착했는데도 촬영 확인이 끝나지 않아 정찰 임무가 실패하는 경우가 있었습니다.

강체 모의 시험에서 `sector-2`는 `scout-2`에서 `scout-3`으로 다시 배정됐습니다. 시험 결과에서 `scout-3`은 목표 위치 근처인 `(14.000016, 0.000002, 1.501324)m`에 있었지만, 마지막 촬영 판정은 `outside_frame`이었습니다. 위치 도착만으로 촬영 성공을 처리하지 않아 실패가 드러났습니다.

## 원인 확인

점검면 중심은 `(22, 0, 0.62)m`, 바깥쪽을 향하는 면의 법선은 `(-1, 0, 0)`입니다. 이 면을 촬영하려면 드론은 면의 서쪽에 자리 잡고 동쪽, 즉 `+X` 방향을 바라봐야 합니다.

하지만 재배정된 드론은 시작 위치 `x=20m`에서 목표 `x=14m`로 이동합니다. 기존 경유점 처리는 이동 방향을 바라보도록 목표 자세를 정했기 때문에 카메라도 서쪽을 향했습니다. 실패 당시 기록된 기체 방향은 약 `-2.406rad`였고, 카메라 시야가 점검면을 향하지 않아 모서리가 화면 안에 들어오지 않았습니다.

카메라 판정은 거리만 확인하지 않습니다. 점검면의 네 모서리가 모두 영상 범위에 들어오는지도 검사하므로, 목표 위치에 도착해도 카메라 방향이 틀리면 촬영으로 인정하지 않습니다.

## 수정

경유점 명령에 선택적으로 목표 방향을 지정할 수 있게 했습니다. 일반 이동은 기존처럼 경유점을 바라보고, 점검면이 있는 정찰 임무는 경유점과 점검면 중심을 잇는 방향을 별도로 계산합니다. 그래서 드론은 이동 경로를 따라가면서 카메라로 점검면을 바라볼 수 있습니다.

잘못된 숫자가 목표 방향으로 들어오면 명령을 거부합니다. 점검면이 없는 일반 임무에는 새 방향을 적용하지 않습니다.

## 검증 결과

Windows Release 빌드에서 운동학과 AirSim 강체 모의의 재배정 시나리오를 실행했습니다. 두 모의 방식 모두 네 구역을 완료했고, 다시 배정된 구역에서도 카메라 프레임 조건이 `Ready`가 됐습니다. 같은 빌드에서 전체 CTest 30개와 Viewer 시작 시험도 통과했습니다.

Viewer 시작 시험은 창이 열리는지만 확인합니다. 실제 화면에서 카메라 배치와 임무 장면을 사람이 확인한 결과는 아닙니다. 실제 비행에서 같은 방향 제어가 적절한지도 검증하지 않았습니다.

## 재발 방지

정찰 시험은 목표 위치 도착과 영상 촬영 조건을 따로 확인합니다. 특히 면의 위치·법선, 카메라 시야각, 목표 방향을 함께 넣어 재배정 뒤에도 촬영이 되는지 검사합니다. 자세만 맞춰 시험이 통과하도록 경로 목표를 바꾸지 않습니다.

현재 구현 상태와 남은 확인 항목은 [기능 현황](../../../../SPEC.md)에서 확인할 수 있습니다.
