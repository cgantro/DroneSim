# Linux CI에서 기록 재생 시험이 시간 제한에 걸린 문제

## 증상

2026년 10월 22일 Ubuntu 24.04의 자동 시험에서 지상통제 기록·재생을 확인하는 시뮬레이터 시험이 실패했습니다. 시험 로그에는 앱 종료 코드 `4`와 UDP 응답 시간 초과가 함께 남았습니다. [네이티브 시험 기록](https://github.com/cgantro/DroneSim/actions/runs/39826253649)과 [계측·커버리지 시험 기록](https://github.com/cgantro/DroneSim/actions/runs/39826253629)은 소스 리비전 `7855c460`에서 발생했습니다.

## 원인

네트워크 스모크 실행에는 재생이 끝나기 전에 15초가 지나면 종료하는 제한이 있었습니다. 녹화·재생 시험은 UDP 응답을 기다리는 단계가 여러 번 있어, 이 제한이 먼저 끝나면 시뮬레이터가 코드 `4`로 종료하고 이후 명령은 응답을 받지 못합니다. 로그의 종료 코드와 제한 조건이 일치해, 이 시험에서 보인 UDP 시간 초과는 앱이 먼저 종료된 뒤에 나타난 결과로 확인했습니다.

느린 화면 처리, 스케줄링, 계측 중 무엇이 실행을 늦췄는지는 따로 측정하지 않았습니다. 따라서 특정 환경 요소를 원인으로 단정하지 않습니다.

## 수정

네트워크 스모크 실행 제한을 30초로 늘리고, 시험은 최대 35초까지 앱 종료를 기다리도록 맞췄습니다. 제한 자체는 남겨 두어 재생이 끝나지 않을 때 무한히 기다리지 않게 했습니다.

## 확인 결과와 한계

수정한 Windows Release에서는 해당 시험이 0.93초에 통과했고, 전체 CTest 20개도 통과했습니다. 이 수정이 포함된 코드는 아직 GitHub Actions에서 실행하지 않아 Linux 재검증은 남아 있습니다. 이 기록은 자동 시험에서 발생한 종료 문제를 다루며, 사용자의 지상통제 창에서 발생하는 UDP 시간 초과까지 해결됐다는 뜻은 아닙니다.
