# 웹 시뮬레이터가 로딩 화면에서 멈춘 문제

## 증상

웹 페이지는 열렸지만 로딩 문구가 사라지지 않았고, 장면도 나타나지 않았습니다. 사용자의 브라우저에서는 개발자 도구를 열기 어려울 만큼 페이지가 응답하지 않았습니다.

처음에는 큰 지도나 모델 파일을 받느라 늦는 상황처럼 보였습니다. 하지만 이번 실행에서 JavaScript와 WebAssembly 파일 요청은 모두 성공했습니다. 브라우저 자동 검사에서도 WebAssembly 런타임 초기화와 C++ 실행 함수 진입을 확인했습니다. 파일을 못 받아 생긴 문제는 아니었습니다.

## 원인 확인

화면 문구만으로는 초기화가 어디까지 진행됐는지 알 수 없었습니다. 개발자 도구도 사용할 수 없어, 웹 빌드 결과물을 자동 Chromium에서 직접 실행하고 시작 단계마다 별도 시험 서버에 진행 신호를 보내도록 했습니다. 이렇게 하면 화면을 그리는 쪽이 멎어도 검사 로그에는 마지막 시작 단계가 남습니다.

첫 실행에서는 C++ 앱 객체를 만들기 시작한 뒤 더 진행하지 않았습니다. 다음 실행에서 모의 코어 내부를 나눠 기록하자 `ECS 저장소와 Flecs 월드 생성` 단계에서 멈췄습니다. 아직 드론·카메라 시스템이나 화면 렌더러를 만들기 전이었습니다.

원인은 WebAssembly 스택 크기였습니다. Emscripten의 기본 스택은 64KB인데, Flecs가 월드를 초기화할 때 이 크기로는 부족했습니다. Flecs 개발자 이슈에도 `ecs_init()` 중 스택 오버플로가 나며 1MB로 늘려 해결한 사례가 있습니다. [Flecs 이슈 #1042](https://github.com/SanderMertens/flecs/issues/1042)

## 수정

웹 시뮬레이터와 웹용 시나리오 실행 파일의 스택 크기를 1MB로 늘렸습니다. 네이티브 실행 설정은 바꾸지 않았습니다.

## 확인 결과

수정 전에는 같은 Chromium 검사가 30초 안에 첫 화면을 확인하지 못했습니다. 수정 후에는 Flecs 월드 생성, 드론·카메라 시스템 등록, 그래픽 초기화와 첫 프레임 표시까지 이어졌습니다.

GitHub Actions 실행 [40214655300](https://github.com/cgantro/DroneSim/actions/runs/40214655300)에서 Emscripten 빌드와 창 없이 실행한 Chromium의 첫 화면 검사가 통과했고, 이어 GitHub Pages 배포도 성공했습니다. 이 검사는 실제 사용자의 브라우저가 아니라 Ubuntu의 Chromium과 소프트웨어 WebGL로 실행했습니다.

## 왜 앞선 확인으로 찾지 못했나

이전 웹 문제 해결 기록에는 브라우저 메인 스레드에서 반복문을 계속 돌린 문제도 있었습니다. 그 문제를 고친 뒤 웹 빌드와 Pages 배포는 성공했지만, 당시 자동 검사는 페이지를 브라우저로 열어 첫 화면까지 확인하지 않았습니다. 빌드가 성공해도 웹 실행까지 성공한 것은 아니었습니다.

이번에는 브라우저 실행 검사를 배포 전에 넣었습니다. 앞으로는 빌드 성공만으로 웹 실행이 정상이라고 판단하지 않고, 자동 브라우저가 첫 프레임까지 그리는지 확인합니다.
