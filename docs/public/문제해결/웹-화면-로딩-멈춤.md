# 웹 시뮬레이터가 불러오기 화면에서 멈춘 문제

## 증상

배포 페이지를 열면 불러오기 안내가 남고 시뮬레이터 장면이 나타나지 않았습니다. 새로 연 페이지에서도 같은 안내가 보였고, 화면 상태를 읽는 브라우저 도구는 응답 제한 시간 안에 페이지 정보를 가져오지 못했습니다.

## 처음 확인한 내용

처음에는 장면 자료가 너무 커서 내려받기가 끝나지 않는 상황을 의심했습니다. 산악 지도와 고해상도 기체 모델은 실행 장면에 필요하지 않아 이미 배포 대상에서 제외한 상태였습니다. 배포 서버에서 다시 받은 파일 크기는 다음과 같았습니다.

| 파일 종류 | 받은 크기 |
| --- | ---: |
| 웹 문서 | 2.6KB |
| 실행 코드 | 154KB |
| WebAssembly 모듈 | 903KB |
| 보조 자료 묶음 | 8.0KB |

요청은 모두 정상 응답을 반환했습니다. 따라서 큰 장면 자료를 내려받느라 멈춘 현상은 아니었습니다.

## 원인 확인

웹 실행의 시작 경로를 따라가 보니, 창이 닫힐 때까지 `RunFrame`을 부르는 반복문이 브라우저 메인 스레드에서 계속 돌고 있었습니다. 데스크톱 프로그램에서는 일반적인 구조지만, 웹 브라우저에서는 이 스레드가 입력 처리와 화면 갱신도 맡습니다. 반복문이 제어를 돌려주지 않으면 WebAssembly가 내려와도 브라우저가 장면을 그릴 수 없습니다.

Emscripten 문서도 화면을 그리는 프로그램은 `emscripten_set_main_loop` 계열 함수에 반복 작업을 맡기고, 브라우저의 `requestAnimationFrame`에 맞춰 실행하도록 안내합니다. [Emscripten 메인 루프 안내](https://emscripten.org/docs/api_reference/emscripten.h.html)

## 수정

웹에서는 프레임을 한 번 처리한 뒤 브라우저에 제어를 돌려주도록 바꿨습니다. 다음 프레임은 브라우저가 화면 갱신 시점에 맞춰 호출합니다. 프레임 사이에 사용하는 앱 상태는 반복 호출이 끝날 때까지 보관합니다. Windows와 Linux의 기존 프레임 반복 구조는 그대로 둡니다.

## 확인 결과

- Windows Release 빌드가 성공했습니다.
- 핵심 CTest 20개가 모두 통과했습니다. 여기에는 Viewer 화면 스모크 검사가 포함됩니다.
- 웹 CI에서 WebAssembly 구성과 빌드, Pages 배포까지 성공했습니다.
- 브라우저가 화면을 다시 그리는지까지 확인하는 실행 검사는 완료하지 못했습니다. 따라서 배포 파일 생성과 공개 여부는 확인했지만, 브라우저에서의 최종 화면 동작은 아직 직접 검증하지 않았습니다.

## 다음부터 확인할 기준

웹 화면 반복 작업에서는 브라우저가 다음 프레임을 실행할 수 있도록 제어를 돌려줘야 합니다. 빌드 성공만으로 화면이 실제로 그려진다고 판단하지 않고, 브라우저에서 장면 표시까지 확인합니다.
