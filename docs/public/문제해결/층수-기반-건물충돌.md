# 층수로 높이를 계산한 건물이 하늘까지 막던 문제

## 증상

지도의 건물 높이를 층수로 계산해 화면에 세웠는데도, 충돌 계산은 그 높이를 쓰지 않았습니다. 드론이 건물 지붕보다 높이 날아도 건물 외곽을 지나지 못하는 상황이 생길 수 있는 구조였습니다.

## 처음 의심한 점

OSM에 건물 높이가 없으면 안전을 위해 넓게 막는다고 생각하기 쉽습니다. 하지만 층수 정보가 있는 건물까지 높이를 무시하는 것은 별개의 문제였습니다. 자료가 없는 건물과 높이를 추정할 수 있는 건물을 나누어 확인했습니다.

## 원인 확인

현재 지도에는 건물 외곽선 167개가 있습니다. 이 가운데 69개에는 높이값이 있고, 93개에는 층수 정보가 있습니다. 두 정보가 모두 없는 건물은 74개입니다. 층수는 층당 3m를 곱해 화면 높이와 충돌 높이로 바꿉니다. 이 값은 실제 측량값이 아니라 OSM 정보를 바탕으로 한 추정치입니다.

충돌체를 등록하는 과정은 높이값이 OSM의 `height` 태그에서 왔는지만 확인했습니다. 따라서 층수로 높이를 계산한 건물도 높이 미상 건물과 똑같이 2차원 외곽선으로 등록됐습니다. 이 충돌 방식은 동·북 위치만 보고 접촉을 판단하므로 드론의 고도와 관계없이 건물을 통과하지 못하게 합니다.

## 수정

높이 출처 대신 계산된 높이가 0보다 큰지를 기준으로 충돌체를 정하도록 바꿨습니다. OSM 높이값과 층수 기반 추정치가 모두 건물의 바닥부터 지붕까지 유한한 범위를 가진 충돌체로 들어갑니다.

높이와 층수 정보가 모두 없는 건물은 기존처럼 모든 고도에서 막는 2차원 외곽선으로 남습니다. 이 처리는 충돌 누락을 줄이기 위한 보수적 선택이며, 실제 건물 높이나 형상을 뜻하지 않습니다.

## 검증 결과와 남은 한계

수정한 시뮬레이터 코드는 Release 구성에서 컴파일됐고, CTest 22개가 모두 통과했습니다. 다만 현재 실행 중인 시뮬레이터가 실행 파일을 사용 중이어서 새 실행 파일을 다시 연결하지 못했습니다. 따라서 화면에서 드론이 지붕 위를 지나가는 동작은 아직 직접 확인하지 않았습니다.

현재 자료에서 74개 건물은 높이와 층수 정보가 없습니다. 이 건물들은 여전히 모든 고도에서 통과할 수 없습니다. OSM 높이값과 층수 기반 높이도 측량값과 대조하지 않았습니다. 교량 상판 높이와 교각 형상은 별도 공간 자료가 없어 아직 충돌에 들어가지 않습니다.

## 다음에 확인할 점

- 높이 정보가 없는 건물의 높이를 확인할 수 있는 자료를 확보합니다.
- 실행 중인 프로그램을 닫은 뒤 새 Release 실행 파일로 지붕 위 비행과 측면 충돌을 확인합니다.
- 층수에서 계산한 높이는 실제 높이 자료와 구분해 결과를 해석합니다.
