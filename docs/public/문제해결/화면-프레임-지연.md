# 카메라 픽셀을 읽을 때 화면이 멈춘 문제

## 관찰한 현상

숨김 창에서 장면과 EO 카메라를 함께 실행하면 평균 프레임 속도는 높아도 드물게 화면이 오래 멈췄습니다. 화면 읽기 여부를 나눈 5초 측정에서 가장 긴 프레임은 115.04ms였습니다.

## 원인

화면을 그리는 스레드가 `glReadPixels`로 카메라 픽셀을 바로 가져옵니다. 이 호출은 GPU가 해당 화면을 준비할 때까지 CPU를 기다리게 할 수 있습니다. 측정한 프레임과 호출 시간은 다음과 같습니다.

| 측정 구간 | 표본 | p95 | 최댓값 |
| --- | ---: | ---: | ---: |
| EO 픽셀을 읽은 프레임 | 293 | 8.23ms | 115.04ms |
| EO 픽셀을 읽지 않은 프레임 | 1,224 | 2.66ms | 7.06ms |
| `glReadPixels` 호출 | 293 | 3.78ms | 111.20ms |

가장 긴 프레임과 픽셀 읽기 호출이 같은 실행에서 함께 길어졌습니다. 영상 품질 분석의 p95는 4.63ms였고 시뮬레이션 Tick p95는 31.1µs였습니다. 이 측정에서는 동기식 픽셀 읽기가 긴 프레임을 만든 주된 구간으로 확인됐습니다. 다만 측정은 숨김 창과 RTX 3060 Ti 한 대에서 한 번 진행했으므로 다른 그래픽 카드와 드라이버에서도 같은 결과라고 단정할 수 없습니다.

## 현재 상태와 시도한 조치

현재도 픽셀 읽기는 동기식입니다. GPU 픽셀 버퍼를 이용한 비동기 읽기를 시도했지만 Viewer 스모크가 두 번 `0xc0000409` 오류로 종료됐습니다. 정확한 크래시 지점을 확인하지 못해 그 변경은 되돌렸습니다. 따라서 화면 멈춤은 아직 코드에서 해결되지 않았습니다.

실행 조건과 전체 표본은 [화면 읽기 여부를 나눈 측정 결과](../../../benchmarks/results/aerosimlab-eo-readback-correlation-release-2026-10-23.json)에 있습니다. 이전 세 번 측정은 [반복 측정 결과](../../../benchmarks/results/aerosimlab-graphics-repeats-release-2026-10-23.json)에서 볼 수 있습니다.

## 다음 확인

비동기 읽기를 다시 적용할 때는 OpenGL 실행 환경의 수명과 GPU 완료 신호를 함께 확인해야 합니다. 변경 뒤에는 Viewer 실행과 화면·EO 측정을 다시 수행하고, 기존 측정과 같은 조건에서 비교해야 합니다.
