# DEM 경계 밖에서 드론이 지형을 빠져나간 문제

## 증상

DEM이 덮는 지도 범위를 벗어나면 네이티브 강체 비행과 웹 운동학 비행의 결과가 달랐습니다. 강체 모드는 지도 밖을 해발 0m 지면으로 보고 그 위에 멈췄고, 웹은 지형 검사를 건너뛰어 바깥으로 계속 이동했습니다. 실제 높이 자료가 없는 곳에서 지면 접촉을 계산하거나 지도 밖으로 비행할 수 있는 상태였습니다.

## 원인 확인

두 경로의 지형 조회 정책이 서로 달랐습니다. 네이티브는 높이 격자 밖에서 임의로 0m를 반환했습니다. 그래서 그 위치에서도 평지와 충돌할 수 있었습니다. 웹 운동학은 드론 중심이 격자 안에 있을 때만 지면을 확인했습니다. 중심이 경계를 넘으면 지면과 충돌 모두 검사하지 않았습니다.

각 경로의 기존 핵심 시험에 지도 경계를 재현하도록 조건을 바꿔 실행했습니다. 수정 전 웹 시험에서는 드론 중심이 허용 경계 0.7m를 넘어 0.9006m까지 이동했고, 동쪽 속도도 남았습니다. 수정 전 강체 시험에서는 지형 밖에서 가짜 0m 지면에 멈춰 새 조건을 통과하지 못했습니다.

경계 충돌 정보를 물리 엔진에 넘기는 것만으로는 바깥에 있는 기체를 되돌릴 수 있는지도 확인했습니다. 그 방식에서는 중심이 x=3m에 남았고 고도는 약 -36.4m까지 내려갔습니다. 접촉 정보 전달만으로 경계 안 복귀를 보장하지 못한다는 결과였습니다.

## 수정

높이 격자 밖에서는 지면 높이를 만들어 내지 않도록 했습니다. 대신 DEM 사각형을 비행 영역의 경계로 삼고, 기체의 회전된 충돌 상자 전체가 경계 안에 머물도록 위치를 제한합니다. 경계 바깥으로 향하는 속도 성분은 제거합니다. 물리 계산 전과 후에 같은 제한을 적용해, 시작 위치가 지도 밖이거나 한 Tick 이동으로 경계를 넘는 경우도 처리합니다.

웹 운동학에도 같은 비행 영역 제한을 넣었습니다. 화면이나 충돌에 쓸 DEM이 없으면 기존의 평지 동작을 유지합니다.

## 검증 결과와 범위

수정 전 실패하던 경계 시험은 수정 후 통과했습니다. Windows Release에서 시뮬레이션 시험 6개 시나리오 묶음을 실행했고 모두 통과했습니다. 시험은 네이티브 강체 경로와 운동학 경로에서 각각 지도 밖 이동과 경계 방향 속도를 확인합니다. WebAssembly로 다시 빌드해 확인하지는 않았습니다.

이 경계는 DEM 자료의 사각형 범위입니다. 실제 비행 금지 구역이나 지리적 안전 경계가 아닙니다. 지도 경계 모서리에서의 경로 계획, DEM 외부를 포함한 실제 지형, 좁거나 복잡한 비행 구역은 확인하지 않았습니다. DEM을 교체하거나 범위를 바꿀 때는 경계 크기와 시작 위치를 함께 확인해야 합니다.
