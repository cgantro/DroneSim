# 물리값을 AirSim으로 넘길 때 표현 범위를 확인하지 않던 문제

## 문제와 기대 동작

시뮬레이터는 위치와 기체 제원을 `double`로 다루지만, AirSim 내부의 벡터와 기체 파라미터 일부는 `float`입니다. 입력이 `double`에서 유한하다는 사실만으로는 변환 결과도 유효하다고 보장할 수 없습니다. `float`의 최대 범위를 넘는 위치나 질량은 변환 뒤 무한대가 될 수 있고, 너무 작은 양수 질량은 0으로 반올림될 수 있습니다.

물리 월드는 이런 값을 받기 전에 거부하고, 거부 과정에서 현재 강체 상태도 바꾸지 않아야 합니다.

비행 중 재현된 오류는 없었습니다. 코드와 시험 범위를 살펴 AirSim에 값을 넘길 때 빠진 검사를 찾았습니다.

## 원인을 확인한 과정

기체 생성은 질량·관성·크기가 유한한지와 양수인지를 확인했습니다. 위치·속도·바람도 유한한지 확인했습니다. 그러나 이 검사는 `double` 범위만 확인하므로, AirSim에 전달하기 전 `float`으로 바뀌는 값의 허용 범위까지 검사하지 못했습니다.

이전 강체 엔진인 Jolt를 사용하던 때에는 질량·힘·시간의 `float` 범위와 큰 자세값을 다루는 경계 시험이 있었습니다. AirSim으로 교체한 뒤에는 값 변환 코드가 새로 작성됐지만, 해당 경계 시험은 현재 경로에 다시 연결되지 않았습니다. 당시 시험 통과 기록만으로 현재 AirSim 변환도 안전하다고 볼 수 없었습니다.

상태를 직접 바꾸는 경로에도 순서 문제가 있었습니다. 강체가 한 번 진행된 뒤 새 상태를 넣으면 모터와 AirSim 모델을 먼저 초기화하고, 그 다음에 값을 AirSim 형식으로 바꿨습니다. 변환에 실패하면 요청은 거부되더라도 기존 강체는 이미 초기화된 상태일 수 있었습니다.

`double`로 유효한 값도 `float`으로 바꾸면 무한대나 0이 될 수 있습니다. 질량과 크기는 변환 뒤 0이 되면 물리값으로 쓸 수 없습니다. 검사는 원래 값뿐 아니라 AirSim 자료형으로 바꾼 결과에도 필요합니다.

## 수정한 내용

AirSim에 숫자를 전달하는 공통 변환 단계에서 먼저 값이 유한하고 `float` 범위 안인지 확인합니다. 범위를 벗어나면 물리 계산을 진행하기 전에 입력 오류로 처리합니다. 질량·관성·기체 크기·모터 제원처럼 반드시 양수여야 하는 값은 변환 뒤에도 0보다 큰지 확인하므로, 너무 작은 값이 0으로 바뀌는 경우도 거부합니다.

위치와 속도, 바람, 각속도, 자세 성분과 충돌 깊이도 같은 범위 확인을 거칩니다. 기존의 NaN·무한대 검사와 양수 검사는 그대로 둡니다. 공통 변환 단계는 값이 AirSim의 `float` 범위 안에 드는지 확인하고, 물리값 검사는 질량·크기처럼 양수여야 하는 조건을 확인합니다.

강체 상태를 바꿀 때는 AirSim 형식 변환을 먼저 끝낸 뒤 모델 초기화와 상태 변경을 시작하도록 순서를 바꿨습니다. 입력이 거부되면 이전 강체 상태가 그대로 남습니다.

값 변환에 실패하면 강체 상태도 그대로 남아야 합니다. 먼저 새 값을 모두 변환한 뒤 모델과 상태를 바꾸도록 순서를 고쳤습니다. 일부 값만 바뀐 채 요청이 거부되는 상황을 막습니다.

## 검증 결과

기존 물리 시험 묶음에 다음 경계 확인을 더했습니다. CTest 항목 수는 늘리지 않았습니다.

| 입력 | 기대 결과 | 확인 내용 |
| --- | --- | --- |
| `float` 최대값의 두 배인 바람 속도 | 거부 | 잘못된 바람이 AirSim에 전달되지 않음 |
| `float` 최대값의 두 배인 위치 | 거부 | 이미 진행된 강체의 위치가 요청 거부 뒤에도 유지됨 |
| `float` 최대값의 두 배인 질량 | 거부 | 생성 단계에서 표현할 수 없는 제원을 차단 |
| `float` 변환 뒤 0이 되는 양수 질량 | 거부 | 물리 모델에서 질량 0이 되는 경우를 차단 |

코드는 위치·속도·자세·각속도, 바람, 기체 제원과 접촉값을 `float`으로 바꾸기 전에 범위를 검사합니다. 자동 시험은 표의 바람·위치·질량 경계를 다룹니다. 속도·자세·각속도·접촉값의 초과 입력은 각각 회귀 시험에 넣지 않았습니다.

Windows Release 빌드에서 CTest 20개가 모두 통과했습니다. 이 결과로 입력 범위와 요청 거부 뒤 상태 보존을 확인했습니다. 물리 모델의 정확도나 모든 극단값에서의 안정성을 확인한 시험은 아닙니다.

## 남은 한계

이번 수정은 `double`에서 `float`으로 바꿀 때 생기는 무한대와 0을 막습니다. 표현 가능한 값도 실제 운용 범위를 벗어날 수 있으므로 위치와 풍속의 상한은 기체 제원과 장면 크기에 맞춰 정해야 합니다. 시험은 AirSim 입력 범위와 요청 거부 뒤 상태를 확인했습니다. 바람 반응과 제어 안정성, 과거 접근 위반과의 관계는 조사하지 않았습니다.
