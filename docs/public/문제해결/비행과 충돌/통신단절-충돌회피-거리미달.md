# 통신 단절 뒤 충돌 회피가 실제 위치를 놓친 문제

> **현재 상태 — 2026년 10월 28일:** 네 대 정찰 통합 시험에서 발견한 경로 예측과 회피 목표 문제를 수정했습니다. Release 전체 CTest 31개와 정찰·강체 재배정 시나리오가 통과했습니다. 측정 범위는 아래의 [최신 재검증](#최신-재검증-2026년-10월-28일)을 확인하세요.

## 증상

네 대의 드론이 구역을 조사하다 두 번째 드론의 통신이 끊기면, 맡고 있던 구역을 다른 드론에 다시 배정합니다. 운동학 시험은 통과했지만 강체 물리 시험에서는 두 기체의 실제 중심 간 거리가 1m 기준보다 가까워졌습니다.

초기 강체 재현은 1,200 Tick 동안 실행했습니다. 안전거리 2m, 예측 시간 3초, 옆 이동 3m를 설정했을 때 실제 최소 간격은 0.212m였고, 시험을 통과하지 못했습니다. 같은 실행의 예측 최소 거리 기록은 1.455m, 회피 시작 횟수는 1회였습니다. 두 최소값은 실행 전체에서 각각 따로 집계한 값이므로, 같은 시점의 예측 거리와 실제 거리를 직접 비교한 결과는 아닙니다.

## 원인 확인

처음에는 이 결과만으로 예측 시간, 회피 방향, 물리 제어 가운데 어느 부분이 원인인지 확정할 수 없었습니다. 통신 상태 갱신과 회피 경로가 만들어지는 흐름을 확인했습니다.

하트비트 시간 초과 뒤에도 관측 자료에는 마지막으로 받은 위치와 속도가 남습니다. 기존 회피 계산은 통신 단절 뒤에도 그 속도가 계속 유지된다고 가정했습니다. 그래서 마지막 위치에 `속도 × 경과 시간`을 더해 현재 위치를 추정했습니다. 하지만 연결이 끊기면 새 상태를 받지 못하므로, 오래된 속도가 계속 맞는다고 보장할 수 없습니다. 실제 기체가 정지하거나 다른 동작을 시작해도 이 계산은 예전 방향으로 이동한다고 추정할 수 있습니다.

통신이 끊긴 기체를 마지막 확인 위치의 정지 장애물로 바꾸자 회피 동작이 더 자주 시작됐습니다. 첫 수정 뒤에도 최소 간격은 0.637m에 그쳤고, 임무 하나는 기한을 넘겼습니다. 회피 목표가 임무 목적지를 기준으로 잡히는 점을 확인했습니다. 강체 모의에서는 목적지까지 남은 거리와 관성이 함께 작용하므로, 위험을 감지한 위치에서 옆으로 피하는 목표를 만들고 위험이 사라질 때까지 유지하도록 바꿨습니다.

통신 시간 초과 때 `hold_position`을 선택하더라도 기체가 아직 이륙 중이면 위치 명령을 받을 수 없습니다. 기존 코드는 한 번만 시도했기 때문에 안전 동작을 적용하지 못한 채 지나갈 수 있었습니다.

## 수정

통신이 끊긴 기체는 오래된 속도로 현재 위치를 외삽하지 않고, 마지막으로 확인한 위치의 정지 장애물로 계산합니다. 회피가 시작되면 선택된 드론의 현재 위치를 기준으로 옆 이동 목표를 한 번 만들고, 상대도 임무 중이면 위험 예측이 안전거리의 1.5배를 넘어설 때까지 같은 목표를 유지합니다. 상대가 정지 장애물이면 설정 안전거리까지 벌어졌을 때 회피를 풉니다. 위험 구간을 벗어나면 임무 경로를 다시 적용합니다.

`hold_position`을 선택한 시나리오는 기체가 위치 명령을 받을 수 있는 상태가 될 때까지 안전 동작을 다시 시도합니다. 명령이 실제 적용된 경우에만 결과 기록에 남깁니다. 기본 동작은 이전처럼 마지막 명령을 계속 수행하는 `continue_last_command`입니다.

최종 반복 시나리오는 안전거리 2m, 예측 시간 6초, 옆 이동 5m를 사용합니다. 운동학은 320 Tick, 강체 물리는 1,800 Tick으로 실행하고, 실제 최소 중심 간 거리 1m 이상을 통과 기준으로 둡니다.

## 검증 결과와 범위

2026년 10월 24일 Release 전체 시험 20개가 통과했습니다. 대표 통신 장애 시나리오는 준비 실행 1회 뒤 모의 방식별 세 번 반복했고, 모두 네 구역을 완료했습니다. 이는 당시 코드와 해당 시나리오 설정의 결과입니다.

| 모의 방식 | Tick 수 | 임무 완료 | 통신 상태 미확정 | 실제 최소 중심 간 거리 | 임무 실행 시간 중앙값 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 운동학 | 320 | 4/4 | 1대 | 3.417m | 2.11ms |
| AirSim 강체 | 1,800 | 4/4 | 1대 | 2.221m | 12.77ms |

초기 실패 실행과 최종 반복은 Tick 수, 예측 시간, 옆 이동 거리가 다릅니다. 그러므로 두 결과의 차이를 충돌 회피 개선율로 해석하지 않았습니다. 최종 결과는 한 시나리오의 재현 시험입니다. 실제 UDP 손실, PX4의 기체 자체 통신 상실 기능, 기체 크기를 반영한 충돌 여부는 검증하지 않았습니다. 최소 거리는 기체 중심 사이 거리이며, 다른 배치와 속도에서도 같은 안전성을 보장하지 않습니다.

실행별 설정과 수치는 [반복 측정 원자료](../../../../benchmarks/results/archive/aerosimlab-full-benchmark-release-2026-10-24-c55c76de.json), 다른 부하 시험은 [성능 검증 안내](../../성능검증.md)에서 확인할 수 있습니다.

## 재발 방지

통신 상태가 오래된 기체의 속도를 현재까지 그대로 외삽하지 않습니다. 충돌 시험은 예측 거리만 확인하지 않고, 실제 최소 간격·회피 실행 여부·임무 완료를 함께 검사합니다. 새로운 장애물·속도·배치 조건을 추가해 범위를 넓힐 때는 조건별 시험 결과를 따로 기록합니다.

## 최신 재검증 — 2026년 10월 28일

첫 재검증에서는 전체 Release 시험 31개 중 30개가 통과했습니다. 네 대 정찰 시나리오의 기준은 기체 중심 간격 2m 이상과 네 과제의 기한 내 완료입니다. 이 실행에서 최소 간격은 1.47m였고 `scout-1`은 기한을 넘겼습니다. 추적 기록에 회피 명령이 74회 남아, 회피 목표가 반복해서 시작되고 취소되는 현상도 확인했습니다.

원인을 찾을 때는 예측값과 실제 위치를 같은 Tick에서 비교했습니다. 연결이 끊긴 기체는 마지막 확인 위치에 멈춰 있다고 계산했지만, 기존 예측은 임무 중인 기체의 속도를 6초 동안 계속 연장했습니다. 운동학 기체는 경유점에 도착하면 멈추므로, 이 계산은 목표 지점에서 멈추는 실제 시험 경로와 달랐습니다. 임무 경로를 끝없이 이어 계산한 결과가 충돌 위험을 과하게 잡고, 드론이 서로의 목표 쪽으로 비키게 만들었습니다.

충돌 예측은 각 기체가 현재 경유점까지 이동한 뒤 멈추는 경로를 사용하도록 바꿨습니다. 회피 목표도 충돌 예상 지점 옆에만 두지 않고, 그 지점을 지난 뒤로 옮겼습니다. 한쪽 경로가 비켜 나오는 동안 반대쪽 드론도 반대편으로 지나가도록 목표를 짝지었습니다.

수정 뒤 같은 Release 시험 묶음 31개가 모두 통과했습니다. 주요 재검증 결과는 다음과 같습니다.

| 시험 | 실제 최소 중심 간격 | 임무 결과 | 회피 명령 |
| --- | ---: | ---: | ---: |
| 운동학 네 대 정찰·통신 단절 | 3.42m | 4개 구역, Tick 254 완료 | 2회 |
| AirSim 강체 네 대 정찰·통신 단절 | 4.11m | 4개 구역, Tick 865 완료 | 0회 |
| AirSim 강체 저전력·통신 단절 재배정 | 4.67m | 3개 구역, Tick 975 완료 | 2회 |

강체 정찰 시험에서 회피 명령이 없었던 이유는 해당 경로의 예측 최소 간격이 기준보다 컸기 때문입니다. 회피가 필요하지 않은 경로에서는 불필요한 방향 전환을 만들지 않습니다. 최소 간격은 기체 중심 사이 거리이며, 기체 외형의 충돌이나 다른 배치·속도 조건까지 보증하지 않습니다. 실제 시험 설정과 전체 통과 결과는 Release 실행과 [기능 현황](../../../../SPEC.md)에서 확인할 수 있습니다.
