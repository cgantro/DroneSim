# 맞닿은 충돌 모양이 후보 검사에서 빠지던 문제

## 증상

충돌 계산은 먼저 빠른 후보 검사를 하고, 후보로 남은 쌍에만 회전 상자 검사를 합니다. 두 상자가 정확히 맞닿는 경우에도 정밀 검사는 접촉으로 판정하도록 되어 있었지만, 후보 단계에서 같은 쌍을 건너뛸 수 있었습니다. 두 단계의 경계 비교가 서로 달랐기 때문입니다.

이 문제는 일반적인 겹침보다 경계에 놓인 접촉에서 나타납니다. 후보 검사에서 제외되면 그 쌍의 접촉 정보가 AirSim으로 전달되지 않습니다.

## 원인 확인

후보 검사는 두 드론 중심 사이 거리의 제곱이 두 외접구 반경 합의 제곱보다 **크거나 같으면** 정밀 검사를 건너뛰었습니다. 정밀 상자 검사는 분리 거리가 겹침 한계보다 **클 때만** 접촉이 아니라고 판단했습니다. 그래서 두 상자가 한 점에서 맞닿은 경계에서는 앞 단계가 후보를 버리고 뒤 단계는 접촉으로 보는 차이가 생겼습니다.

재현 시험에는 반크기가 3m, 4m, 12m인 상자 두 개를 사용했습니다. 한 상자의 중심을 `(0, 0, 0)`, 다른 상자의 중심을 `(6, 8, 24)`에 두면 외접구 반경은 각각 13m이고 중심 간 거리도 26m입니다. 거리 제곱과 반경 합의 제곱은 모두 676입니다. 정밀 상자 검사는 모서리 접촉을 찾았지만, 기존 후보 검사는 이 쌍을 제외했습니다.

## 수정

후보 검사도 거리가 반경 합과 같은 경우에는 쌍을 남기도록 바꿨습니다. 서로 떨어진 쌍은 계속 건너뛰고, 경계에 놓인 쌍만 정밀 검사까지 진행합니다. 접촉 형상이나 AirSim의 반응 계산은 바꾸지 않았습니다.

## 검증 결과와 범위

재현 조건을 기존 물리 시험 묶음에 추가했습니다. 수정 전에는 정밀 검사에서 접촉을 찾았는데도 후보 검사가 `false`를 반환해 시험이 실패했습니다. 비교를 맞춘 뒤 해당 물리 시험과 Windows Release 전체 CTest 20개가 통과했습니다.

이번 검증은 두 상자가 정확히 맞닿는 조건을 확인했습니다. 다양한 무작위 배치에서 후보 누락이 없는지, 다른 컴파일러·플랫폼에서도 같은지, 수정으로 성능이 달라졌는지는 확인하지 않았습니다.

## 재발 방지

빠른 후보 검사와 정밀 검사가 접촉 경계를 같은 방식으로 해석하는지 함께 확인합니다. 후보 검사가 접촉을 확정하지 않는 단계라면, 경계 조건에서 실제 접촉 가능성이 있는 쌍을 제거하지 않도록 합니다.
