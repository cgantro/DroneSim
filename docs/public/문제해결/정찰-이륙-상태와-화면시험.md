# 정찰 중 이륙 상태가 멈추고 화면 시험이 실패한 문제

## 증상

시뮬레이터 화면에서 정찰 임무가 `목표 1/5: 이륙 중`에 머물렀습니다. 화면에는 모의 시간 99.02초, 5,941번째 Tick, 위치 X=-472m가 표시됐고 드론은 보이지 않았습니다. 기대 동작은 이륙한 뒤 첫 정찰 위치로 이동하는 것입니다.

같은 빌드의 자동 화면 시험도 종료할 때 `0xC0000409` 오류로 실패했습니다. 이 코드는 Windows가 스택의 보안 값이 손상된 것을 감지했을 때 나타납니다. 화면 정지와 종료 오류가 같은 원인인지 먼저 분리해 확인했습니다.

## 가설과 확인

처음에는 바람이나 강체 비행 제어 때문에 이륙이 끝나지 않았을 가능성을 확인했습니다. 이전 시험은 지형만 적용했으므로 화면과 같은 조건인지 확인하기 어려웠습니다. 이번에는 시뮬레이터가 읽는 건물 충돌체와 같은 바람 변화 주기·세기를 적용하고, 이전 출발점과 현재 출발점에서 각각 100초 동안 이륙을 반복했습니다. 두 위치 모두 `taking_off`를 벗어났습니다. 따라서 강체 이륙만으로 화면의 장시간 정지를 재현하지는 못했습니다.

화면에서 기체가 보이지 않는 원인도 따로 확인했습니다. 장면 카메라는 기체 뒤 18m, 위 10m에서 기체를 따라갑니다. 캡처 좌표와 기본 진행 방향을 적용한 재현 시험에서 카메라가 체육관 안에 들어갔습니다. 카메라가 건물 안에 있으면 외벽이 화면을 가리고 기체와 주변 장면은 보이지 않습니다. 반면 그 좌표의 기체 중심은 높이 정보가 있는 건물 충돌 부피 안에 있지 않았습니다. 두 현상은 같은 원인으로 확인되지 않았습니다.

화면에는 이전 출발점인 X=-472m가 표시되어 있고, 현재 소스의 출발점은 X=-410m입니다. 실행 중인 프로그램이 사용하는 파일도 최신 카메라 보정 코드보다 먼저 만들어졌습니다. 화면이 그 프로세스에서 나온 것이라면 이전 실행 파일을 보고 있는 셈입니다. 다만 창 응답 상태나 CPU 사용량만으로 모의 Tick이 진행되는지는 확인할 수 없습니다.

자동 화면 시험의 종료 오류는 별도로 추적했습니다. 실행 진입점이 사용하는 앱 클래스 정의는 바뀌었지만, 진입점 객체는 그 변경 뒤에도 다시 컴파일되지 않았습니다. Ninja 의존성 기록을 비교하니 진입점 객체에는 포함 헤더가 0개였고, 앱 구현 객체에는 270개가 기록돼 있었습니다. 오래된 진입점 객체는 이전 클래스 크기를 기준으로 스택 공간을 잡고, 새 앱 구현은 그보다 큰 객체를 사용했습니다. 실행 중 바람 난수 생성기의 상태를 갱신할 때 스택 경계를 넘어 보안 값이 덮였고, 종료 시점에 오류가 발견됐습니다.

## 수정

잘못된 의존성 기록이 있던 진입점 객체 파일만 지우고 다시 빌드했습니다. 새 객체에는 앱 헤더를 포함한 185개 의존성이 기록됐습니다. C++ 비행 동작은 이 문제를 고치기 위해 변경하지 않았습니다.

카메라 가림은 출발점을 옮기는 것만으로 처리하지 않도록 보정했습니다. 원하는 카메라 위치가 건물 안이면 기체를 향해 0.5m 간격으로 확인하고, 건물 밖인 위치를 찾으면 그곳으로 카메라를 옮깁니다. 카메라가 원래 건물 밖에 있으면 기존 위치를 유지합니다. 건물 외곽 안에 점이 있는지 확인하는 계산은 경로 탐색과 물 영역 판정이 함께 쓰도록 한곳으로 모았습니다.

## 검증 결과

Release 빌드에서 다음 시험을 실행했습니다.

| 시험 | 결과 |
| --- | --- |
| 지형·높이 정보가 있는 건물 충돌체·고정 바람 조건에서 두 출발점 이륙 | 각 100초 실행, 두 위치 모두 `taking_off`를 벗어났고 마지막 높이가 지면보다 0.5m 이상 높음 |
| 카메라가 체육관 안에 들어가는 위치 확인 | 건물 안에 들어감을 재현하고, 보정 위치는 확인된 건물 밖으로 이동 |
| 정찰 시나리오와 다중 기체 회귀 시험 | 통과 |
| 자동 화면 실행·종료 시험 | 수정 전 실패, 진입점 재컴파일 뒤 통과 |

관련 회귀 시험과 자동 화면 실행·종료 시험은 재컴파일 뒤 통과했습니다. 건물 충돌체와 바람을 넣은 이륙 시험을 추가한 뒤 시뮬레이션 시험 6개 묶음도 모두 통과했습니다. 시뮬레이터 앱 라이브러리는 최신 소스로 다시 연결됐지만, 실행 중인 프로그램이 실행 파일을 사용하고 있어 최종 실행 파일 연결은 Windows 오류 `LNK1104`로 실패했습니다. 따라서 카메라 보정이 포함된 새 프로그램은 아직 직접 실행하지 못했습니다.

## 남은 확인과 재발 방지

스택 손상은 자동 화면 시험 종료 오류의 원인이었습니다. 기체가 보이지 않은 현상은 관찰 카메라가 건물 안에 들어간 경우로 확인했고, 건물 밖으로 카메라를 옮기는 계산과 회귀 시험을 추가했습니다. 이전 위치와 현재 위치의 강체 이륙은 지형·건물 충돌체·바람 조건에서 100초 시험을 통과했습니다. 그래도 정찰 임무 전체를 실행한 상태에서 99초 넘게 `taking_off`로 남은 원인은 아직 찾지 못했습니다. 새 실행 파일에서 전체 정찰 임무와 EO 영상이 정상 동작하는지도 직접 확인하지 못했습니다. 그러므로 임무 정지까지 해결됐다고 보지는 않습니다.

출발 위치와 드론 방향이 바뀌어도 카메라가 건물 안에 들어가지 않게 매 프레임 위치를 확인합니다. 실행 중인 프로그램이 있으면 종료한 뒤 새 실행 파일을 연결하고, 실제 정찰 임무에서 모의 시간·Tick·비행 상태가 함께 갱신되는지 확인해야 합니다. 창이 응답한다는 사실만으로 임무가 진행 중이라고 판단하지 않습니다. 빌드 뒤에는 자동 화면 시험을 실행하고, 앱의 클래스 정의가 바뀌면 진입점 객체도 새 정의로 다시 빌드됐는지 확인합니다. 의존성 기록이 비어 있으면 실행 파일을 사용하기 전에 해당 객체를 다시 빌드합니다.
