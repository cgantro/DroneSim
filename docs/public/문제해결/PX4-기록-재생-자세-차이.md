# PX4 비행 기록을 재생하자 자세와 궤적이 달라진 문제

## 증상: 같은 시작 자세와 모터 명령인데 비행 경로가 빠르게 벌어졌다

PX4 공개 기록의 약 12초부터 16초까지를 골라 AirSim 강체 모의에 재생했습니다. 시작 위치와 속도, 자세, 각속도를 기록에 맞추고 네 모터 명령도 시간 순서대로 넣었습니다. 그런데 시뮬레이터는 첫 1초 안에 지면에 닿았고, PX4 기록과 자세 차이가 빠르게 커졌습니다.

4초 구간 비교에서 위치 오차의 제곱평균제곱근은 0.698m, 자세 오차는 76.3도였습니다. 자세 오차는 0.5초에 이미 27.1도였습니다. 이 결과는 [비행 기록 재생 비교](../기술검토.md#4초-구간을-재생해-본-결과)에 전체 수치와 함께 정리했습니다.

이 기록은 실제 위치를 측정한 모션 캡처가 아니라 PX4의 추정 상태입니다. 따라서 두 궤적이 달라졌다는 사실만으로 AirSim 모델이 실제 기체와 다르다고 결론 내릴 수는 없습니다. 먼저 입력을 잘못 옮겼는지 확인했습니다.

## 첫 가설: 명령 시간이나 모터 순서가 어긋났다

원본 로그에서 네 모터의 추력 명령은 약 10Hz로 기록됐습니다. 모의는 초당 60회 진행하므로, 비교에 사용한 입력은 이웃한 로그 표본 사이를 직선으로 보간해 Tick마다 만들었습니다. 명령이 어느 시각에서 시작했는지와 네 채널을 어떤 순서로 넣었는지가 맞지 않으면 자세가 바로 달라질 수 있습니다.

원본 `actuator_motors.control[0..3]`과 60Hz 입력을 시간축을 조금씩 옮겨가며 대조했습니다. 시작 시각을 로그 기준 12.05초로 두고 채널 순서를 그대로 유지했을 때 정규화된 RMSE가 약 0.00070으로 가장 작았습니다. 채널을 재배열할 이유는 발견되지 않았습니다. 이는 입력 데이터가 원본 명령과 맞는다는 확인이지, 실제 기체의 각 모터가 시뮬레이터의 어느 위치에 연결됐는지까지 증명하지는 않습니다.

로터 배치와 회전 방향에서 계산한 모터 간 차이도 PX4 몸체 좌표계(FRD)의 X·Y·Z 토크 목표와 대조했습니다. 현재 채널 순서를 썼을 때 세 축의 부호 있는 패턴이 토크 목표와 모두 같은 방향으로 움직였고, 각 축의 선형 상관계수는 +1.00이었습니다.

| PX4 FRD 축 | 현재 로터 순서에서 계산한 명령 차이 | 토크 목표와의 상관 |
| --- | --- | ---: |
| X | `-u0 + u1 + u2 - u3` | +1.00 |
| Y | `u0 - u1 + u2 - u3` | +1.00 |
| Z | `u0 + u1 - u2 - u3` | +1.00 |

여기서 `u0`부터 `u3`은 정규화된 로터 명령입니다. 이 비교는 PX4가 기록한 토크 목표의 축 방향과 현재 로터 순서의 조합이 맞물린다는 뜻입니다. 토크 목표는 실제 토크 측정값이 아니므로, 토크의 절대 크기나 실기체의 회전 응답까지 검증하지는 않습니다.

코드 흐름도 확인했습니다. 시나리오 명령은 해당 Tick의 물리 계산 전에 적용됩니다. 입력값은 모터 추력 비율로 해석해 제곱근을 취한 회전 속도 목표로 바뀝니다. AirSim은 회전 속도의 제곱에 따라 추력을 계산하므로, 이 변환은 `추력 비율 = 회전 속도 비율²` 관계를 맞추기 위한 것입니다. 비교에 넣은 값은 매 Tick에 기록되어 있었으므로, 시나리오 실행 중 명령을 0.1초 동안 붙잡아 두는 문제도 아니었습니다.

## 확인 과정: 입력은 맞았지만 처음 모터 상태는 달랐다

입력 채널과 시간축을 대조한 뒤에는 시작 조건을 살펴봤습니다. PX4 기록의 해당 구간은 이미 공중에 떠 있는 비행에서 시작하며, 모터 명령도 처음부터 대략 0.5~0.7 범위입니다. 반면 강체 모의의 새 기체는 회전 속도 0에서 시작해 기록된 목표까지 모터를 가속합니다.

시작 위치·속도·자세·각속도는 지정할 수 있지만, PX4 기록에는 ESC가 측정한 실제 회전 속도가 없습니다. 모터 명령값에서 회전수를 계산해 넣어도 실제 측정값이 아니라 추정치입니다. 따라서 같은 시작 회전수를 재현할 근거가 없습니다. 기동 초기의 추력 차이가 두 궤적을 벌릴 수는 있지만, 이것만으로 0.5초 뒤의 큰 자세 오차를 전부 설명할 수는 없습니다.

또 다른 차이는 제어 방식입니다. PX4 기록의 모터 명령은 비행 중 위치와 속도 오차를 계속 읽는 PX4 제어기가 만든 출력입니다. 현재 재생은 그 출력을 AirSim에 넣을 뿐, PX4 제어기를 다시 실행하지 않습니다. 시뮬레이터 상태가 기록과 조금 달라져도 다음 모터 명령은 그 차이를 보정하지 않습니다. 그래서 시간이 지날수록 궤적 차이가 커질 수 있습니다.

| 확인 항목 | 관찰 결과 | 이 결과로 말할 수 있는 범위 |
| --- | --- | --- |
| 모터 명령 채널과 시각 | 원본 채널 순서와 12.05초 시작의 60Hz 보간 입력이 가장 잘 맞음 | 이번 입력 생성에서 채널 순서·시간 오차를 원인으로 볼 증거가 없음 |
| 모터 명령과 토크 축 방향 | 현재 로터 순서의 세 축 차이가 PX4 토크 목표와 모두 +1.00 상관 | 명령 축 부호와 순서는 일치하지만 실제 토크 크기는 모름 |
| 시작 로터 속도 | PX4 기록에는 ESC가 측정한 회전수가 없음. 현재 AirSim 로터도 0에서 시작 | 시작 액추에이터 상태를 같게 맞출 수 없음. 차이가 궤적에 준 크기는 따로 확인해야 함 |
| 시작 상태의 회전수 입력 | 이전에는 물리 상태에 반영되지 않았음 | 현재는 강체 모드에서 로터별 초기 속도를 설정할 수 있음. 단, PX4 기록에는 실제 회전수 측정값이 없음 |
| 비행 제어기 | 기록은 PX4 폐루프 출력, 재생은 명령을 그대로 넣는 개루프 실행 | 동일한 입력을 넣어도 같은 비행 궤적이 나와야 하는 비교가 아님 |
| 로터 힘·토크 | 모델 파라미터와 명령 변환식은 확인했지만 실제 회전수·토크 측정은 없음 | 추력·토크 계수의 실기체 오차나 회전 방향 오류를 확정할 수 없음 |

## 수정과 결과: 시작 회전수를 강체 모드에 전달하도록 고쳤다

채널 순서나 추력 계수를 바꾸면 결과를 더 비슷하게 만들 수는 있지만, 현재 자료로는 어느 값을 조정해야 하는지 알 수 없습니다. 그래서 로터 배치, 토크 방향, 추력 계수, 모터 응답값은 수정하지 않았습니다.

코드 경로를 다시 확인하면서 별도의 입력 오류도 찾았습니다. 상태 자료형에는 모터 회전 속도 항목이 있었고 시작 상태 검사도 그 값이 유한한지 확인했지만, 실제 물리 월드에 전달하는 상태에는 위치·자세·선속도·각속도만 포함됐습니다. 이후 상태를 다시 읽는 과정에서 AirSim이 계산한 값으로 덮어써져, 사용자가 넣은 회전수는 아무 안내 없이 사라졌습니다. 즉, 시작 속도를 지정할 수 있다는 인상을 주지만 실제로는 반영하지 않는 입력이었습니다.

현재는 강체 모드의 시작 상태에서 네 로터의 속도를 각각 지정할 수 있습니다. 값은 0 이상이어야 하며 기체 설정의 최대 속도를 넘으면 거부합니다. 초기 속도와 그에 맞는 추력 신호를 모터 응답 모델에 넣고, 첫 물리 Tick 전에는 시작 상태 조회에도 입력값을 그대로 돌려줍니다. 운동학 모드에서는 이 값을 지원하지 않습니다.

다만 AirSim 로터 내부 필터의 시작 출력은 0입니다. 입력한 속도 신호를 필터에 넣어도 첫 Tick에는 이전 출력이 쓰이고, 다음 Tick부터 입력한 회전수에 가까워집니다. 따라서 기록의 첫 표본부터 실제 RPM까지 맞춘 것은 아닙니다. 이 한 Tick 지연을 포함해 기존 4초 구간을 다시 비교하지 않았으므로, 앞서 적은 RMSE는 로터가 0에서 시작했던 이전 조건의 결과입니다.

Release 빌드와 시뮬레이션 시험 6개 묶음이 통과했습니다. 새 시험은 시작 직후 속도 보존, 두 번째 Tick 뒤 AirSim 출력이 초기 속도에 도달하는지, 잘못된 길이의 로터 배열과 최대 속도 초과를 확인합니다. 이 시험은 입력 연결을 검증할 뿐, PX4 로그와의 궤적 비교를 다시 검증하지는 않습니다. 모터 명령은 실제 RPM이 아니며 PX4의 위치·자세도 지상 진실값이 아니므로, 이 결과로 X500의 현실 정확도를 주장할 수 없습니다.

이번 채널·시간 대조는 한 번 실행한 분석입니다. 60Hz 입력을 만든 변환 절차와 그 결과는 저장소에서 자동으로 다시 만들 수 있는 시험으로 아직 정리되지 않았습니다. 따라서 이 수치는 회귀 시험 결과가 아니라 원인 후보를 좁히는 데 사용한 진단 자료입니다.

## 다음 확인

- 원본 비행 로그에서 시작 모터 속도를 직접 알 수 있는 자료가 있는지 확인합니다. 없으면 명령값에서 계산한 속도는 추정값으로 구분합니다.
- PX4 제어기를 포함해 폐루프를 재현할 수 있는지 검토합니다. 어렵다면 기록된 상태 오차가 커지기 전에 끝나는 짧은 개루프 구간만 비교 대상으로 사용합니다.
- 로터별 토크와 자세 응답을 확인할 때는 입력 축·회전 방향·관성·기체 좌표계를 따로 바꾸고, 원본 기록에 실제 토크나 회전수 측정이 없는 한 계수 보정이라고 주장하지 않습니다.
- 같은 로그에서 명령을 추출하고 시간·좌표 변환을 재현하는 절차를 보존하기 전에는 이번 일회성 비교를 자동 검증 기준으로 취급하지 않습니다.
