# PX4 비행 기록 재생에서 초기 RPM 추정이 오차를 키운 문제

## 증상

PX4 X500 V2의 Position 비행 기록을 골라 시뮬레이터에 재생하면 위치와 자세가 기록에서 벗어났습니다. 처음에는 기록을 재생할 때 로터가 0rpm에서 시작해 초반 추력이 부족한 탓이라고 의심했습니다. 하지만 공개 기록에는 ESC가 측정한 로터 회전수가 없습니다. 모터 명령만으로 시작 회전수를 계산해도 되는지부터 확인해야 했습니다.

예전에 적어 둔 위치 RMSE 0.698m와 자세 RMSE 76.3도는 실행 시나리오와 변환 자료가 저장되지 않아 지금 상태에서 다시 만들 수 없습니다. 새 시험은 입력 자료와 오차 계산을 함께 저장해 반복할 수 있게 구성했습니다. 과거 수치는 현재 기준선에서 제외합니다.

## 첫 가설: 모터가 0rpm에서 출발해 초반 운동이 틀어졌다

비행 기록은 공중에서 시작하고 첫 모터 추력 명령도 이미 0보다 큽니다. 반면 강체 시뮬레이션은 기본적으로 로터 속도 0에서 시작합니다. 이 차이가 초기 추력을 줄여 궤적을 벌릴 가능성은 있었습니다.

이 가설을 확인하려면 실제 시작 RPM이 필요하지만, 이 로그에는 RPM 측정값이 없습니다. 따라서 명령에서 계산한 속도를 실제 상태로 단정할 수는 없습니다. 우선 속도 0으로 시작하는 조건과 명령에서 추정한 속도로 시작하는 조건을 같은 입력으로 비교했습니다.

## 확인 과정: 시간·좌표를 맞춘 뒤 초기 속도만 바꿨다

PX4 ULog의 시작 시각은 부팅 후 1,307.424085초입니다. 비교 구간은 그 시각에서 12.05초 뒤인 1,319.474085초부터 4초간입니다. 초당 60회 계산하도록 맞췄고, 위치·속도·자세·각속도는 각 기록 시각 사이를 보간했습니다. 모터 입력도 각 Tick 시각에 맞춰 보간했습니다.

위치와 속도는 PX4의 북·동·아래(NED)에서 프로젝트의 동·북·위(ENU)로, 각속도는 앞·오른쪽·아래(FRD)에서 앞·왼쪽·위(FLU)로 바꿨습니다. 자세 쿼터니언에도 같은 좌표축 변환을 적용했습니다. 위치는 첫 표본을 원점으로 옮겨 이동량을 비교했습니다. 위치·속도·자세 값은 지상 진실값이 아니라 PX4 추정값입니다.

PX4의 `actuator_motors.control`은 로터별 정규화 추력 명령입니다. 실제 RPM이 아닙니다. [PX4 메시지 정의](https://github.com/PX4/PX4-Autopilot/blob/main/msg/versioned/ActuatorMotors.msg)에도 값의 의미가 정규화된 추력으로 적혀 있습니다. 추력은 회전 속도 제곱에 비례한다고 가정해, 두 번째 비교에서는 첫 명령 `u`를 `√u × 설정 최대 회전수`로 바꿨습니다. 이 변환은 비교용 추정이며 실측 RPM을 복구한 것이 아닙니다.

두 번의 재생은 시작 로터 속도만 다르고, 상태 기록·모터 명령·기체 파라미터와 계산 간격은 같습니다. 위치·속도는 벡터 오차 크기, 자세는 두 쿼터니언 사이의 최단 회전각, 각속도는 벡터 오차 크기를 구해 241개 시각의 RMSE로 요약했습니다.

| 오차 RMSE | 로터 속도 0에서 시작 | 첫 명령으로 속도를 추정해 시작 |
| --- | ---: | ---: |
| 위치 이동량 | 0.411m | 0.468m |
| 속도 | 0.267m/s | 0.366m/s |
| 자세 | 27.70도 | 52.34도 |
| 각속도 | 0.557rad/s | 0.876rad/s |

이 구간에서는 초기 속도를 추정해 넣은 쪽의 네 오차가 모두 더 컸습니다. 0rpm 시작이 실제로 더 정확하다는 뜻은 아닙니다. 두 조건 모두 실제 시작 RPM과 비교하지 못했습니다. 또한 시뮬레이션에는 지형을 넣지 않았고 PX4 제어기를 닫힌 고리로 다시 실행하지 않았습니다. 기록된 제어기 출력을 새 물리 상태에 그대로 넣은 개루프 비교입니다.

## 수정: 초기 속도를 시나리오에서 지정하고 같은 비교를 시험에 저장했다

강체 시나리오에서 로터별 `initial_motor_speeds_radians_per_second` 값을 지정할 수 있도록 했습니다. 값은 0 이상이며 기체 설정의 최대 회전수를 넘을 수 없습니다. 실행 전에 자료가 잘못됐는지 확인할 수 있도록 4개 값이 아닌 배열과 범위를 벗어난 값은 거부합니다. 운동학 모드에서는 초기 RPM을 받지 않습니다.

시간·좌표 변환을 마친 참조 상태와 재생 입력을 GPS 정보 없이 한 시험 자료로 저장했습니다. 자동 시험은 이 자료로 두 초기 조건을 모두 실행하고 위치·속도·자세·각속도 RMSE를 확인합니다. 시험 자료는 공개 PX4 로그를 바탕으로 만든 것이며, 원본 ULog와 GPS 좌표는 저장소에 넣지 않았습니다.

AirSim 로터 내부 신호 필터는 시작값이 0입니다. 초기 속도를 지정해도 첫 Tick 출력은 필터의 이전 값이고 다음 Tick부터 새 입력을 따라갑니다. 따라서 현재 기능은 시뮬레이터의 모터 응답 상태에 초기 목표를 전달하지만, AirSim 내부 로터 필터의 순간 상태까지 완전히 초기화하지는 않습니다.

## 결과와 남은 확인

Release 빌드와 시뮬레이션 시험 6개 묶음이 통과했습니다. 두 초기 조건의 재생 결과는 시험에서 같은 자료로 반복 계산됩니다. 이 시험은 변환된 참조 자료와 모의 궤적의 차이를 재현하는 기준이지, X500 모델의 현실 정확도를 증명하는 시험은 아닙니다.

이번 비교에서 모터 명령으로 만든 초기 RPM 추정은 오차를 낮추지 못했습니다. 실제 회전수나 모터별 추력 측정이 없는 상태에서 이를 보정값으로 채택하지 않습니다. 다음 단계에서는 명령값과 실제 추력·RPM의 관계, AirSim 내부 필터의 초기 상태 처리, PX4 제어기를 포함한 폐루프 재현 가능성을 따로 확인해야 합니다. 현재 자동 시험에는 ULog 원본을 읽어 참조 자료를 다시 만드는 가져오기 기능도 없습니다.
