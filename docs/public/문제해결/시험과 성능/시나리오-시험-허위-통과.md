# 시나리오가 실패했는데 CTest는 통과한 문제

## 증상

CTest에서는 여러 헤드리스 비행 시험이 통과로 보였지만, 같은 시나리오를 직접 실행하면 프로그램이 실패 종료 코드를 반환했습니다. 결과 JSON에도 `"outcome": "failed"`와 적용하지 못한 명령이 남았습니다.

예를 들어 두 대 독립 비행 시험은 180 Tick(3초) 뒤에도 두 기체가 `taking_off` 상태였고, 90 Tick에 보낸 경유점 명령을 적용하지 못했습니다. 두 지점 임무도 시작 기한까지 이륙하지 못했습니다. 통신 장애 시험은 최종 호버링을 기대했지만 두 기체 모두 아직 상승 중이었습니다.

## 원인 확인

시험 실행은 정상 종료 코드뿐 아니라 출력 문자열도 통과 조건으로 검사하고 있었습니다. CTest의 `PASS_REGULAR_EXPRESSION`은 지정한 문구가 출력되면 시험을 통과 처리합니다. 실패 JSON에도 기체 이름, 임무 항목, `stale` 상태가 출력되므로, 기대한 성공 결과와 관계없는 문구가 일치해 실패 종료가 가려졌습니다.

물리 시험 시간도 이전 운동학 모델에 맞춰져 있었습니다. 강체 모델은 이륙 직후 바로 호버링 상태가 되지 않습니다. 90 Tick(1.5초)에 경유점 명령을 보내거나, 180 Tick(3초) 만에 임무가 끝나기를 기대한 조건이 실제 모터와 기체 응답보다 빨랐습니다.

## 수정

네 헤드리스 시나리오 시험에서 출력 문자열을 통과 기준으로 쓰지 않게 했습니다. 시나리오 실행기가 예상 결과를 검사해 반환하는 종료 코드를 CTest가 그대로 확인합니다. 그래서 JSON에 일부 단어가 들어 있어도 실패 결과가 통과로 바뀌지 않습니다.

기체가 이륙해 명령을 받을 수 있을 때까지 기다리도록 단일·다중 기체 시험을 조정했습니다. 경유점 사이 시간과 착륙 대기 시간도 늘렸고, 지면에 닿은 기체의 기준 위치를 기체 원점 높이와 맞췄습니다. 정상 네 대 임무는 장애 조건을 섞지 않고 별도 시나리오로 두어 네 구역 완료를 직접 확인하게 했습니다.

## 재검증 결과

2026년 10월 30일 Windows Release 빌드에서 전체 CTest 26개가 통과했습니다.

| 확인 항목 | 결과 |
| --- | --- |
| 단일 기체 이륙·경유점 이동·착륙 | 1,500 Tick(25초) 실행 후 착륙, 통과 |
| 두 대 독립 비행 | 1,000 Tick 실행, 두 대 모두 호버링, 통과 |
| 두 지점 임무 | 두 작업 모두 완료, 완료 Tick 1,115, 통과 |
| 네 대 정찰 임무 | 네 구역 모두 완료, 완료 Tick 684, 통과 |
| 통신 차단·복구 | 80 Tick에 차단, 139 Tick에 오래된 상태 표시, 300 Tick에 새 상태 수신, 통과 |
| 전체 CTest | 26/26 통과 |

이전에는 실패했으나 지금은 같은 시험에서 통과하는 것을 확인했습니다. 자동 시험은 모의 안의 명령·상태·임무 결과를 검증합니다. 실제 X500 기체의 비행 정확도를 확인한 것은 아닙니다.

## 다시 생기지 않게

헤드리스 실행은 프로그램의 종료 코드와 시나리오 결과를 통과 기준으로 둡니다. JSON 출력의 단어가 있는지만 검사해 시험 성공을 판정하지 않습니다. 새 시험을 추가할 때는 명령이 적용되는 시점과 기체가 목표 상태에 도달할 시간을 현재 물리 모델로 확인합니다.
