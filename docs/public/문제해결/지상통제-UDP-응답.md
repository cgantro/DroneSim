# 지상통제 창의 UDP 응답 시간 초과

## 증상

명령줄 프로그램은 응답을 받았지만 지상통제 창에서는 같은 주소와 포트를 사용해도 응답 시간이 끝나는 문제가 있었습니다.

## 추적 과정과 수정

명령줄 프로그램은 응답을 받는데 창에서는 시간 초과가 났으므로, 주소와 포트보다 요청을 보내고 응답을 받는 창의 비동기 경로를 먼저 살폈습니다. 이 경로는 요청마다 UDP 소켓을 만들고 닫고 있었습니다. 창의 통신 상태가 소켓을 재사용하고, 한 요청이 끝나기 전에는 다른 요청이 같은 소켓을 쓰지 않게 바꿨습니다.

수정 이력은 UI가 요청별 소켓을 만들던 구조를 창의 통신 상태가 소유한 소켓을 재사용하도록 바꿨음을 보여 줍니다. Windows가 왜 이전 구조에서 GUI 응답을 놓쳤는지 운영체제 내부 원인까지는 확인하지 않았으므로 그 이상은 단정하지 않습니다.

## 확인 결과와 한계

지상통제 창의 명령·응답과 기록 재생을 포함하는 UDP 확인 절차가 추가됐습니다. 이 안내만으로 현재 사용자의 PC에서 같은 문제가 완전히 재현되지 않는다고 보장할 수는 없습니다. 다시 발생하면 실행한 명령, 창에 표시된 상태, 시뮬레이터 로그와 재현 순서를 함께 남겨야 합니다.
