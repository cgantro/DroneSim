# 경사 지형에서 비행 높이와 충돌 위치가 맞지 않던 문제

## 증상: 화면에는 땅이 있는데 기체가 박히거나 건물 옆을 지나갔다

평지에서는 드러나지 않던 차이가 경사면과 건물이 있는 장소에서 나타났습니다. 드론을 경사 위에 두었는데 지면에 파고들 수 있고, 이륙·착륙 판단이 실제 지면 높이와 맞지 않을 수 있었습니다. 건물은 화면에서 보이는 위치와 크기대로 충돌하지 않을 수 있었습니다.

처음에는 이륙과 착륙 목표가 월드 높이 0을 기준으로 계산되는지 의심했습니다. 코드를 따라가며 문제를 둘로 나눴습니다. 하나는 지형 높이를 비행 기준으로 전달하지 않는 문제였고, 다른 하나는 지도에서 읽은 건물의 동·북·높이 축을 화면용 좌표와 충돌용 좌표에 혼합한 문제였습니다.

## 원인 1: 경사 지점의 지면 높이가 비행 목표에 전달되지 않았다

기체가 지형 위에서 시작하려면 시작 위치 아래의 지면 높이를 초기 상태와 함께 보관해야 합니다. 그 값을 기준으로 이륙 높이를 정하고, 착륙 완료 시에는 기체의 충돌 형상과 원점을 고려해 지면에 놓였는지 판단해야 합니다.

지면 높이를 0으로 가정하면 경사면 위에서도 제어기는 바닥이 원점에 있다고 판단합니다. 화면에서는 지형이 솟아 있어도 제어 목표와 착륙 판정은 평지 기준으로 계산될 수 있습니다.

높이 격자는 절대 고도를 매 위치마다 반복 저장하는 대신 기준 고도와 기준에서의 높이 차이를 보관합니다. 현지 동·북 좌표를 격자 행·열로 바꾼 뒤 인접 샘플 사이를 보간해 지면 높이를 구합니다. 이 결과가 초기 기체 원점과 이륙·착륙 계산에 들어가야 화면 지형과 물리 바닥이 같은 기준을 공유합니다. 격자 바깥에 있는 위치를 어떻게 다룰지도 별도 정책이 필요하므로, 시험은 먼저 범위 안의 지점과 경계 조건을 나눠야 합니다.

강체 모드에서는 드론별 시작 지점의 지면 높이를 저장하도록 했습니다. 이륙 목표는 지면 높이에 기본 이륙 높이를 더하고, 착륙 완료는 지면 높이와 기체가 바닥에 놓일 때의 모델 원점 높이를 함께 고려합니다. 지형 격자가 설정되지 않은 물리 월드에는 기존처럼 z=0 평면을 바닥으로 사용합니다.

## 원인 2: 건물 화면 크기와 충돌 크기에 서로 다른 축 기준이 섞였다

지도 건물 자료는 동쪽·북쪽 위치와 높이를 사용합니다. 시뮬레이션에서는 위쪽이 Z축이지만 화면 좌표에서는 위쪽을 Y축으로 표시합니다. 이때 화면용 크기 배열을 충돌 계산에 그대로 넘기면 북쪽 폭과 높이가 서로 바뀔 수 있습니다.

화면에서 산과 지형을 보기 좋게 세로 방향으로 두 배 키워 그리는 표현도 있었습니다. 이 확대값이 충돌 상자 크기에도 들어가면 실제 높이보다 높은 건물로 충돌을 계산하게 됩니다. 화면에서 보이는 크기와 충돌 계산에 쓰는 물리 크기는 같은 배열을 공유해서는 안 됩니다.

건물 외곽선과 지형 높이에서 동·북·위 기준의 충돌 상자를 만들고, 화면 표시 크기는 별도로 계산하도록 고쳤습니다. 충돌에는 원래 높이를 사용하고, 시각적 세로 확대는 화면 그리기에만 적용합니다. 높이 자료가 없는 건물은 실제 높이를 안다고 가정하지 않고 시연용 3m를 적용합니다.

축 혼동은 배열의 세 숫자가 모두 그럴듯한 양수여도 발생할 수 있어 단순 유효성 검사로 찾기 어렵습니다. 그래서 동쪽 폭, 북쪽 폭, 높이가 서로 다른 비대칭 예제를 사용했습니다. 정육면체처럼 폭과 높이가 같은 예제만 쓰면 축을 잘못 바꿔도 화면과 충돌 상자가 비슷해 보여 오류를 놓칠 수 있습니다.

## 확인 과정과 당시 결과

경사 접촉을 확인하던 과거 시험은 3×3 높이 격자에서 동쪽 방향으로 높이가 -1m, 0m, 1m가 되는 경사면을 만들었습니다. 기체 충돌 상자의 여러 꼭짓점을 지형에 대조하고, 시작 중심 높이 0.3m에서 60 Tick 뒤에도 바닥 아래로 빠지지 않는지 확인했습니다.

건물 좌표는 동쪽 폭, 북쪽 폭, 높이가 서로 다른 예제로 검사해 축이 뒤바뀌지 않는지 확인했습니다. 실제 지도에서 불러온 건물 하나를 고르고, 드론이 측면으로 접근했을 때 강체 모드의 수평 속도가 줄어드는 시험도 추가했습니다.

## 현재 자동 시험이 보장하는 범위

시험을 핵심 시나리오로 줄이면서 과거의 경사면 꼭짓점 접촉 시험은 제거됐습니다. 현재 자동 확인은 높이 격자 조회, 건물 충돌 상자의 축과 높이 계산, 평지에서의 접촉 정지, 지도 건물 옆면 접촉을 포함합니다. 다양한 경사 방향에서 장시간 착륙하고 이동하는 동작은 현재 자동 회귀 시험으로 확인하지 않습니다.

이 검증은 지형 자료가 등록된 네이티브 강체 모드에 한정됩니다. 운동학 모드는 지형 충돌 월드를 사용하지 않습니다. 웹 빌드도 운동학 모드를 사용하므로, 지형을 화면에 표시하는 것과 강체 충돌을 계산하는 것은 별개의 기능입니다.

### 운동학 모드가 지면 고도를 무시하던 문제

운동학 모드는 지형과 드론 사이의 충돌을 계산하지 않지만, 시작할 때 전달한 지면 높이는 상태에 저장합니다. 따라서 화면 없는 운동학 실행이나 웹 빌드에서도 이륙 목표와 착륙 위치는 그 지면 높이를 기준으로 삼아야 합니다. 지형 충돌을 지원하지 않는다는 사실이 고도를 항상 0으로 취급해도 된다는 뜻은 아닙니다.

문제를 추적했을 때 초기화 경로는 `groundElevationMeters`를 상태에 저장했지만, 운동학 비행 계산은 그 값을 읽지 않았습니다. 이륙 목표를 월드의 `z = 1.5m`, 착륙 위치와 지면 아래 정지 기준을 `z = 0m`로 고정하고 있었습니다. 지면 고도 42m에서 시작한 드론은 이륙 목표 43.5m 대신 1.5m로 옮겨질 수 있고, 착륙도 42m가 아니라 0m를 향했습니다.

이 문제는 강체 모드의 지형 접촉 계산과는 다른 경로였습니다. AirSim 강체 모드는 지면 높이와 기체 원점의 기준을 별도로 사용합니다. 따라서 강체 모드에서 경사 지면을 시험한 결과만으로 운동학 모드의 이륙·착륙을 확인할 수 없습니다.

42m 고도에서 시작해 이륙 후 43.5m에 도달하고, 다시 착륙해 42m로 돌아오는 회귀 시험을 추가했습니다. 수정 전 시험은 이륙 뒤 1.5m, 착륙 뒤 0m를 반환해 두 확인 모두 실패했습니다. 이는 코드에서 확인한 기준 높이 오류가 실제 결과에도 나타났다는 증거입니다.

운동학 모델은 저장된 지면 고도를 더해 이륙 목표를 계산하고, 착륙과 공중 상태의 지면 정지도 같은 높이를 사용하도록 수정했습니다. 같은 회귀 시험은 수정 뒤 통과했습니다. Windows Release 전체 빌드와 20개 CTest도 통과했습니다. 이 결과는 고도가 있는 시작 지점에서 운동학 모델의 이륙·착륙을 확인한 것이며, 지형 충돌이나 WebAssembly 빌드는 검증하지 않았습니다.

또한 접촉 시험 통과는 지도 전체에서 충돌 모양이 정확하다는 뜻이 아닙니다. 현재 자료는 지형을 일정 간격의 높이 격자로 표현하고, 건물은 외곽을 둘러싼 상자로 근사합니다. 실제 건물 벽의 오목한 부분, 지붕 형태, 작은 지형 굴곡은 이 모델에 들어 있지 않습니다. 화면의 삼각형 표면과 물리 충돌의 높이 보간 사이에도 샘플 간 근사 오차가 남습니다.

## 남은 한계와 재발 방지

- 현재 높이 격자는 대략 30m 간격입니다. 작은 굴곡이나 좁은 구조물을 표현하기 어렵습니다.
- 경사면 접촉은 충돌 상자 꼭짓점과 높이 격자로 근사합니다. 실제 지형 삼각형 메시와의 정밀 충돌은 아닙니다.
- 건물 충돌은 다각형 외곽을 감싼 직사각형으로 계산합니다. 높이가 누락된 건물의 3m는 실제 데이터가 아니라 시연용 값입니다.
- 좌표계를 바꾸거나 화면 지형 크기를 조정할 때는 동·북·위 축과 화면 전용 확대값이 물리 계산에 섞이지 않는지 각각 확인합니다.
- 화면에서 바닥에 닿아 보이는 결과만으로 물리 접촉이 검증됐다고 판단하지 않습니다.
