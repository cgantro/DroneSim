# 경사 지형에서 비행 높이와 충돌 위치가 맞지 않던 문제

## 증상과 처음 세운 가설

평평한 바닥에서는 드러나지 않지만, 시작 위치가 경사면이거나 건물이 있는 곳이면 드론이 지면에 박히거나 이륙·착륙 상태가 실제 높이와 맞지 않을 수 있었습니다. 처음에는 이륙과 착륙 목표가 월드 높이 0을 기준으로 계산되는지 의심했습니다.

코드를 따라가면서 화면에 보이는 지형과 물리 계산의 높이 기준이 다르다는 사실도 확인했습니다. 또 화면용 건물 크기를 물리 충돌 상자에 그대로 전달해 동·북·위 축이 섞이는 문제가 있었습니다. 이 문제들은 서로 관련은 있지만 원인은 각각 지면 기준, 화면 표현과 물리 축의 차이였습니다.

## 지면 기준이 어긋난 원인

경사 지형 위에서 드론을 시작하려면 현재 위치의 지면 높이를 초기 자세와 함께 보관해야 합니다. 이륙·착륙 목표도 그 높이에 더해 계산해야 합니다. 기준 높이가 0으로 남으면 경사 위에서 시작해도 비행 제어기는 지면이 원점에 있다고 판단할 수 있습니다.

수정 뒤 강체 모드는 드론마다 시작 지점의 지면 높이를 저장합니다. 이륙 목표는 지면 높이에 기본 이륙 높이를 더하고, 착륙 완료 판정은 지면 높이와 기체가 바닥에 놓일 때의 모델 원점 높이를 함께 사용합니다. 지형 격자가 설정되지 않은 물리 월드는 계속 z=0 평면을 바닥으로 사용합니다.

화면에서 산 높낮이를 읽기 쉽도록 세로 크기를 두 배로 그리는 표현도 있습니다. 비행 높이와 물리 접촉은 원래 지형 높이를 사용합니다. 따라서 화면에서 산이 높아 보인다는 이유만으로 물리 계산의 높이가 두 배가 된 것은 아닙니다.

## 건물 상자 축이 바뀐 원인과 수정

지도에서 건물은 동쪽·북쪽 위치와 높이를 사용합니다. 화면에서는 세로가 Y축이지만 시뮬레이션의 위쪽은 Z축입니다. 화면용 크기 배열은 동쪽·위쪽·북쪽 순서였는데 이를 충돌 계산에도 넘기면서 북쪽 폭과 높이가 맞바뀌었습니다. 화면의 높이 확대값까지 물리 크기에 들어가 실제 건물 높이와 충돌 높이도 달라졌습니다.

건물 외곽선과 지형 높이로 동·북·위 기준의 충돌 상자를 만들고, 같은 기준에서 화면 크기를 따로 계산하도록 고쳤습니다. 충돌은 원래 높이로 검사하고, 화면에서만 세로를 보기 좋게 늘립니다. 높이 자료가 없는 건물은 자료가 있다고 가정하지 않고 시연용 3m를 적용합니다.

## 확인한 결과

초기에는 3×3 높이 격자에 동쪽 방향으로 높이가 `-1m, 0m, 1m`씩 변하는 경사면을 만들고, 드론 충돌 상자의 여러 꼭짓점으로 접촉을 확인하는 시험이 있었습니다. 당시에는 시작 중심 높이 0.3m에서 60 Tick 뒤에도 기체가 바닥 아래로 빠지지 않는지 확인했습니다.

건물 축은 서로 다른 동쪽·북쪽 폭과 높이를 가진 예제로 상자의 중심·반 크기를 확인했습니다. 실제 지도에 있는 건물 하나를 불러와 드론이 옆면에 접근했을 때 수평 속도가 줄어드는 강체 시험도 추가했습니다.

## 현재 시험이 보장하는 범위

시험 시나리오를 줄인 뒤에는 경사면 접촉을 직접 검사하던 물리 시험이 제거됐습니다. 현재 자동 시험은 높이 격자 조회, 건물 상자의 축·높이 계산, 평지 접촉 정지와 지도 건물 옆면 접촉을 확인합니다. 경사면에서 장시간 착륙하거나 다양한 경사 방향을 지나는 동작은 현재 자동 회귀 시험으로 확인하지 않습니다.

운동학 모드는 지형 충돌 월드를 사용하지 않습니다. 웹 빌드도 운동학 방식을 쓰므로 화면에 지형을 그려도 강체 지형 접촉을 계산하지 않습니다. 따라서 여기의 지형 충돌 확인은 지형이 등록된 네이티브 강체 모드에 한정됩니다.

## 남은 한계

- 지형 높이 자료는 약 30m 간격이라 작은 굴곡과 좁은 구조물을 충분히 표현하지 못합니다.
- 경사면 접촉은 충돌 상자의 꼭짓점과 높이 격자로 근사합니다. 삼각형 지형 메시와의 정밀 충돌은 아닙니다.
- 건물은 다각형 외곽선을 감싼 직사각형으로 충돌을 계산합니다. 높이가 없는 건물의 3m 값도 실제 자료가 아니라 시연용 가정입니다.
- 지면 높이와 화면 표현을 바꾸는 경우, 시각적 세로 확대와 물리 좌표·크기를 별도로 확인해야 합니다.
