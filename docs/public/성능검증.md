# 성능 시험과 현재 기준선

이 문서는 같은 조건에서 비행 동작과 계산 시간을 반복해, 이후 바뀐 물리 엔진과 비교할 기준을 남깁니다. 지금 수치는 개선 결과가 아니라 AirSim을 쓰는 현재 실행의 기준값입니다.

## 무엇을 재는가

| 확인할 내용 | 기록할 값 |
| --- | --- |
| 비행 동작 | 이륙·경유점 이동·착륙, 임무 완료 여부와 모의 시간 |
| 충돌 안전 | 최소 기체 간격, 충돌·안전 중단 횟수 |
| 계산량 | 시뮬레이션 Tick과 물리 단계의 p50·p95·p99 시간, 주기 기준 초과 수 |
| 화면 처리 | 화면 그리기와 앱 프레임 시간, 측정 FPS |
| 메모리 | 작업 집합과 프로세스 전용 메모리 |

p50은 표본의 가운데 값입니다. p95는 표본 100개 중 약 95개가 그 시간 안에 끝났다는 뜻이고, p99는 약 99개가 그 안에 끝났다는 뜻입니다. 최대값 하나만 보면 드문 튐과 평소 성능을 구분하기 어려워 이 값들을 함께 봅니다.

## 현재 기준선

2026년 10월 30일, Windows Release 빌드에서 확인했습니다. 앱 성능 측정은 프로그램 창을 숨기고 1280×720 화면 크기로 실행했습니다.

| 항목 | 조건 |
| --- | --- |
| 실행 빌드 | Release, MSVC 14.50, Ninja |
| 그래픽 장치 | NVIDIA GeForce RTX 3060 Ti, OpenGL 3.3.0, 드라이버 581.42 |
| 측정 방법 | 준비 1초 뒤 5초 측정, 조건별 새 프로세스로 3회 반복 |
| 단일 기체 | 자동 이륙 명령을 넣고 1대의 물리 Tick을 측정 |
| 네 대 임무 | 자동 시연을 켜고 4대 임무를 시작한 뒤 물리 Tick을 측정 |
| 측정 코드 리비전 | `ce769a85` |

단일 기체와 네 대 실행은 같은 5초 측정기를 사용합니다. 단일 기체 실행은 측정 전 자동 이륙을 시작하고, 네 대 실행은 자동 편대 임무를 시작합니다. 5초 측정은 전체 임무 완료 시간을 재는 구간이 아닙니다. 임무가 끝나는 시간은 아래 시나리오 시험에서 따로 확인했습니다.

측정에는 `--benchmark`를 사용하고, 네 대 자동 임무에는 `--demo`를 함께 지정합니다. 결과에는 기체 수와 시연 모드 여부도 기록됩니다.

### 앱 성능 측정값

아래의 대표값은 세 실행 결과의 중앙값입니다. 괄호 안은 세 실행에서 가장 낮은 값과 높은 값입니다. 시간 단위는 마이크로초(µs)입니다.

| 실행 조건 | Tick p50 | Tick p95 | Tick p99 | 물리 단계 p95 | 화면 FPS | 화면 프레임 p95 | 작업 집합 / 전용 메모리 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 단일 기체 | 25.7 | 34.5 (34.1–35.3) | 37.0 (36.3–37.9) | 14.0 (14.0–14.3) | 414.4 (413.7–415.0) | 2,500 | 121.8 / 288.0 MB |
| 네 대 임무 | 57.1 | 99.5 (95.8–102.7) | 114.0 (107.7–122.6) | 30.6 (30.0–31.6) | 409.3 (408.8–412.4) | 2,608 | 122.4 / 418.6 MB |

세 실행 모두 측정 Tick은 300회였습니다. Tick 계산 시간이 16.67ms를 넘은 횟수는 두 조건 모두 0회입니다. 이 항목은 각 Tick의 계산 시간만 봅니다. 실제 화면 갱신 간격이나 60Hz 제어가 보장됐다는 뜻은 아닙니다.

측정 창을 숨긴 상태라 FPS는 모니터에서 체감하는 화면 속도가 아닙니다. GPU 처리 시간은 따로 측정하지 않았습니다. 화면 프레임 시간에는 CPU의 화면 처리와 버퍼 교체가 포함되므로 GPU 렌더 시간으로 읽으면 안 됩니다.

### 비행과 임무 확인

| 시험 | 입력과 실행 길이 | 결과 |
| --- | --- | --- |
| 단일 기체 정찰 비행 | 이륙, 경유점 세 곳, 착륙, 총 1,500 Tick(25초) | 통과, 최종 상태 착륙 |
| 네 대 구역 임무 | 네 대가 각자 한 구역을 맡고 총 1,100 Tick(18.33초) 실행 | 4/4 구역 완료, 완료 Tick 684, 임무 시작 뒤 5.4초, 최소 기체 간격 약 10.0m |
| 통신 차단·복구 | 두 대, 600 Tick 실행. 80 Tick부터 차단하고 300 Tick에 복구 | 139 Tick에 상대 상태가 오래된 정보로 바뀌고 300 Tick에 새 상태를 받음. 최종 비행 상태는 두 대 모두 호버링 |

네 대 통신 장애 시나리오에서는 끊긴 기체의 구역이 완료되지 않아 결과가 `inconclusive`였습니다. 이는 정상 네 대 임무 완료 시험과 다른 조건이며, 통신 단절 중 임무가 자동으로 끝난 것으로 처리하지 않습니다.

성능 표의 실행 코드는 `ce769a85`입니다. 이후 `bf576ddb`에서 시험 입력을 전체 단일 비행으로 바꿨고, 앱 성능 측정 코드는 바뀌지 않았습니다. 이 리비전의 Release 전체 빌드와 CTest 26개가 통과했습니다. 이전에는 출력 문구만 맞으면 실패 종료 코드가 있어도 일부 시나리오 시험이 통과로 표시됐습니다. 현재 시험은 프로그램의 정상 종료 결과를 확인하며, 자세한 재현 과정은 [시나리오 시험이 실패를 통과로 표시한 문제](문제해결/시험과%20성능/시나리오-시험-허위-통과.md)에 기록했습니다.

## 다음 버전과 비교하는 방법

물리 엔진을 바꾼 뒤에는 같은 기체 수, 맵, 임무, 시작 상태, 측정 길이와 컴퓨터에서 다시 세 번 측정합니다. 앱 성능 시험은 화면을 숨긴 1대와 4대 조건을 각각 돌리고, 임무 시험은 완료 시간과 최소 기체 간격을 확인합니다. 빌드 종류나 장면이 다르면 같은 표에 개선율로 합치지 않습니다.

현재 기준선의 물리 단계 p95는 단일 기체 14.0µs, 네 대 30.6µs입니다. 이는 다음 물리 구현과 비교할 출발값이며, 실제 X500 기체와 같은 비행 품질을 증명하는 값은 아닙니다.
