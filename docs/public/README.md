# 문서 길잡이

읽는 목적에 맞는 문서부터 고르면 됩니다. 구현 상태를 확인할 때는 목표 문서보다 **기능 현황**을 먼저 보세요.

## 처음 실행할 때

1. [실행 안내](시작하기.md)에서 실행 방법과 조작을 확인합니다.
2. [현재 기능과 시험 결과](../../SPEC.md)에서 되는 기능과 아직 확인하지 않은 항목을 살펴봅니다.

## 궁금한 내용에 따라 읽기

| 알고 싶은 내용 | 문서 |
| --- | --- |
| 프로젝트가 무엇을 만들려는가 | [개발 목표](../../GOAL.md) |
| 지금 어떤 기능이 동작하고 무엇을 확인했는가 | [현재 기능과 시험 결과](../../SPEC.md) |
| 임무·통신·비행 계산이 어떻게 이어지는가 | [기술 구조](기술구조.md) |
| 성능 시험은 무엇을 확인했고 결과를 어떻게 읽는가 | [성능 검증](성능검증.md) |
| 과거에 발생한 주요 문제는 어떻게 확인하고 고쳤는가 | [문제 해결 기록](문제해결.md) |
| 성능 시험의 원본 자료는 어디에 있는가 | [측정 자료 찾아보기](../../benchmarks/results/README.md) |

## 문서 역할

- 저장소 첫 화면은 프로젝트를 짧게 소개하고 필요한 문서로 안내합니다.
- 개발 목표는 만들 결과와 범위를 설명합니다.
- 기능 현황은 현재 코드와 실제 확인 결과를 기록합니다.
- 실행 안내와 기술 구조는 각각 사용 방법과 내부 데이터 흐름을 설명합니다.
- 문제 해결 기록과 성능 검증은 과거 코드·환경·시험 조건에 따른 기록입니다. 현재 상태를 판단할 때는 기능 현황을 기준으로 삼습니다.

목표에 적힌 기능이 이미 구현됐다는 뜻은 아닙니다. 실행하지 않은 시험은 통과로 적지 않습니다.
