# 기술 선택과 구현 방향

이 문서는 현재 상태와 다음 구현 순서를 정리합니다. 아래 선택은 조사 결과를 바탕으로 한 추천입니다. 아직 코드에 넣지 않은 기능은 구현된 것처럼 설명하지 않습니다.

## 지금 프로그램이 하는 일

- 드론 위치와 속도, 수평면에서 도는 방향각(Yaw)을 1/60초 간격으로 갱신합니다. 중력, 기울기, 모터, 추력, 공기 저항은 계산하지 않습니다.
- 그래픽 앱이 화면 표시와 함께 게임패드, UDP 명령, 기록·재생, 시나리오 시연, 성능 측정을 맡고 있습니다.
- 화면이 없는 시나리오 실행 경로와 OpenGL을 쓰는 화면 실행 경로가 따로 있습니다.
- Flecs와 강체 물리엔진은 아직 연결되어 있지 않습니다.

다음 작업은 현재 화면과 명령 흐름을 한 번에 다시 만드는 일이 아닙니다. 모의 상태를 관리하는 작은 중심부를 만들고 기존 기능을 한 단계씩 연결합니다.

## 우선 선택

### Flecs는 객체 관리에만 사용

Flecs는 화면 객체와 시뮬레이션 객체를 식별하고 필요한 상태를 묶는 데 사용합니다. 첫 단계에서는 드론과 카메라만 Entity로 만듭니다. 입력 처리, UDP 소켓, OpenGL 자원은 기존 C++ 객체로 둡니다.

Entity는 장면 속 대상의 번호입니다. Component는 그 대상에 붙이는 위치·속도 같은 데이터이고, System은 그 데이터를 읽거나 갱신하는 계산입니다.

처음 필요한 데이터는 드론의 식별 정보, 비행 명령, 모터 상태, 물리 Body 참조와 화면에 보여 줄 자세입니다. Flecs 고급 파이프라인이나 병렬 실행은 넣지 않습니다. 한 고정 Tick 안에서 실행 순서를 코드로 읽을 수 있게 유지하고, 실제 객체 수나 처리량이 늘어날 때 다시 판단합니다.

### 물리엔진은 Jolt로 시작

현재 프로그램은 자체 OpenGL 창과 화면 없는 실행 경로를 이미 갖고 있습니다. Jolt를 선택하면 그 구조 안에 강체와 충돌 계산을 추가할 수 있습니다. Gazebo는 쿼드콥터 모터 예제가 있다는 장점이 있지만 별도의 시뮬레이터 환경까지 함께 관리해야 하므로 우선순위에서 제외합니다.

Jolt가 드론을 대신 날려 주지는 않습니다. 작은 C++ 비행 모델에서 모터 회전속도에 따른 추력·토크를 계산하고, 그 힘을 Jolt의 강체(물리 계산 대상)에 적용합니다. Jolt가 계산한 위치·자세·속도를 물리 상태의 기준으로 삼습니다. ECS나 화면 코드가 같은 값을 다시 적분하지 않습니다.

조사 당시 공식 배포 목록에서 확인한 Flecs 4.1.6과 Jolt 5.5.0을 첫 고정 후보로 둡니다. 실제 빌드에 연결할 때는 두 버전을 명시적으로 고정하고 Windows용 C++ 컴파일러와 화면 없는 빌드에서 확인합니다. 아직 내려받거나 연결하지 않았으므로 서로 잘 맞는지는 검증하지 않았습니다.

### 첫 기체는 PX4 X500으로 검증

첫 실기체 기준 모델은 PX4 X500으로 진행합니다. 제조사 제원과 시각 자료가 있고, PX4 공개 시뮬레이션 모델에는 관성·로터 위치·모터 응답·추력 계수의 출발점이 있습니다. 모델에 들어 있는 숫자는 제조사 실측값이 아니라 시뮬레이터 설정값으로 표시합니다.

제조사 페이지는 무게 610g과 500mm 휠베이스를 안내하지만, PX4 모델의 기준 링크 질량은 2kg입니다. 두 숫자의 측정 범위가 같은지는 확인되지 않았으므로 서로 바꿔 쓰지 않습니다. 완성 기체의 질량·무게중심·관성 자료를 확보하기 전에는 X500과 물리적으로 일치한다고 주장하지 않습니다.

화면 모델은 공개된 PX4 자료를 우선 검토합니다. 저장소의 BSD 3-Clause 표시는 확인했지만, 개별 메시와 텍스처의 권리까지 자동으로 해결되는 것은 아닙니다. 제조사 CAD를 프로젝트에 복사하거나 배포하기 전에도 해당 파일의 이용·재배포 조건을 확인합니다.

### 첫 지형은 SRTM으로 만들고 건물은 별도 처리

시험 지역은 서울 북한산 남쪽의 작은 구역을 우선 후보로 둡니다. SRTM의 실제 고도 자료로 지형을 만들고, 같은 높이 자료에서 화면 형상과 충돌 지형을 함께 생성합니다. 격자 간격이 약 30m라 바위·도로 턱·건물 외벽은 재현하지 못합니다.

건물이 필요해지면 OpenStreetMap을 보조 자료로 검토합니다. 출처 표시와 ODbL 조건을 지키는 배포 방법을 먼저 정합니다. 그 전까지는 임의의 건물 높이를 실측 데이터처럼 넣지 않습니다.

## 상태가 흐르는 순서

```text
명령·시나리오 입력
  → 비행 제어와 모터 목표 계산
  → 로터 힘·토크 적용
  → Jolt 고정 시간 계산
  → Flecs 상태 갱신
  → 센서와 결과 판정
  → 화면용 자세 전달
```

한 객체의 수명은 모의 중심부가 관리합니다. 드론을 만들거나 지울 때 Flecs Entity와 Jolt Body를 같은 경로에서 함께 만들고 정리합니다. Jolt의 Body 식별자는 다른 객체가 임의로 저장·삭제하지 않게 합니다. 첫 구현에서는 물리 계산도 한 스레드에서 실행해 상태 소유권을 단순하게 유지합니다.

## 남은 확인 사항과 다음 작업

현재 코드에는 강체 물리, Flecs, 실제 기체 메시, 실제 지형이 없습니다. 이번 검토에서는 추가하지 않았습니다. Flecs와 Jolt를 연결하기 전에는 저장소 빌드에서 쓸 버전을 고정하고 Windows/MSVC와 화면 없는 실행 경로를 각각 빌드해야 합니다. PX4 시뮬레이션의 질량·관성·모터 계수는 검증 자료와 구분해 보관합니다. 호버링·자유낙하·차등 추력 시험 전에는 실제 비행과 비슷하다고 표현하지 않습니다.

X500 화면 자산의 파일별 권리, 서울 시험 구역의 SRTM 타일과 높이 기준, OSM 자료의 배포 조건은 모델 파일을 추가하기 전에 확인합니다. 다음 구현에서는 Flecs로 드론 한 대와 카메라 한 대를 관리하고, 기존 고정 Tick 시나리오가 같은 결과를 내는지 확인합니다. 그 뒤 Jolt의 자유낙하와 지면 접촉 시험을 더합니다.
