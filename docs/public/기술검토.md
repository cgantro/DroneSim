# 기술 선택과 구현 방향

이 문서는 현재 상태와 다음 구현 순서를 정리합니다. 아래 선택은 조사 결과를 바탕으로 한 추천입니다. 아직 코드에 넣지 않은 기능은 구현된 것처럼 설명하지 않습니다.

## 지금 프로그램이 하는 일

- 네이티브 그래픽 앱은 Flecs Entity에 붙은 Jolt Body로 위치·속도·Quaternion 자세·각속도를 계산합니다. 운동학 기준선은 비교 시험과 WebAssembly 실행에서 사용합니다.
- 그래픽 앱이 화면 표시와 함께 게임패드, UDP 명령, 기록·재생, 시나리오 시연, 성능 측정을 맡고 있습니다. UDP 상태 응답은 위치·속도와 함께 자세 Quaternion 및 각속도도 전달합니다.
- 화면이 없는 시나리오 실행 경로와 OpenGL을 쓰는 화면 실행 경로가 따로 있습니다.
- Flecs 4.1.6은 연결했습니다. 드론과 EO 카메라를 각각 Entity로 만들고, 상태 데이터를 Component로 보관해 고정 Tick마다 System이 갱신합니다.
- 강체 모드는 고정 Tick, PD 비행 제어, 모터·로터 힘·항력, 바람, 평평한 바닥 또는 높이 지형의 접촉을 연결했습니다. 화면에는 PX4가 공개한 X500 메시를 불러와 물리 상태의 위치와 자세로 그립니다.

다음 작업은 현재 화면과 명령 흐름을 한 번에 다시 만드는 일이 아닙니다. 모의 상태를 관리하는 작은 중심부를 만들고 기존 기능을 한 단계씩 연결합니다.

## 우선 선택

### Flecs는 객체 관리에만 사용

Flecs는 화면 객체와 시뮬레이션 객체를 식별하고 필요한 상태를 묶는 데 사용합니다. 드론 Entity에는 위치·속도·비행 상태와 제어 목표를, 카메라 Entity에는 센서 상태를 데이터 Component로 보관합니다. Flecs System이 이 데이터를 읽고 갱신합니다. 입력 처리, UDP 소켓, OpenGL 자원은 기존 C++ 객체로 뒀습니다.

Entity는 장면 속 대상의 번호입니다. Component는 그 대상에 붙이는 위치·속도 같은 데이터이고, System은 그 데이터를 읽거나 갱신하는 계산입니다.

현재는 상태와 제어 목표를 필요한 만큼만 나눴습니다. Flecs 기반 객체 관리의 첫 단계는 끝났지만, 여러 기체나 물리엔진을 연결하는 상태 구조까지 완성된 것은 아닙니다. 다음 단계에서 물리 Body와 모터 상태를 더할 때 같은 값을 두 곳에서 관리하지 않도록 주의합니다. Flecs 고급 파이프라인이나 병렬 실행은 넣지 않았습니다.

### 물리엔진은 Jolt로 시작

현재 프로그램은 자체 OpenGL 창과 화면 없는 실행 경로를 이미 갖고 있습니다. Jolt를 기존 구조에 연결하면 별도 시뮬레이터 없이 강체와 충돌을 계산할 수 있습니다. 강체 실행 모드에서는 Flecs Entity가 Jolt Body 핸들을 보유하고, Flecs System이 1/60초씩 Jolt를 진행한 뒤 계산된 위치·속도·자세·각속도를 Entity 상태에 복사합니다. 이 경로에서는 운동학 적분을 실행하지 않습니다. Gazebo는 쿼드콥터 모터 예제가 있다는 장점이 있지만 별도의 시뮬레이터 환경까지 함께 관리해야 하므로 우선순위에서 제외합니다.

Jolt가 드론을 대신 날려 주지는 않습니다. 작은 C++ 비행 모델에서 모터 회전속도에 따른 추력·토크를 계산하고, 그 힘을 Jolt의 강체(물리 계산 대상)에 적용합니다. Jolt가 계산한 위치·자세·속도를 물리 상태의 기준으로 삼습니다. ECS나 화면 코드가 같은 값을 다시 적분하지 않습니다.

Jolt 강체를 만들 때 질량과 함께 기체 축 기준의 주관성 모멘트를 직접 넣을 수 있게 했습니다. 값은 `kg·m²` 단위이며, 생략하면 기존처럼 상자 크기와 질량으로 계산합니다. X500 호버링 시험에는 공개 시뮬레이터 설정의 관성을 전달하고, 같은 회전력을 받았을 때 관성이 작은 물체가 더 빠르게 도는지도 확인합니다. 0 이하이거나 유한하지 않은 관성값은 거부합니다.

강체 모드에서는 TakeOff·속도·경유점·Yaw 회전·Land 명령을 PD 제어로 모터 속도에 연결합니다. 위치·속도 오차에서 필요한 가속도를 구하고, `F = m(a + g)`로 필요한 힘을 계산합니다. 힘 방향으로 목표 자세를 만들고, 자세·각속도 오차를 토크로 바꿉니다. 로터별 힘은 로터 위치와 회전 방향으로 구성한 4×4 식을 풀어 나눕니다. 현재 제어 이득은 위치 3.0, 속도 2.5, 자세 20.0, 각속도 7.0이며 가속도는 4m/s², 토크는 0.5N·m로 제한합니다. 이 값은 초기 설정이며 실기체 자료에 맞춰 조정하거나 검증하지 않았습니다.

X500 충돌 형상은 PX4 공개 Gazebo 모델을 참고해 아홉 개 상자로 단순화했습니다. 중심 프레임 하나, 착륙 다리 둘, 스키드 둘, 프로펠러 면 넷으로 구성합니다. 각 상자는 기체 중심 기준 위치와 방향을 갖고 하나의 강체로 함께 움직입니다. 화면에는 이 상자 대신 PX4가 공개한 본체·모터·프로펠러 메시를 표시합니다. 착륙 다리 아래쪽이 지면에 닿도록 모델 기준점은 지면에서 0.24m 높이에 둡니다. 네이티브 그래픽 앱은 강체 모드로 실행합니다. 헤드리스 시나리오는 기본적으로 운동학 기준선을 사용하고, 시나리오 설정에서 같은 강체 경로를 선택할 수 있습니다. 한 Entity의 위치를 두 방식이 동시에 계산하지 않도록 경로를 분리했습니다. WebAssembly 빌드는 아직 Jolt 대신 운동학 경로를 사용하며, 이 환경의 전체 빌드는 별도로 확인하지 않았습니다.

### 로터가 만드는 힘과 토크

각 로터의 추력은 `T = k_f ω²`로 계산합니다. `ω`는 모터 회전 속도이고, `k_f`는 속도가 추력으로 바뀌는 비율입니다. 기체에 걸리는 회전력은 로터 위치에서 생기는 `r × F`와 프로펠러 반작용 토크를 더합니다. 회전 방향 값은 반시계 방향일 때 `s=+1`, 시계 방향일 때 `s=-1`입니다. 반작용 토크의 Z축 성분은 `τ_z = -s · 0.016 · T`입니다. 두 회전 방향의 로터가 같은 속도로 돌면 Yaw 토크가 서로 상쇄됩니다.

모터 속도는 목표값에 즉시 도달하지 않습니다. `ω_next = e^(-Δt/τ) × ω_now + (1 - e^(-Δt/τ)) × ω_target` 식으로 한 단계씩 움직입니다. 속도가 올라갈 때와 내려갈 때 서로 다른 `τ`를 사용합니다. 현재 X500 설정은 추력 계수 `8.54858×10⁻⁶`, 반작용 토크 비율 `0.016`, 상승 시간 `0.0125초`, 하강 시간 `0.025초`, 최대 속도 `1000 rad/s`입니다. 로터 위치와 회전 방향도 PX4 Gazebo 설정에서 가져왔습니다.

로터 항력은 PX4 X500 Gazebo 설정의 로터 항력 계수와 구름 모멘트 계수를 사용합니다. 각 로터 위치의 공기 상대 속도에서 로터 축 방향 성분을 뺀 뒤, `F_drag = -|ω| k_d v_perp`로 항력을 계산합니다. 로터와 기체 중심 사이의 위치 벡터 `r`을 이용해 항력이 만드는 모멘트 `r × F_drag`도 더합니다. 구름 모멘트는 `τ_roll = -|ω| k_r v_perp`로 계산합니다. 월드 좌표계에서 기체 속도에서 바람 속도를 빼 공기 상대 속도를 구합니다. 이 계산은 Gazebo 멀티콥터 모터 모델을 단순화해 적용한 것입니다.

이 숫자는 실측값이 아니라 PX4 Gazebo 시뮬레이터 설정값입니다. 중심 기체 2kg에 로터 링크 네 개의 질량을 더해 총 2.0643kg으로 계산합니다. 관성도 각 로터의 관성과 중심까지의 거리를 평행축 정리로 더했습니다. 로터 높이 0.06m도 항력이 만드는 회전력 계산에 반영했습니다. 다만 로터를 각각 회전하는 강체로 계산하지 않고, 질량과 관성을 한 강체에 합친 근사입니다. 기체 몸체 전체의 공기 저항과 실제 기체 제어도 아직 모델에 넣지 않았습니다. 같은 속도의 로터가 만드는 추력·토크, 모터 응답과 로터 항력 방향은 시험했지만, 이 계산만으로 실제 비행 성능을 확인한 것은 아닙니다.

헤드리스 강체 시나리오는 `wind_velocity_meters_per_second`로 일정한 월드 바람을 설정할 수 있습니다. 2m/s 바람을 X축으로 둔 10초 이륙·착륙 시험에서는 착륙 위치가 처음 위치에서 약 1.71m 벗어났습니다. 현재 제어기는 공중에서 속도를 줄이지만 위치를 고정하지 않습니다. 또 로터가 중심 기체보다 0.06m 높은 곳에서 항력을 받아 자세에 회전력이 생깁니다. 이 값은 현재 모델에서 재현한 결과이지 실제 X500의 바람 대응 성능을 뜻하지 않습니다.

공식 배포 목록에서 확인한 Flecs 4.1.6과 Jolt 5.6.0을 기준으로 합니다. Flecs 4.1.6은 Release 빌드와 화면 없는 실행, Viewer 스모크 시험에서 확인했습니다. 강체 단위 시험에는 자유낙하, 힘·토크, 평평한 바닥·실제 높이 지형 접촉, 로터 추력으로 만든 호버링, 입력한 관성에 따른 회전 차이, 여러 상자로 된 강체의 접촉이 포함됩니다. 강체 경로에서는 상승·속도 이동·경유점·Yaw 회전·착륙 명령과 같은 입력의 반복 결과도 확인합니다. 헤드리스 실행에서는 바람을 포함한 강체 모드 이륙·착륙 시나리오도 확인합니다. 지형 격자 읽기, 좌표 변환, 최고점 충돌과 Viewer 시작도 확인합니다. 최신 전체 빌드와 시험 결과는 아래 기록에서 갱신합니다. 제어 이득과 공력 값의 실기체 적합성은 검증하지 않았습니다.

### 첫 기체는 PX4 X500으로 검증

첫 실기체 기준 모델은 PX4 X500으로 진행합니다. 제조사 제원과 시각 자료가 있고, PX4 공개 시뮬레이션 모델에는 관성·로터 위치·모터 응답·추력 계수의 출발점이 있습니다. 모델에 들어 있는 숫자는 제조사 실측값이 아니라 시뮬레이터 설정값으로 표시합니다.

제조사 자료의 610g은 X500 V2 프레임 키트 무게이고, 500mm는 휠베이스입니다. PX4 Gazebo는 중심 기체를 2kg, 로터 링크 네 개를 합쳐 2.0643kg으로 설정합니다. 프레임 키트 무게와 시뮬레이터 기체 질량은 포함 부품과 기준이 다르므로 직접 비교하지 않습니다. 배터리와 탑재 장비를 포함한 비행 상태의 질량·무게중심·관성 자료를 확보하기 전에는 X500 실기체와 물리적으로 일치한다고 주장하지 않습니다.

화면에는 PX4가 공개한 X500 본체, 모터와 프로펠러 메시를 불러옵니다. 원본의 미터·Z축 위 좌표를 화면의 Y축 위 좌표로 바꾸고, SDF에 적힌 부품 위치를 적용해 하나의 메시로 묶었습니다. 약 25만 개 삼각형으로 된 형상이며, 표면 무늬와 개별 재질은 가져오지 않아 현재 화면에서는 한 가지 색으로 보입니다. PX4 모델 저장소는 BSD 3-Clause 조건을 표시하고 있어 그 안내를 모델 자산과 함께 보관합니다. 이 시각 메시를 X500 전체의 정확한 CAD나 실측 형상으로 간주하지 않습니다.

### 실제 지형 높이를 화면과 충돌에 연결

북한산 남쪽 구역의 NASA SRTM 자료를 65×65 격자로 잘라 화면 지형과 Jolt 높이 충돌체에 함께 사용합니다. 자료 중심의 위도·경도를 시뮬레이션 원점 `(0, 0)`에 두고, 지역 범위가 작아 위도·경도 차이를 동쪽·북쪽 평면 거리로 근사합니다. 기준 높이는 중심점의 EGM96 고도이며, 지형 높이는 이 값에서 얼마나 위·아래인지 나타냅니다.

격자는 동서 약 24.5m, 남북 약 30.9m 간격입니다. 자동 시험은 실제 격자의 최고점에서 강체가 멈추는지 확인합니다. Viewer 시작 시험은 지형 자료를 읽어 화면 장면을 그리는 경로를 실행합니다. 지형 높이 정확도나 실제 지도 화면의 시각 품질을 별도 측량 자료와 비교하지는 않았습니다.

건물이 필요해지면 OpenStreetMap을 보조 자료로 검토합니다. 출처 표시와 ODbL 조건을 지키는 배포 방법을 먼저 정합니다. 그 전까지는 임의의 건물 높이를 실측 데이터처럼 넣지 않습니다.

## 앞으로 연결할 상태 흐름

```text
명령·시나리오 입력
  → 비행 제어와 모터 목표 계산
  → 로터 힘·토크와 항력 적용
  → Jolt 고정 시간 계산
  → Flecs 상태 갱신
  → 센서와 결과 판정
  → 화면용 자세 전달
```

현재 단일 드론에서는 모의 코어가 Flecs Entity와 Jolt Body를 함께 만들고 정리합니다. 여러 드론을 추가하거나 개별 Entity를 삭제하는 경로는 아직 없습니다. Jolt 물리 월드는 한 스레드에서 고정 Tick마다 계산합니다.

## 남은 확인 사항과 다음 작업

네이티브 그래픽 앱은 강체 모드로 실행하며 드론 Entity가 Jolt Body와 모터 상태를 보유합니다. 고정 Tick마다 비행 제어, 모터 응답, 로터 힘·토크·항력, Jolt 적분, 상태 복사를 순서대로 실행합니다. 헤드리스 실행은 기본적으로 운동학 기준선을 사용하지만, 시나리오 설정으로 강체 모드와 월드 바람을 선택할 수 있습니다. 바람을 포함한 Release 이륙·착륙 시나리오, 실제 지형 충돌 시험, Viewer 스모크가 통과했습니다. X500의 아홉 충돌 상자를 단일 강체로 만들고 지면에 놓는 시험도 추가했습니다. WebAssembly는 운동학 경로로 지형을 그리지만 Jolt 충돌을 계산하지 않습니다. PX4 공개 메시와 제조사 CAD·실물의 치수 및 외관 비교, 제어 이득과 공력 값의 실기체 적합성, 건물 충돌, 기체 몸체 항력은 아직 확인하지 않았습니다. PX4 시뮬레이션의 질량·관성·모터 계수는 실측값과 구분해 보관합니다.

자유낙하 시험은 처음에 1초 뒤 위치를 약 5.1m로 예상했지만, Jolt는 각 단계에서 속도를 먼저 갱신한 뒤 위치를 움직입니다. 이 계산을 60단계에 적용하면 위치는 약 5.013m가 됩니다. 시험 기대값을 이 단계별 계산에 맞춰 고쳤습니다. 이 값은 Jolt의 적분 방식을 확인한 것이며 실제 기체의 낙하 결과를 뜻하지 않습니다. 첫 빌드 시도에서 `cassert`를 찾지 못한 문제는 C++ 개발 환경을 불러오지 않은 데서 생겼고, 환경을 설정한 뒤에는 코드 변경 없이 빌드됐습니다.

X500 화면 자산의 이용 조건, 서울 시험 구역의 SRTM 높이 기준, OSM 자료의 배포 조건은 데이터를 추가하기 전에 확인합니다. 다음에는 공개 메시의 크기와 배치를 제조사 CAD·실물 자료와 대조하고, 물리 상태의 자세가 센서·화면·기록 경로에서 같은 기준으로 쓰이는지 확인합니다. PX4 시뮬레이션 파라미터와 제조사 제원 사이의 차이도 유지하며, 실측 자료를 확보하기 전까지 물리 일치성을 주장하지 않습니다. 운동학 기준선은 비교 시험에 남겨 둡니다.
