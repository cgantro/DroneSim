# AeroSimLab 사용 문제 해결

이 문서는 프로그램을 실행하거나 사용하는 중 문제가 생겼을 때 확인할 순서를 안내합니다.

## 프로그램이 시작되지 않음

1. Visual Studio의 출력 창이나 콘솔에서 가장 먼저 나온 오류를 확인합니다.
2. Visual Studio에서 저장소 폴더를 CMake 프로젝트로 열었는지 확인합니다.
3. vcpkg를 사용한다면 `VCPKG_ROOT`가 vcpkg 최상위 폴더를 가리키는지 확인하고, 환경 변수를 바꾼 뒤 Visual Studio를 다시 시작합니다.
4. 빌드가 성공했는데 셰이더나 화면 자원을 찾지 못하면 시뮬레이터를 빌드 출력 폴더에서 실행해 봅니다. 앱은 상대 경로로 자원을 찾습니다.

## 창은 열리지만 화면이 비어 있음

- 그래픽 드라이버가 OpenGL 3.3을 지원하는지 확인합니다.
- 셰이더 파일이 실행 파일이 기대하는 상대 경로에 있는지 확인합니다.
- 창을 닫았다가 다시 실행하고, 출력 창의 초기화 오류를 확인합니다.
- `--smoke-test`는 자동 화면 시작 점검 모드이며, 사용자 화면의 모든 장면과 입력을 확인하는 기능은 아닙니다.

## 지상통제 명령에 응답이 없음

- 시뮬레이터가 실행 중인지 확인합니다. 데스크톱 시뮬레이터는 기본 UDP 포트 `27015`를 사용합니다.
- 지상통제 프로그램의 대상 주소와 포트가 시뮬레이터의 주소·포트와 같은지 확인합니다. 로컬 실행 기본 주소는 `127.0.0.1:27015`입니다.
- 방화벽이나 다른 프로그램이 해당 UDP 포트를 막거나 점유하고 있는지 확인합니다.
- 명령 응답 제한 시간은 지상통제 클라이언트 기본값 4초이며, 대기 중 400ms 간격으로 재전송할 수 있습니다. 제한 시간 안에 응답을 받지 못하면 CLI는 종료 코드 3을 반환합니다.
- UDP는 전달을 보장하지 않습니다. 응답 시간 초과는 명령이 적용되지 않았다는 확정 증거가 아니므로, 상태를 확인한 뒤 같은 동작을 반복할지 판단합니다.

## 명령이 거부됨

- `takeoff`는 지상 상태에서, 이동·회전·정지·착륙은 공중 상태에서 사용할 수 있습니다.
- 좌표는 미터, 회전 속도는 라디안/초입니다. 숫자 세 개가 필요한 명령에는 x, y, z 값을 모두 입력합니다.
- 속도는 최대 5m/s, Yaw 회전 속도는 최대 1.5rad/s로 제한됩니다.
- GUI와 CLI 클라이언트를 동시에 사용할 때 명령 시퀀스가 서로 다르면 중복·역순으로 판단될 수 있습니다. 한 번에 한 클라이언트로 확인하세요.

## 게임패드가 반응하지 않음

- Windows의 게임 컨트롤러 설정에서 장치가 인식되는지 확인합니다.
- 시뮬레이터를 장치 연결 뒤 다시 실행합니다.
- 제품별 버튼 배치가 다를 수 있으며, 모든 Xbox 호환 장치의 동작을 검증한 것은 아닙니다.

## 카메라 상태나 영상이 기대와 다름

- 카메라 `fault` 상태는 `recover` 명령으로 복구합니다. 장애 상태에서 단순히 `on`을 보내도 장애가 해제되지 않습니다.
- `off`는 센서를 비활성화합니다. 비활성 상태에서는 프레임 메타데이터가 증가하지 않습니다.
- 화면에 표시되는 RGB 픽셀은 시뮬레이터가 만든 장면입니다. 실제 EO 카메라의 입력·초점·노출이나 전송 상태를 나타내지 않습니다.
- 카메라 메타데이터는 활성 상태에서 매 시뮬레이션 Tick마다 갱신되며, 픽셀 Readback은 그래픽 화면 생성과 별도입니다.

## 시나리오가 실패하거나 파일을 읽지 못함

- JSON 문법과 필수 `version`, `ticks`, `commands`, `expected` 항목을 확인합니다.
- 시나리오 버전은 현재 `1`이어야 합니다. Tick 수는 0 이상의 정수여야 합니다.
- 각 명령의 Tick이 실행 범위 안에 있고, 필요한 좌표 배열에 숫자 3개가 있는지 확인합니다.
- 프로그램은 결과 JSON의 `issues`와 `events`에 판정 근거를 씁니다. 종료 코드 `0`은 통과, `1`은 시나리오 판정 실패, `2`는 실행·입력 오류입니다.
- 현재 시나리오는 시작 위치·방향을 입력할 수 없고, 고정 초기 상태에서 시작합니다.
