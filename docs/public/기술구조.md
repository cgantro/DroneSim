# DroneSim 기술 구조

이 문서는 드론의 상태가 갱신되고, 통신망과 화면에 반영되는 흐름을 설명합니다. 실행과 조작 방법은 [시작 안내](시작하기.md), 기능별 구현 여부는 [현재 상태](../../SPEC.md), 시험 수치는 [성능 검증](성능검증.md)에서 확인할 수 있습니다.

## 한 번의 시뮬레이션 흐름

시뮬레이션은 1초를 60번으로 나눈 고정 간격으로 진행합니다. 이 한 단계를 `Tick`이라고 합니다. 화면이 그려지는 속도와 시뮬레이션 진행 속도는 서로 다를 수 있습니다.

```mermaid
flowchart LR
    Input[게임패드·지상통제·임무] --> Core[시뮬레이션 상태 갱신]
    Core --> Physics[비행·접촉 계산]
    Core --> Network[드론 간 가상 통신]
    Physics --> State[위치·자세·배터리·임무 상태]
    Network --> State
    State --> Render[3D 장면·EO 카메라·상태 패널]
    State --> Result[시험 결과와 기록]
```

시뮬레이션 중심부는 드론 상태와 임무를 관리합니다. 입력·화면·통신은 각자 맡은 방식으로 명령이나 상태를 전달합니다. 그래서 화면을 띄우지 않는 자동 시나리오 시험도 같은 비행·임무 계산을 사용할 수 있습니다.

## 현재 시험 임무

현재 기준 대상은 한 종류의 X500 드론 네 대입니다. 기체 수와 기종을 설정 파일에서 자유롭게 바꾸는 기능은 아직 없습니다.

| 단계 | 현재 동작 | 남은 점 |
| --- | --- | --- |
| 편대 이동 | 리더의 목표를 가상 통신망으로 전달하고 선택한 대형을 따라 이동합니다. | 좁은 공간에서 대형을 자동으로 바꾸지 않습니다. |
| 분산 정찰 | 사람이 미리 정한 지점을 여러 드론에 나눠 주고, 각 지점으로 이동한 뒤 착륙합니다. | 영상 저장·전달과 장애 뒤 임무 재배정은 이 화면 흐름에 연결되지 않았습니다. |
| 복귀 | 각 드론이 자신이 출발한 자리로 돌아가 착륙합니다. | 공통 집결 지점에서 대형을 다시 만든 뒤 함께 복귀하는 단계는 없습니다. |

정찰 지점에서 시설물 파손이나 새로운 조사 위치를 자동으로 판단하지 않습니다. 촬영 결과의 판독은 사람이 합니다. 시험 지점을 방문하는 동작과 실제 촬영 자료의 수집은 별개의 기능입니다.

## 비행과 물리 계산

Windows 네이티브 실행은 AirSim의 멀티로터 강체 계산에 로터 입력을 전달합니다. AirSim은 모터 응답, 추력·토크, 중력, 공기 저항, 기체 이동과 접촉 반응을 계산합니다. 시뮬레이터는 계산 결과를 다시 드론 상태와 화면에 반영합니다.

제어기는 목표 위치·속도와 현재 상태의 차이에서 필요한 가속도를 구하고, 자세 오차와 각속도로부터 기체 회전 목표를 계산합니다. 그 결과를 네 로터의 회전 목표로 배분합니다. 이 구성은 공개 X500 제원과 모터 자료를 참고했지만, 실제 기체의 측정 궤적과 대조해 정확도를 입증한 것은 아닙니다.

웹 실행은 AirSim을 포함하지 않고 간단한 운동학 계산을 사용합니다. 그러므로 웹과 네이티브의 비행 결과를 같은 물리 모델의 검증 결과로 비교할 수 없습니다.

월드 좌표는 동·북·위(ENU), 기체 좌표는 앞·왼쪽·위(FLU)를 기준으로 합니다. AirSim 경계에서는 북·동·아래(NED), 앞·오른쪽·아래(FRD) 기준으로 축과 부호를 바꿉니다. 이 변환은 위치·속도·자세뿐 아니라 로터 위치와 충돌 정보에도 적용됩니다.

### PX4 X500 기록 비교

PX4 공개 비행 기록을 60Hz로 다시 맞춰 현재 강체 모델에 입력하고, 위치·속도·자세·각속도 차이를 계산하는 경로가 있습니다. 최근 문서화된 시험은 한 번의 X500 비행에서 공중 구간 22개를 골라 4초씩 비교했습니다. 모터 입력에는 기록에 남은 ESC 회전수를 사용했습니다.

| 오차 | PX4 설정 | 제조사 시험표를 참고한 설정 |
| --- | ---: | ---: |
| 위치 중앙값 | 0.651m | 0.601m |
| 속도 중앙값 | 0.537m/s | 0.460m/s |
| 자세 중앙값 | 18.74° | 22.13° |
| 각속도 중앙값 | 0.259rad/s | 0.366rad/s |

이 비교는 한 번의 로그에서 잘라낸 구간이며, 참조 위치와 자세도 PX4의 추정값입니다. 모든 구간에서 시뮬레이션 기체가 평면 바닥에 닿았습니다. 따라서 표는 입력 재생과 오차 계산이 동작한 결과이지, 실제 X500의 비행 정확도를 검증한 결과가 아닙니다. 시험 범위와 다른 입력 방식의 결과는 [PX4 기록 재생 문제](문제해결/PX4-기록-재생-자세-차이.md)에 정리했습니다.

## 드론 간 가상 통신

가상 통신망은 각 드론의 위치와 건물 가림을 사용해 직접 연결할 이웃을 찾습니다. 드론은 이웃 정보를 교환하고 목적지까지 여러 드론을 거치는 경로를 찾습니다. 링크가 끊겨 기존 경로를 쓸 수 없으면 경로 오류를 알리고 새 경로를 찾습니다.

이 통신망은 AODV에서 쓰는 경로 요청·응답 흐름을 참고한 시뮬레이션 코드입니다. 실제 무선 신호, 주파수 간섭, 안테나 특성은 계산하지 않습니다. 현재 화면에서는 편대가 움직이는 동안 드론 사이 링크를 끊거나 복구하고, 최근 네트워크 사건을 볼 수 있습니다. 이 사건 목록은 최근 64개만 메모리에 보관하며 파일로 남기지 않습니다.

## 장면, 충돌, 카메라

기본 장면은 산업시설과 자연물 에셋을 배치한 반복 시험용 가상 훈련장입니다. 실제 탄천이나 특정 도시를 정확히 옮긴 지도가 아니며, 건물·지형의 위치와 치수가 실측과 일치한다고 보장하지 않습니다.

화면에는 GLB 모델을 사용하고 충돌 계산에는 별도로 준비한 단순 형상을 사용합니다. 따라서 보이는 표면과 충돌 표면은 다를 수 있습니다. 지형·건물·드론 접촉은 충돌 형상으로 계산하며, 화면 모델의 세밀한 표면 전체를 충돌 메시로 쓰지는 않습니다.

장면과 EO 카메라는 OpenGL로 그립니다. 카메라는 기체의 위치와 탑재 자세를 기준으로 영상을 만듭니다. OpenCV는 CPU로 전달된 영상의 밝기·대비·선명도를 계산합니다. 이 값은 화면 품질 지표이며 사람이나 파손을 찾아내는 영상 인식 결과가 아닙니다.

## 프로그램 구성과 기술 선택

| 기술 | 프로젝트에서 맡은 일 | 선택 이유와 범위 |
| --- | --- | --- |
| C++20 | 시뮬레이션, 비행, 통신, 화면 모듈 구현 | `std::jthread`·취소 토큰으로 작업 수명을 관리하고, `std::span`으로 데이터를 복사하지 않는 읽기 범위를 전달합니다. `std::bit_cast`, `std::endian`, `std::lerp`, `std::numbers`도 지형 읽기와 수치 계산에 사용합니다. |
| Flecs | 드론별 상태와 Tick 작업 관리 | 드론 상태 데이터와 이를 갱신하는 일을 구분합니다. 현재 기체 수는 네 대로 고정해 시험합니다. |
| AirSim | 네이티브 멀티로터 강체 계산 | 로터부터 기체 운동까지 직접 적분기를 만들지 않고 외부 물리 구현을 사용합니다. 웹 빌드에는 포함되지 않습니다. |
| OpenGL·GLFW | 장면·카메라 렌더링과 창·입력 처리 | 네이티브 화면을 직접 제어합니다. GPU 자원과 화면 구성을 프로젝트가 관리합니다. |
| Dear ImGui | 비행 상태와 패널 조작 화면 | 시뮬레이터 창 안에 상태와 조작 요소를 표시합니다. |
| GLM | 벡터·행렬·쿼터니언 계산 | 그래픽과 시뮬레이션에서 같은 고정 크기 수학 형식을 사용합니다. |
| GStreamer | 네이티브 영상 인코딩·전송 경로 | 검증된 미디어 구성요소를 사용합니다. 임무별 영상 저장과 전송 완료 판정은 현재 분산 정찰 흐름에 연결되지 않았습니다. |
| OpenCV | EO 영상의 기본 품질 지표 계산 | 필요한 영상 통계를 직접 구현하지 않고 라이브러리로 계산합니다. 객체 탐지는 하지 않습니다. |
| CMake | 네이티브·웹 빌드 구성과 의존성 연결 | 플랫폼별로 포함할 기능을 나눕니다. 네이티브와 웹은 물리 기능이 다릅니다. |

C++20을 고른 이유는 최신 문법 자체가 목적이어서가 아닙니다. 스레드 취소, 스레드 수명, 비소유 데이터 범위와 파일 비트 해석을 표준 기능으로 처리해 자체 보조 코드를 줄이기 위해서입니다. 템플릿 메타프로그래밍, 코루틴, C++ 모듈은 현재 핵심 동작에 사용하지 않습니다.

## 검증 범위

시험 결과와 확인한 시점을 [기능 현황](../../SPEC.md)에 기록합니다. 자동 시험에서 통신 경로 변경이 확인됐더라도, 분산 정찰과 복귀 버튼을 실제 창에서 눌러 전체 비행을 확인한 것은 아닙니다. 실기체 안전성, 실제 무선 통신 성능, 실제 도시와의 지형·건물 오차도 검증하지 않았습니다.

과거 문제의 증상과 수정 당시 시험은 [문제 해결 기록](문제해결.md)에 따로 정리했습니다. 당시 결과는 현재 전체 기능이 모두 정상이라는 뜻이 아닙니다.
