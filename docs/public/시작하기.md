# 실행하고 기본 기능 확인하기

이 안내는 Windows에서 시뮬레이터를 실행하고, 현재 화면에서 확인할 수 있는 기능을 살펴보는 순서입니다. 기능별 구현 상태와 자동 시험 범위는 [기능 현황](../../SPEC.md)에 있습니다.

## 1. 프로그램 실행

1. 저장소를 Visual Studio에서 엽니다.
2. CMake 구성으로 `ninja-release`를 선택합니다.
3. `aerosimlab_simulator` 대상을 빌드하고 실행합니다.
4. 3D 장면과 비행 상태 패널이 나타나는지 확인합니다.

처음 구성할 때 의존성 내려받기에 인터넷 연결이 필요할 수 있습니다.

## 2. 화면 살펴보기

- **장면:** 가상 훈련장과 드론 위치를 보여 줍니다.
- **카메라:** 드론별 시점을 두 열로 배치합니다. 화면 비율은 각 카메라 모델 설정을 따릅니다.
- **비행 상태:** 비행 모드, 위치, 모의 시간과 임무 진행을 표시합니다.
- **통신 사건:** 메시지 중계·전달과 경로 상태를 표시합니다. 최근 사건은 실행 중 최대 64개까지 보관하며 파일로 저장하지 않습니다.

장면과 카메라 패널은 제목을 끌어 옮기고 경계를 끌어 크기를 바꿀 수 있습니다. 자동 Viewer 시험은 창이 시작되는지만 확인하므로 패널 배치와 화면 비율은 직접 확인해야 합니다.

현재 녹화와 영상 품질 분석은 주 드론 카메라만 처리합니다. 다른 드론 카메라 화면을 임무 자료로 저장하거나 전송하는 기능은 아직 연결되지 않았습니다.

## 3. 게임패드 연결 확인

게임패드를 연결한 뒤 프로그램을 실행합니다.

| 입력 | 동작 |
| --- | --- |
| A 버튼 | 이륙 |
| B 버튼 | 착륙 |
| 왼쪽 스틱 | 앞·뒤·좌·우 이동 |
| 오른쪽 스틱 가로축 | 좌우 회전 |
| 왼쪽·오른쪽 트리거 | 하강·상승 |

Windows가 장치를 찾는지 확인하려면 `Win + R`을 누르고 `joy.cpl`을 실행합니다. 처음에는 스틱과 트리거를 조금씩 움직여 기체 반응을 살펴보세요.

## 4. 편대 통신 장애 살펴보기

1. 비행 상태 패널에서 V자·일렬·횡대 가운데 대형을 고릅니다.
2. 드론이 모두 지상에 있을 때 **편대 이동 시작**을 누릅니다.
3. 통신 장애 설정에서 두 드론을 고르고 **링크 끊기**를 누릅니다.
4. 통신 사건에서 경로 탐색과 메시지 전달이 바뀌는지 확인합니다.
5. **패킷 손실률**을 0보다 높여 전달·중계·폐기 횟수가 달라지는지 확인합니다.
6. **링크 복구**를 누르고 손실률을 0으로 되돌립니다.

이 시험은 드론 사이 거리, 건물 가림, 설정한 지연과 손실을 사용하는 가상 통신입니다. 실제 무선 장비나 전파 환경을 재현하지 않습니다. 패킷 손실 중 전체 임무가 복구되는 과정은 창에서 검증하지 않았습니다.

## 5. 세 단계 임무 실행

**전체 임무 시작 (M01 → M02 → M03)**을 누르면 편대 이동, 지점 분담 정찰, 재집결과 복귀 순서로 진행합니다. 추종 드론은 리더가 보낸 경로를 받은 뒤 이동합니다. 확인 응답이 오지 않으면 60 Tick 간격으로 다시 보내며, 최대 10회까지 시도합니다.

경로 재전송은 통신망 시험에서 확인했습니다. 실제 창에서 처음부터 끝까지 진행되는지, 패킷 손실 뒤 임무가 복구되는지는 확인하지 않았습니다. 정찰 지점은 사람이 정하며 드론은 그곳의 영상과 위치 정보를 확보합니다. 파손 여부는 사람이 판단합니다.

## 실행 환경의 차이

- Windows 네이티브는 AirSim 강체 물리를 사용합니다.
- 웹 빌드는 단순화한 운동학 계산을 사용합니다.
- 두 실행 환경의 비행 결과는 같은 물리 모델로 계산되지 않습니다.
- 가상 통신망은 실제 전파·안테나·무선 장비 성능을 계산하지 않습니다.
