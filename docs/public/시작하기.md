# AeroSimLab 처음 실행하고 조작하기

AeroSimLab은 가상 드론의 움직임, 만들어진 카메라 화면, 지상통제 명령을 시험하는 프로그램입니다. 실제 드론·조종기·카메라를 제어하거나 실제 비행 안전성을 보증하지 않습니다.

## Windows에서 빌드

필요한 도구는 C++20을 지원하는 CMake, Ninja, Visual Studio C++ 빌드 도구, vcpkg입니다. `VCPKG_ROOT` 환경 변수는 vcpkg 최상위 폴더를 가리켜야 합니다. 처음 구성할 때는 의존성 설치를 위해 네트워크가 필요할 수 있습니다.

저장소 폴더에서 PowerShell을 열고 다음 순서로 실행합니다.

```powershell
cmake --preset ninja-release
cmake --build --preset ninja-release
```

그래픽 시뮬레이터는 `build-ninja-release/aerosimlab_simulator.exe`입니다. 시뮬레이터는 실행 위치에서 셰이더 등 화면 자원을 찾으므로 빌드 출력 폴더에서 실행합니다.

```powershell
Set-Location build-ninja-release
./aerosimlab_simulator.exe
```

도움말은 `./aerosimlab_simulator.exe --help`로 확인합니다. 그래픽 실행 옵션은 `--demo`(자동 시연), `--smoke-test`(자동 화면 시작 확인), `--benchmark`(5초 측정), `--udp-port <포트>`입니다. 기본 UDP 포트는 `27015`입니다. `--smoke-test`와 `--benchmark`는 일반 사용 모드가 아니라 확인·측정 모드입니다. 성능 측정 결과는 실행 파일 옆의 `benchmark-latest.json`에 저장하며, 다음 측정 때 같은 파일을 덮어씁니다.

## 화면과 조작

창 왼쪽은 장면을 바라보는 관찰자 시점이고, 오른쪽은 기체 앞쪽에 고정된 EO 카메라 시점입니다. 지원되는 게임패드가 감지되면 다음 입력을 사용할 수 있습니다.

| 입력 | 동작 |
| --- | --- |
| A 버튼 | 이륙 |
| B 버튼 | 착륙 |
| 왼쪽 스틱 | 앞·뒤·좌·우 이동 |
| 오른쪽 스틱 가로축 | 방향 회전 |
| 왼쪽·오른쪽 트리거 | 높이 낮추기·높이 올리기 |

장치별 입력 배치가 다를 수 있고 모든 Xbox 호환 기기 조합을 검증한 것은 아닙니다. 게임패드 조작과 지상통제 명령을 동시에 사용하지 마세요.

## 지상통제 명령 보내기

시뮬레이터와 지상통제 프로그램을 함께 실행합니다. Windows 빌드에서 명령 줄 버전은 `aerosimlab_ground_control_cli.exe`입니다. 포트를 바꾸지 않았다면 대상 주소는 `127.0.0.1`, 포트는 `27015`입니다.

창으로 조작하려면 `aerosimlab_ground_control.exe`를 실행하고 Host와 Port를 확인합니다. 창에는 이륙·정지·착륙, 좌표를 입력하는 경유점, 카메라 켜기·끄기·장애 주입·복구, 게임 입력 기록 시작·정지·재생 버튼이 있습니다. 입력 기록은 시뮬레이터가 실행 중인 동안 메모리에 보관되며 파일로 저장되지 않습니다.

```powershell
./aerosimlab_ground_control_cli.exe --help
./aerosimlab_ground_control_cli.exe --command takeoff
./aerosimlab_ground_control_cli.exe --command waypoint 3 0 1.5
./aerosimlab_ground_control_cli.exe --command land
./aerosimlab_ground_control_cli.exe --camera fault
./aerosimlab_ground_control_cli.exe --camera recover
```

다른 주소나 포트는 `--host IPv4`, `--port 번호`로 지정합니다. 가능한 비행 명령은 `takeoff`, `land`, `stop`, `velocity x y z`, `waypoint x y z`, `yaw-rate 값`입니다. 좌표와 속도는 미터·초 기준이고 회전 속도는 rad/s입니다. 속도 벡터 크기는 최대 5m/s, Yaw 회전 속도는 최대 1.5rad/s로 제한됩니다.

응답에는 접수 여부, 적용 Tick, 드론 상태와 카메라 메타데이터가 표시됩니다. 지상통제 프로그램은 기본 4초 동안 응답을 기다리고 재전송할 수 있습니다. UDP는 명령 전달을 보증하지 않으므로 timeout 뒤에는 상태를 확인하세요.

## JSON 시나리오 실행

화면 없이 정상 비행 시나리오를 실행하려면 빌드 출력 폴더에서 다음을 실행합니다.

```powershell
./aerosimlab_headless.exe --scenario ../scenarios/flight/normal-flight.json
./aerosimlab_headless.exe --scenario ../scenarios/flight/rigid-body-flight.json
./aerosimlab_headless.exe --scenario ../scenarios/fault-injection/fault-injection.json
```

프로그램은 판정 JSON을 출력합니다. `passed: true`와 종료 코드 `0`은 통과, 종료 코드 `1`은 실행 후 기대값과 맞지 않음, `2`는 파일·형식·명령 사용 오류입니다. 결과의 `issues`와 `events`를 확인해 판정 이유를 살펴보세요.

기본 시나리오는 원점에서 시작하는 드론 한 대를 사용합니다. 여러 대를 시험하려면 최상위 `drones` 목록에 각 드론의 `name`과 `initial_position_meters`를 적습니다. 명령에 `drone` 이름을 붙여 대상을 고르고, `expected.drones`에 각 드론의 마지막 상태와 위치를 적습니다. 명령에서 `drone`을 생략하면 목록의 첫 드론을 대상으로 합니다. `expected.minimum_drone_separation_meters`에는 허용할 최소 3차원 중심 간 거리를 적습니다. 실제 거리가 이 값보다 짧으면 시나리오는 실패하고, 측정한 최소 거리는 결과에 표시됩니다.

`formation_links`를 쓰면 한 드론이 다른 드론의 위치를 따라갑니다. `leader`의 위치에 `offset_meters`를 더해 `follower`의 목표로 삼습니다. `outages`에는 연결이 끊기는 시작·끝 Tick을 적습니다. 시작 Tick에는 연결이 끊기고 끝 Tick부터 복구됩니다. 연결이 끊긴 동안 follower는 마지막 목표를 유지하고, 복구 뒤 새 위치를 따라갑니다. 이 기능은 매 Tick 위치를 공유하는 단순한 한 방향 연결입니다. 실제 무선 지연이나 신호 세기는 계산하지 않습니다. [위치 공유 장애 예제](../../scenarios/multi-drone/leader-following-outage.json)에서 동작을 확인할 수 있습니다. 카메라는 시나리오 전체에서 아직 하나만 사용합니다.

공동 임무는 최상위 `mission`에 이름과 `tasks`를 적습니다. 각 임무에는 고유한 `name`, 맡은 `role`, 담당 `drone`, `target_position_meters`, `start_tick`, `deadline_tick`, `tolerance_meters`가 필요합니다. 두 대 이상의 드론에 서로 다른 임무를 배정해야 합니다. 각 드론은 임무 시작 시 이미 비행 중이어야 합니다. 목표 허용 거리 안에 들어오면 그 임무를 완료로 기록하고, 하나라도 기한을 넘기거나 시작할 수 없으면 전체 시나리오가 실패합니다. 결과 JSON의 `mission` 항목에서 역할별 성공 여부와 완료 Tick을 확인할 수 있습니다. [두 지점 조사 예제](../../scenarios/multi-drone/two-point-survey.json)를 참고하세요. 임무 목표가 지정된 드론은 같은 시간에 `formation_links`의 follower로도 지정할 수 없습니다.

명령과 카메라 이벤트는 JSON에 지정한 Tick 순서로 처리됩니다. 기본 계산 방식은 운동학입니다. JSON 최상위 항목에 `"dynamics": "rigid_body"`를 넣으면 모터·비행 제어기와 Jolt 강체 물리를 사용합니다. 이때 `"wind_velocity_meters_per_second": [2, 0, 0]`처럼 월드 좌표의 바람 속도도 지정할 수 있습니다. 바람은 강체 시나리오에서만 사용할 수 있습니다. 여러 드론의 개별 명령, 중심 간 최소 거리, 위치 공유 장애, 역할별 목표 지점 임무를 시험할 수 있습니다. 임무 간 선후 관계, 실제 통신 특성, 물리 접촉 시각·충격량을 이용한 판정, 화면 조작은 아직 지원하지 않습니다.

## 무엇을 모의하고 무엇을 모의하지 않나

- 모의 Tick은 60Hz 고정 간격으로 진행합니다. 화면 그리기 주기와 별개입니다.
- 그래픽 앱과 `rigid_body` 시나리오는 관성·모터 지연·로터 추력·로터 항력·자세 변화를 포함한 Jolt 강체 경로를 사용합니다. 바람은 강체 시나리오에서만 지정할 수 있습니다. 제어 이득과 공력 값이 실제 기체에 맞는지는 검증하지 않았습니다.
- `kinematic` 시나리오는 시험 기준선으로 유지합니다. 위치·속도 명령을 간단한 운동 모델로 처리하며, 가속도·관성·모터·추력·기체 기울기는 계산하지 않습니다.
- 카메라 영상은 화면 장면에서 생성하는 RGB 픽셀입니다. 밝기·대비·선명도는 단순 요약값이지 실제 광학 품질 판정이 아닙니다.
- 화면과 강체 충돌에 북한산의 실제 높이 자료를 사용합니다. 격자는 약 30m 간격이며 도로·건물·작은 장애물과 가시성 분석은 아직 없습니다.
- 실제 EO 영상 입력, 지상통제 영상 전송, AI 영상 분석, 다중 드론 협동, 실제 비행 성능·안전성 검증은 범위 밖입니다.

실행 오류는 [사용 문제 해결](문제해결.md)을 참고하세요. 현재 구현과 향후 요구의 구분은 [MVP 명세](../../SPEC.md)에 있습니다.
