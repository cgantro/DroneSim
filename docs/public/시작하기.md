# 실행하고 임무 살펴보기

이 안내는 Windows에서 시뮬레이터를 열고 기본 임무와 통신 장애 조작을 살펴보는 순서입니다. 기능의 전체 구현 상태는 [기능 현황](../../SPEC.md)에서 확인하세요.

## 프로그램 실행

Visual Studio에서 저장소를 열고 CMake 구성 `ninja-release`를 선택합니다. `aerosimlab_simulator` 대상을 빌드해 실행하면 3D 장면과 비행 상태 패널이 나타납니다. 첫 구성에는 의존성 내려받기를 위해 인터넷 연결이 필요할 수 있습니다.

## 화면 살펴보기

- **장면:** 훈련장과 드론 위치를 보여 줍니다.
- **카메라:** 드론별 시점을 표시합니다. 각 영상은 해당 카메라 설정의 가로·세로 비율을 따릅니다.
- **비행 상태:** 모드, 위치, 모의 시간, 임무 진행을 보여 줍니다.
- **통신 사건:** 메시지 전달·중계·폐기와 경로 상태를 보여 줍니다. 최근 사건은 실행 중 최대 64개까지 보관하고 파일로 저장하지 않습니다.

장면이나 카메라 창의 제목을 끌면 위치를 바꿀 수 있고, 창 경계를 끌면 크기를 조절할 수 있습니다. Viewer 시작 시험은 창이 열리는지만 확인하므로 실제 화면 배치와 영상 비율은 프로그램에서 살펴봐야 합니다.

## 게임패드 사용

게임패드를 연결한 뒤 프로그램을 실행합니다.

| 조작 | 동작 |
| --- | --- |
| A 버튼 | 이륙 |
| B 버튼 | 착륙 |
| 왼쪽 스틱 | 앞·뒤·좌·우 이동 |
| 오른쪽 스틱 가로축 | 좌우 회전 |
| 왼쪽·오른쪽 트리거 | 하강·상승 |

Windows에서 `Win + R`을 누르고 `joy.cpl`을 입력하면 운영체제가 게임패드를 인식하는지 확인할 수 있습니다. 처음 조작할 때는 스틱과 트리거를 조금씩 움직여 반응을 살펴보세요.

## 전체 임무 실행

모든 드론이 지상에 있을 때 비행 상태 패널의 **전체 임무 시작 (M01 → M02 → M03)**을 누릅니다. 편대 이동, 지점 분담 정찰, 재집결과 복귀 순서로 진행합니다. 정찰 지점은 사람이 정하며, 드론은 해당 지점의 영상과 위치 정보를 확보합니다. 파손 여부는 사람이 영상으로 판단합니다.

경로 확인 응답이 오지 않으면 60 Tick 간격으로 최대 10회까지 다시 보냅니다. 이 재전송 동작은 통신망 시험으로 확인했습니다. 장애를 주입한 상태에서 GUI 임무가 처음부터 끝까지 복구되는지는 아직 확인하지 않았습니다.

## 통신 장애 조작

편대 이동 또는 전체 임무가 진행 중일 때 **통신 장애 시험** 영역을 사용합니다.

1. **패킷 손실률**을 0보다 높여 일부 메시지를 버립니다.
2. 송신 드론과 상대 드론을 고릅니다.
3. **링크 끊기**로 두 드론 사이 경로를 막거나 **선택 드론 송수신 차단**으로 한 드론의 통신을 멈춥니다.
4. 통신 사건과 경로 정보를 살펴봅니다.
5. **링크 복구** 또는 **선택 드론 라디오 복구**를 누르고 패킷 손실률을 0으로 돌립니다.

이 기능은 거리, 건물 가림, 설정한 지연과 손실을 이용하는 가상 통신입니다. 실제 전파나 무선 장비는 시험하지 않습니다. 장애 중 임무 재배정과 리더 교체도 아직 구현·검증되지 않았습니다.

## 네이티브와 웹의 차이

- Windows 네이티브는 AirSim 강체 물리를 사용합니다.
- 웹은 단순화한 운동학 계산을 사용합니다.
- 두 환경은 서로 다른 비행 계산을 사용하므로 결과를 같은 물리 모델로 비교할 수 없습니다.
