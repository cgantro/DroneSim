# DroneSim 실행과 조작

이 안내는 Windows에서 시뮬레이터를 열고 네 대의 편대 임무와 통신 장애 조작을 살펴보는 순서입니다. 기본 장면은 약 500m × 400m의 가상 산업·자연 복합 훈련장입니다. 실제 지도나 무선 장비를 재현하지 않습니다. 기능의 현재 상태와 시험 결과는 [현재 구현과 시험 상태](../../SPEC.md)에서 확인하세요.

## 프로그램 실행

Visual Studio에서 저장소를 열고 CMake 구성 `ninja-release`를 선택해 시뮬레이터를 빌드한 뒤 실행합니다. 3D 장면과 비행 상태 패널이 나타납니다. 첫 구성에는 의존성 내려받기를 위해 인터넷 연결이 필요할 수 있습니다.

## 화면 살펴보기

- **장면:** 훈련장과 드론 위치를 보여 줍니다.
- **카메라:** 드론별 시점을 표시합니다. 각 영상은 해당 카메라 설정의 가로·세로 비율을 따릅니다.
- **비행 상태:** 모드, 위치, 모의 시간, 임무 진행을 보여 줍니다.
- **통신 상태:** 라우팅 표와 최근 전달된 패킷을 확인할 수 있습니다. 화면에는 최근 사건을 최대 64개까지 표시합니다. 별도로 장애 기록 기능을 사용하면 선택한 장애 조작을 파일로 남길 수 있습니다.

장면이나 카메라 창의 제목을 끌면 위치를 바꿀 수 있고, 창 경계를 끌면 크기를 조절할 수 있습니다. Viewer 시작 시험은 창이 열리는지만 확인하므로 실제 화면 배치와 영상 비율은 프로그램에서 살펴봐야 합니다.

## 게임패드 사용

게임패드를 연결한 뒤 프로그램을 실행합니다.

| 조작 | 동작 |
| --- | --- |
| A 버튼 | 이륙 |
| B 버튼 | 착륙 |
| 왼쪽 스틱 | 앞·뒤·좌·우 이동 |
| 오른쪽 스틱 가로축 | 좌우 회전 |
| 왼쪽·오른쪽 트리거 | 하강·상승 |

Windows에서 `Win + R`을 누르고 `joy.cpl`을 입력하면 운영체제가 게임패드를 인식하는지 확인할 수 있습니다. 처음 조작할 때는 스틱과 트리거를 조금씩 움직여 반응을 살펴보세요.

## 세 단계 임무 실행

모든 드론이 지상에 있을 때 비행 상태 패널의 **전체 임무 시작 (M01 → M02 → M03)**을 누릅니다. M01에서 편대로 이동하고, M02에서 정찰 지점을 나눠 맡은 뒤, M03에서 재집결해 돌아옵니다. 정찰 지점은 사람이 정하며, 드론은 해당 지점의 영상과 위치 정보를 확보합니다. 영상 속 대상의 의미나 파손 여부는 사람이 판단합니다.

경로 확인 응답이 오지 않으면 60 Tick 간격으로 최대 10회까지 다시 보냅니다. Release 자동 시험은 M01 이동, M02 정찰, M03 복귀를 거쳐 네 대가 착륙하는 흐름을 확인했습니다. 이 시험은 자동으로 진행되어 실제 창에서 카메라 영상이나 화면 배치를 사람이 확인한 결과는 아닙니다. 통신 장애를 넣은 전체 임무 흐름도 별도 확인이 필요합니다. 시험 범위는 [현재 구현과 시험 상태](../../SPEC.md)에서 확인하세요.

## 조종 입력과 EO 영상 기록

비행 상태 패널에서 **기록과 다시 보기**를 펼칩니다.

- **조종 입력 기록 시작:** 모든 드론이 지상에 있고 임무가 없을 때 주 드론의 조종 입력을 기록합니다. 기록을 마치면 같은 패널에서 처음부터 재생할 수 있습니다. 이 기록은 현재 실행 중 메모리에만 남으므로 프로그램을 닫으면 사라집니다.
- **EO 영상 녹화 시작:** 카메라가 켜져 있고 자동 임무가 실행 중이 아닐 때 수동 녹화를 시작합니다. 같은 패널에서 녹화를 마칩니다. 정찰 임무가 시작한 자동 녹화는 임무가 직접 마무리합니다.

영상은 저장소 안의 `output/recordings`에 MP4로 저장합니다. 같은 이름의 JSONL 파일에는 촬영 시각과 카메라 정보를, 목록 파일에는 저장 프레임 수와 파일 확인값을 기록합니다. GUI에서 저장된 영상을 지상통제 화면으로 전달하고 확인하는 기능은 아직 연결하지 않았습니다.

## 통신 장애 조작

편대 이동 또는 전체 임무가 진행 중일 때 **통신 장애 시험** 영역을 사용합니다.

임무를 시작하기 전에 통신 방식을 고를 수 있습니다. 비행 상태 패널에서 모든 드론이 지상에 있을 때 선택합니다.

| 방식 | 동작 |
| --- | --- |
| 직접 통신 | 송신 드론과 목적 드론이 서로 직접 연결될 때만 전달합니다. |
| 리더 경유 | 드론 사이 메시지를 현재 리더를 거쳐 전달합니다. 리더와 직접 연결되지 않는 기체에는 닿지 않습니다. |
| 다중 홉 고정 경로 | 여러 드론을 거쳐 처음 찾은 경로를 씁니다. 경로가 끊겨도 자동으로 다른 길을 찾지 않는 비교 기준입니다. |
| 장애 적응 다중 홉 | 링크가 끊기거나 경로가 만료되면 새 경로를 찾아 전달을 이어갑니다. |

각 방식을 비교할 때는 같은 임무와 장애 조작을 사용하고, 전달·중계·폐기 수와 최근 패킷 경로를 함께 살펴보세요. 화면에서 방식별 결과를 자동 집계해 비교하는 기능은 아직 없습니다. 통신 방식은 비행 중 바꿀 수 없습니다. 모든 드론을 지상에 둔 뒤 바꾸면 다음 임무에서 적용됩니다.

1. **패킷 손실률**을 0보다 높여 일부 메시지를 버립니다.
2. **지연 흔들림 상한**을 정합니다. 통신망의 기본 지연에 0부터 설정한 상한까지 Tick 수를 무작위로 더합니다. 시뮬레이션은 60Hz이므로 1 Tick은 약 16.7ms입니다. 0으로 두면 추가 지연이 없습니다.
3. 송신 드론과 상대 드론을 고릅니다.
4. **링크 끊기**로 두 드론 사이 양방향을 막습니다. 한쪽 방향만 시험하려면 `드론 A → 드론 B` 또는 `드론 B → 드론 A` 버튼을 따로 눌러 해당 방향만 차단합니다. **선택 드론 송수신 차단**은 그 드론의 모든 통신을 멈춥니다.
5. 통신 사건과 경로 정보를 살펴봅니다.
6. **링크 복구**, 방향별 `→ 복구`, 또는 **선택 드론 라디오 복구**로 연결을 되살립니다. 시험을 마치면 패킷 손실률과 지연 흔들림 상한을 0으로 돌립니다.

같은 임무에서 장애 조작 순서를 남기려면 **기록과 다시 보기**의 **장애 기록 시작**을 누른 뒤, 패킷 손실률·지연 흔들림·양방향 링크·방향별 링크·라디오를 조작하고 **장애 기록 저장**을 누릅니다. 기록은 프로그램 실행 파일 옆 `output/scenarios/fault-timeline.json`에 저장됩니다. 다시 적용할 때는 기록 당시와 같은 임무 종류와 드론 구성으로 임무를 먼저 시작한 다음 **저장한 장애 다시 적용**을 누릅니다. 저장한 각 조작은 기록된 Tick 간격에 맞춰 적용됩니다.

이 기능은 장애 조작만 저장합니다. 임무 경로와 조종 입력, 시작 상태까지 함께 저장해 임무 전체를 똑같이 재현하지는 않습니다. 프로그램을 닫아도 파일은 남지만, 다른 드론 구성이나 임무 종류에서는 재생할 수 없습니다.

이 기능은 거리, 건물 가림, 설정한 지연과 손실을 이용하는 가상 통신입니다. 실제 전파나 무선 장비는 시험하지 않습니다. 정상 전체 임무 자동 시험은 통과했지만, GUI에서 장애를 조작해 임무 완료·복구·착륙까지 확인하는 흐름은 아직 검증하지 않았습니다.

## 네이티브와 웹의 차이

- Windows 네이티브는 AirSim 강체 물리를 사용합니다.
- 웹은 단순화한 운동학 계산을 사용합니다.
- 두 환경은 서로 다른 비행 계산을 사용하므로 결과를 같은 물리 모델로 비교할 수 없습니다.
