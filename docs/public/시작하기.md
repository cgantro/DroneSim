# AeroSimLab 처음 실행하기

AeroSimLab은 가상 드론을 조종하고 카메라 영상과 지상통제 명령을 시험하는 프로그램입니다.

처음에는 **시뮬레이터를 실행하고 드론을 움직여 본 뒤**, 필요하면 지상통제 프로그램이나 화면 없는 시나리오 시험을 사용하면 됩니다.

## 1. 실행 준비

현재는 설치 프로그램 대신 Visual Studio에서 빌드해 실행합니다. Visual Studio 설치 관리자에서 **C++를 사용한 데스크톱 개발**과 CMake 도구를 선택하세요. 첫 구성에는 필요한 외부 라이브러리를 내려받을 인터넷 연결이 필요합니다. Windows 네이티브 빌드는 OpenCV의 `core`, `imgproc` 구성 요소도 필요하며 CMake가 vcpkg에서 준비하거나 이미 설치된 OpenCV를 찾아야 합니다.

1. Visual Studio에서 프로젝트 폴더를 엽니다.
2. 구성 목록에서 `ninja-release`를 선택하고 CMake 구성이 끝날 때까지 기다립니다. 처음에는 라이브러리를 내려받고 빌드하므로 시간이 걸릴 수 있습니다.
3. 솔루션 탐색기의 보기 목록에서 **CMake Targets View**를 선택합니다. 이 화면에서 실행 항목을 고르고 빌드할 수 있습니다. [Visual Studio에서 CMake 대상을 실행하는 방법](https://learn.microsoft.com/en-us/cpp/build/cmake-projects-in-visual-studio?view=msvc-170)도 참고할 수 있습니다.
4. 실행 대상 목록에서 `aerosimlab_simulator`를 시작 항목으로 지정하고 **F5**를 누릅니다. 장면과 카메라 패널이 있는 시뮬레이터 창이 열립니다.
5. 지상통제 창을 함께 쓰려면 실행 대상을 `aerosimlab_ground_control`로 바꾸고 다시 **F5**를 누릅니다. 먼저 실행한 시뮬레이터는 계속 켜 둡니다.

같은 PC에서는 기본 주소 `127.0.0.1`, UDP 포트 `27015`로 연결됩니다. 다른 PC에서 연결하려면 지상통제 창의 주소에 시뮬레이터 PC의 IPv4 주소를 입력하고 두 PC 사이의 UDP `27015` 통신을 허용해야 합니다.

## 2. 장면과 카메라 패널 보기

- **장면**은 드론과 주변 지형을 보는 화면입니다.
- **카메라**는 드론에 달린 EO 카메라 화면입니다. 현재 해상도는 1280×960이며 패널 크기에 맞출 때도 영상 비율을 유지합니다.
- 패널 제목 줄을 마우스로 끌면 위치를 바꿀 수 있습니다. 패널 가장자리를 끌면 크기를 바꿀 수 있습니다.
- 바꾼 패널 배치는 다음 실행에도 적용됩니다.
- 장면을 보는 카메라 시점은 드론을 따라갑니다. 마우스로 시점을 회전하거나 확대하는 기능은 아직 없습니다.
- 카메라가 꺼져 있거나 고장 상태이면 카메라 패널에 영상이 나오지 않습니다. 지상통제 창에서 켜거나 복구할 수 있습니다.

## 3. 게임패드로 연습하기

표준 게임패드로 인식되는 컨트롤러를 연결한 뒤 시뮬레이터를 실행합니다. 창 제목에 연결 상태가 표시됩니다.

| 입력 | 동작 |
| --- | --- |
| A 버튼 | 이륙 |
| B 버튼 | 착륙 |
| 왼쪽 스틱 | 앞·뒤·좌·우 이동 |
| 오른쪽 스틱 가로축 | 좌우 회전 |
| 왼쪽·오른쪽 트리거 | 하강·상승 |

처음에는 스틱을 조금씩 움직여 반응을 확인하세요. 빠르게 이동하려면 스틱을 더 기울입니다. 지상통제 명령이 들어오면 게임패드 조작은 잠시 중단됩니다.

Windows가 컨트롤러를 찾는지 확인하려면 `Win + R`을 누르고 `joy.cpl`을 실행해 버튼과 스틱 입력을 확인합니다. Windows에서는 움직이지만 시뮬레이터 제목에 게임패드 연결이 표시되지 않으면 GLFW가 해당 장치를 표준 게임패드로 인식하지 못한 것일 수 있습니다. 실제 Xbox 기기별 동작은 아직 확인하지 않았습니다.

### 짧은 연습

1. A를 눌러 이륙합니다.
2. 왼쪽 스틱을 조금씩 움직여 장면의 노란 표식으로 이동합니다.
3. 표식 가까이에서 속도를 줄이고 B를 눌러 착륙합니다.

## 웹에서 조종하기

웹 페이지 아래쪽의 지상통제 막대에서 드론을 조작합니다. 시작 화면이 사라진 뒤 버튼을 누를 수 있습니다.

| 버튼 | 동작 |
| --- | --- |
| 이륙 | 드론을 띄웁니다. |
| 정지 | 수평 이동과 회전을 멈추고 제자리 비행합니다. |
| 전진·후진·좌측·우측 | 누르고 있는 동안 해당 방향으로 이동합니다. |
| 상승·하강 | 누르고 있는 동안 고도를 바꿉니다. |
| 좌회전·우회전 | 누르고 있는 동안 방향을 바꿉니다. |
| 착륙 | 지면으로 내려옵니다. |

지상통제 막대에는 비행 상태, 위치, 속도, EO 카메라 상태와 **OSM 외벽 시험 구역의 촬영 구도 판정**이 표시됩니다. 시험면은 시작 위치에서 가까운 건물의 OSM 외곽 상자로 만든 단순화된 면입니다. 건물 높이는 추정값일 수 있고, 등록된 시설물 점검 구역이나 실제 외벽 형상이 아닙니다. 카메라 거리·방향·화면에 담기는 크기만 판정하며 영상 저장·전송 여부는 확인하지 않습니다. 웹 실행은 네이티브 AirSim 강체 물리와 달리 운동학 모델을 사용하고, 지형·건물 충돌은 계산하지 않습니다.

## 4. 지상통제 창 사용하기

시뮬레이터와 지상통제 창을 함께 실행합니다. 같은 PC에서는 기본 주소 `127.0.0.1`, 포트 `27015`로 연결됩니다. 다른 PC라면 시뮬레이터가 실행 중인 PC의 IPv4 주소와 포트를 입력합니다.

- **이륙**, **정지·호버링**, **착륙** 버튼은 주 드론을 조작합니다.
- 경유점에는 X, Y, 높이를 미터로 입력합니다. 모의 좌표에서 X는 동쪽, Y는 북쪽, Z는 위쪽입니다.
- 카메라 버튼으로 영상을 켜거나 끄고 고장 상태를 만들거나 복구합니다.
- 카메라가 켜져 있으면 **영상 녹화 시작**과 **영상 녹화 종료** 버튼으로 EO 영상을 저장할 수 있습니다. 녹화 중에는 입력 기록 재생을 시작할 수 없습니다.
- 녹화 결과는 `%LOCALAPPDATA%\DroneSim\recordings` 폴더에 H.264 MP4 영상, 프레임별 JSONL 정보, 저장 목록 파일로 저장됩니다. JSONL에는 모의 시간과 카메라 위치·자세가 기록됩니다. 저장 목록은 녹화를 끝내고 파일을 닫은 뒤 만들어지며, 파일 크기·저장 프레임 수·CRC-32 체크섬을 담습니다. 점검 구역 ID와 지상 전달 상태는 아직 연결되지 않았습니다.
- 화면 아래에서 주 드론의 상태와 위치, 카메라 프레임 수를 확인할 수 있습니다. 연결 상태는 약 0.25초마다 갱신됩니다.
- **드론 추가**를 누르면 주 드론 근처 지면에 새 드론이 생깁니다. 정해진 자리가 지도 밖이면 요청이 거절됩니다. 최대 8대까지 상태를 볼 수 있지만 추가 드론을 따로 조종하거나 임무를 지정할 수는 없습니다.
- 입력 기록은 드론이 지상에 있을 때 시작할 수 있습니다. 기록을 끝내면 현재 실행 중에 재생할 수 있으며 재생을 시작하면 시뮬레이션을 처음 상태로 되돌린 뒤 기록된 입력을 적용합니다. 기록은 메모리에만 보관되므로 프로그램을 닫으면 사라집니다.

## 5. 화면 없이 시나리오 시험하기

`aerosimlab_headless`는 화면 없이 JSON 시나리오를 한 번 실행합니다. Visual Studio의 실행 대상 목록에서 이 대상을 고른 다음, **Debug > Debug and Launch Settings**를 열어 `args` 항목에 아래 값을 넣습니다. `<프로젝트 폴더 경로>`와 `<시나리오>`는 실제 위치와 고른 시나리오 이름으로 바꿉니다.

```json
"args": [
  "--scenario",
  "<프로젝트 폴더 경로>\\scenarios\\flight\\<시나리오>.json"
]
```

시나리오 자료는 프로젝트 안의 `scenarios` 폴더에 있습니다. 실행 결과는 콘솔에 JSON으로 표시됩니다.

- `outcome`은 `passed`, `failed`, `inconclusive` 중 하나입니다. `passed`는 기대 결과를 만족했고 모든 임무도 끝났다는 뜻입니다.
- `failed`는 명령 거부, 기대 결과 불일치, 임무 기한 초과처럼 확인된 실패입니다. 자세한 이유는 `issues`에서 봅니다.
- `inconclusive`는 통신 단절 등으로 임무 완료 여부를 확인하지 못한 상태입니다. 성공도 실패도 확정하지 않았으며, `passed` 값은 `false`입니다.
- `mission.outcome`은 공동 임무 자체의 결과를 나타냅니다. 드론이 구역을 맡았다는 사실과 실제 구역을 끝냈다는 사실은 별도로 기록됩니다.
- 실행 인수나 JSON을 읽지 못하면 오류가 표시됩니다.
- 공동 임무 결과에서는 완료 비율, 경유점 기준 조사 진행률, 시작·완료 Tick과 임무에 걸린 시간을 확인할 수 있습니다. 배터리 모델을 켰다면 드론별 사용량과 남은 비율도 표시됩니다.

### 여러 드론에 조사 구역 나누기

시나리오의 `mission`에 점 목표 목록 대신 `survey_area`를 넣으면 직사각형 구역을 드론 수만큼 같은 폭으로 나누고, 각 구역에 왕복 경로를 만듭니다. 드론 목록의 순서가 왼쪽 구역부터 배정되는 순서입니다. 좌표는 미터 단위의 월드 X·Y축이며, 고도는 지면 기준이 아닌 월드 Z값입니다.

```json
"mission": {
  "name": "field-survey",
  "survey_area": {
    "name": "field",
    "bounds_meters": [0, 0, 40, 24],
    "altitude_meters": 15,
    "lane_spacing_meters": 6,
    "start_tick": 90,
    "deadline_tick": 900,
    "tolerance_meters": 1
  }
}
```

`bounds_meters`는 `[최소 X, 최소 Y, 최대 X, 최대 Y]`입니다. 띠 간격이 좁을수록 경로와 목표 지점이 늘어납니다. 이 기본 경로는 평면 구역을 나눕니다. 건물·지형 회피와 배터리·비행시간에 따른 구역 조정은 하지 않습니다.

`start_tick`은 임무를 시작할 수 있는 가장 이른 시점입니다. 드론이 이륙 중이면 임무 기한 안에서 비행 가능한 상태가 될 때까지 기다립니다. 기한까지 이륙하지 못하면 임무를 실패로 기록합니다.

통신을 끊을 때는 다음처럼 하트비트 제한과 시간 초과 뒤 동작을 지정할 수 있습니다.

```json
"communication_outages": [
  {
    "drone": "scout-2",
    "start_tick": 95,
    "end_tick": 320,
    "heartbeat_timeout_ticks": 3,
    "on_timeout": "hold_position"
  }
]
```

`on_timeout`을 생략하면 `continue_last_command`를 사용합니다. `hold_position`은 시간 초과 뒤 위치 명령을 받을 수 있게 되면 그 위치를 유지합니다. 이 설정은 시나리오 안에서 통신 장애를 재현하며, 실제 비행제어기의 링크 상실 기능과는 별개입니다.

두 드론이 서로 향하는 경로를 시험하려면 시나리오 최상위에 아래 설정을 더할 수 있습니다. 예상 안전거리는 현재 위치와 속도를 직선으로 연장해 계산하며, 위험하면 한 드론의 임무 경유점을 옆으로 옮깁니다.

```json
"collision_avoidance": {
  "safety_distance_meters": 3,
  "prediction_horizon_seconds": 2,
    "lateral_offset_meters": 10
}
```

연결된 드론은 현재 속도로 계속 움직이고, 통신이 끊긴 드론은 마지막 확인 위치에 멈춘 장애물로 계산합니다. 위험이 사라질 때까지 회피 목표를 현재 위치 기준으로 유지합니다. 경로를 조정하는 대상은 조사 중인 드론입니다. 기체 크기·가속·회전·바람·주변 장애물은 예측하지 않으므로 실제 충돌 방지 기능으로 사용할 수 없습니다.

배터리 예비량에 따라 임무를 넘기고 착륙하는 시험은 `energy_model`을 추가해 켭니다. 전력은 모터에서 계산하지 않고 비행 상태별 고정값으로 사용합니다.

```json
"energy_model": {
  "capacity_watt_hours": 1,
  "hover_power_watts": 40,
  "flight_power_watts": 120,
  "reserve_percent": 20
}
```

드론 항목에 `battery_capacity_watt_hours`와 `initial_battery_percent`를 지정하면 기체별 용량과 시작 잔량을 다르게 설정할 수 있습니다. 예비량에 도달한 드론은 새 임무를 받지 않고 착륙하며, 미완료 구역은 다른 드론이 이어받습니다. 이 설정은 임무 전환을 비교하는 용도입니다. 실제 배터리 성능이나 비행시간을 계산하지 않습니다.

AirSim 강체 시험에서 기체 물성을 바꾸려면 시나리오 최상위에 `quadrotor_model`을 추가합니다. 적지 않은 값은 현재 X500 기준값을 그대로 씁니다.

```json
"quadrotor_model": {
  "mass_kg": 2.5,
  "principal_inertia_kg_m2": [0.03, 0.031, 0.05],
  "thrust_coefficient_newtons_per_speed_squared": 0.000011,
  "moment_to_thrust_ratio": 0.015,
  "motor_time_constant_up_seconds": 0.02,
  "motor_time_constant_down_seconds": 0.025,
  "maximum_motor_speed_radians_per_second": 900
}
```

질량은 kg, 각 축 관성은 kg·m², 추력 계수는 N/(rad/s)², 모터 시간은 초 단위입니다. 이 설정은 `rigid_body` 실행에서만 적용됩니다. 실행 결과의 `physical_model` 항목에는 실제 사용한 값이 함께 기록돼, 두 시나리오의 입력 조건을 비교할 수 있습니다. 상승 시간은 목표 속도가 커질 때, 하강 시간은 목표 속도가 작아질 때 적용합니다.

일정한 바람을 비교하려면 `wind_velocity_meters_per_second`를 시나리오 최상위에 지정합니다. 세 값은 동·북·위(ENU) 방향의 속도(m/s)이며, 생략하면 바람이 없습니다.

```json
"wind_velocity_meters_per_second": [2.0, 0.0, 0.0]
```

이 설정은 일정한 바람만 적용합니다. 돌풍과 높이에 따른 변화는 없으며, 항력 계수도 X500 실측값으로 맞추지 않았습니다. 실행 결과의 `wind_velocity_meters_per_second` 항목에 적용한 바람이 기록됩니다.

같은 기체에서 제어기 반응을 비교하려면 `controller_gains`를 추가합니다. 일부 값만 적으면 나머지는 기본값을 사용합니다.

```json
"controller_gains": {
  "position": 3.0,
  "velocity": 2.5,
  "attitude": 20.0,
  "angular_rate": 7.0
}
```

위 기본값에서 위치·자세 이득의 단위는 1/s², 속도·각속도 이득은 1/s입니다. 위치 이득을 높이면 목표 위치 쪽으로 더 빠르게 가속하고, 속도 이득을 높이면 현재 속도 오차에 더 강하게 반응합니다. 자세와 각속도 이득은 기체의 기울기와 회전 속도를 조절합니다. 네 값은 모두 양수여야 하고, `rigid_body` 실행에서만 사용할 수 있습니다. 결과의 `controller_gains` 항목에서 시나리오에 적힌 값과 기본값 사용 여부를 확인할 수 있습니다.

이 시험은 지정한 가상 조건에서 기능 동작을 확인합니다. 실제 기체의 비행 성능을 확인하는 시험은 아닙니다.

모의 비행을 시간에 따라 비교하려면 시나리오에 궤적 기록을 켭니다.

```json
"record_trajectory": {"sample_every_ticks": 10}
```

예시는 10 Tick마다 상태를 저장합니다. 시작 상태와 마지막 상태도 포함합니다. 실행 결과의 `trajectory`에는 Tick, 모의 시간, 각 드론의 위치·속도·자세·각속도와 로터 속도가 들어갑니다. 위치는 시뮬레이터 월드 좌표(m), 시간은 시뮬레이션 시작 기준 초이며, Tick 간격은 1/60초입니다. 샘플 간격을 생략하면 매 Tick 기록합니다. 기록량은 드론별 상태 10만 개까지 허용하므로, 장시간 시험에서는 간격을 늘려야 합니다.

강체 시나리오는 시작 위치·속도·자세·각속도와 로터 추력 입력도 지정할 수 있습니다. 시뮬레이터가 원본 PX4 ULog를 직접 읽지는 않지만, 별도 변환 도구로 X500 4개 로터의 추력 명령과 참조 상태를 시나리오 자료로 만들 수 있습니다. 현재 도구는 특정 PX4 주제와 정규화 추력 명령을 전제로 합니다. 좌표 변환, 비교 결과와 제한은 [비행 계산과 실제 기록 비교](기술검토.md#시험-후보-x500-v2의-position-비행-기록)에 정리했습니다.

## 6. 물리와 지형에서 알아둘 점

- Windows 네이티브 강체 모의는 AirSim으로 로터 힘, 모터 반응, 기체 운동과 충돌 뒤 반응을 계산합니다.
- 화면 없는 시나리오에서 운동학 방식을 고르면 단순한 기준 모델을 사용합니다. 이 방식은 모터와 관성, 추력을 계산하지 않습니다.
- 웹 실행도 운동학 기준 모델을 사용합니다.
- 화면에는 탄천교 주변의 약 1.2km 구역을 30m 간격으로 나타낸 지형이 표시됩니다. 건물·도로·교량 모양은 아직 들어 있지 않습니다.
- 네이티브 강체 물리는 같은 지형 격자를 지면으로 사용합니다. 웹은 화면에만 지형을 그리고, 웹의 운동학 모의에서는 지면 충돌을 계산하지 않습니다.
- 물리 계수는 공개 자료를 참고했지만 실제 비행 기록과 대조하지 않았습니다.
