# AeroSimLab 처음 실행하고 조작하기

AeroSimLab은 가상 드론의 움직임, 만들어진 카메라 화면, 지상통제 명령을 시험하는 프로그램입니다. 실제 드론·조종기·카메라를 제어하거나 실제 비행 안전성을 보증하지 않습니다.

## Windows에서 빌드

필요한 도구는 C++20을 지원하는 CMake, Ninja, Visual Studio C++ 빌드 도구, vcpkg입니다. `VCPKG_ROOT` 환경 변수는 vcpkg 최상위 폴더를 가리켜야 합니다. 처음 구성할 때는 의존성 설치를 위해 네트워크가 필요할 수 있습니다.

저장소 폴더에서 PowerShell을 열고 다음 순서로 실행합니다.

```powershell
cmake --preset ninja-release
cmake --build --preset ninja-release
```

그래픽 시뮬레이터는 `build-ninja-release/aerosimlab_simulator.exe`입니다. 시뮬레이터는 실행 위치에서 셰이더 등 화면 자원을 찾으므로 빌드 출력 폴더에서 실행합니다.

```powershell
Set-Location build-ninja-release
./aerosimlab_simulator.exe
```

도움말은 `./aerosimlab_simulator.exe --help`로 확인합니다. 그래픽 실행 옵션은 `--demo`(자동 시연), `--smoke-test`(자동 화면 시작 확인), `--benchmark`(5초 측정), `--udp-port <포트>`입니다. 기본 UDP 포트는 `27015`입니다. `--smoke-test`와 `--benchmark`는 일반 사용 모드가 아니라 확인·측정 모드입니다.

## 화면과 조작

창 왼쪽은 장면을 바라보는 관찰자 시점이고, 오른쪽은 기체 앞쪽에 고정된 EO 카메라 시점입니다. 지원되는 게임패드가 감지되면 다음 입력을 사용할 수 있습니다.

| 입력 | 동작 |
| --- | --- |
| A 버튼 | 이륙 |
| B 버튼 | 착륙 |
| 왼쪽 스틱 | 앞·뒤·좌·우 이동 |
| 오른쪽 스틱 가로축 | 방향 회전 |
| 왼쪽·오른쪽 트리거 | 높이 낮추기·높이 올리기 |

장치별 입력 배치가 다를 수 있고 모든 Xbox 호환 기기 조합을 검증한 것은 아닙니다. 게임패드 조작과 지상통제 명령을 동시에 사용하지 마세요.

## 지상통제 명령 보내기

시뮬레이터와 지상통제 프로그램을 함께 실행합니다. Windows 빌드에서 명령 줄 버전은 `aerosimlab_ground_control_cli.exe`입니다. 포트를 바꾸지 않았다면 대상 주소는 `127.0.0.1`, 포트는 `27015`입니다.

창으로 조작하려면 `aerosimlab_ground_control.exe`를 실행하고 Host와 Port를 확인합니다. 창에는 이륙·정지·착륙, 좌표를 입력하는 경유점, 카메라 켜기·끄기·장애 주입·복구, 게임 입력 기록 시작·정지·재생 버튼이 있습니다. 입력 기록은 시뮬레이터가 실행 중인 동안 메모리에 보관되며 파일로 저장되지 않습니다.

```powershell
./aerosimlab_ground_control_cli.exe --help
./aerosimlab_ground_control_cli.exe --command takeoff
./aerosimlab_ground_control_cli.exe --command waypoint 3 0 1.5
./aerosimlab_ground_control_cli.exe --command land
./aerosimlab_ground_control_cli.exe --camera fault
./aerosimlab_ground_control_cli.exe --camera recover
```

다른 주소나 포트는 `--host IPv4`, `--port 번호`로 지정합니다. 가능한 비행 명령은 `takeoff`, `land`, `stop`, `velocity x y z`, `waypoint x y z`, `yaw-rate 값`입니다. 좌표와 속도는 미터·초 기준이고 회전 속도는 rad/s입니다. 속도 벡터 크기는 최대 5m/s, Yaw 회전 속도는 최대 1.5rad/s로 제한됩니다.

응답에는 접수 여부, 적용 Tick, 드론 상태와 카메라 메타데이터가 표시됩니다. 지상통제 프로그램은 기본 4초 동안 응답을 기다리고 재전송할 수 있습니다. UDP는 명령 전달을 보증하지 않으므로 timeout 뒤에는 상태를 확인하세요.

## JSON 시나리오 실행

화면 없이 정상 비행 시나리오를 실행하려면 빌드 출력 폴더에서 다음을 실행합니다.

```powershell
./aerosimlab_headless.exe --scenario ../scenarios/flight/normal-flight.json
./aerosimlab_headless.exe --scenario ../scenarios/fault-injection/fault-injection.json
```

프로그램은 판정 JSON을 출력합니다. `passed: true`와 종료 코드 `0`은 통과, 종료 코드 `1`은 실행 후 기대값과 맞지 않음, `2`는 파일·형식·명령 사용 오류입니다. 결과의 `issues`와 `events`를 확인해 판정 이유를 살펴보세요.

시나리오는 고정 초기 상태(원점, 지상, Yaw 0)에서 시작합니다. 명령과 카메라 이벤트는 JSON에 지정한 Tick 순서로 처리됩니다. 초기 위치 입력과 다중 드론 시나리오는 현재 지원하지 않습니다.

## 무엇을 모의하고 무엇을 모의하지 않나

- 모의 Tick은 60Hz 고정 간격으로 진행합니다. 화면 그리기 주기와 별개입니다.
- 현재 드론은 위치·속도 기반의 단순 운동 모델입니다. 가속도·관성·모터·추력·바람·공기 저항·기체 기울기는 계산하지 않습니다.
- 카메라 영상은 화면 장면에서 생성하는 RGB 픽셀입니다. 밝기·대비·선명도는 단순 요약값이지 실제 광학 품질 판정이 아닙니다.
- 현재 지도는 단순한 3D 장면이며 실제 지형·시설 지도, 장애물·가시성 분석은 없습니다.
- 실제 EO 영상 입력, 지상통제 영상 전송, AI 영상 분석, 다중 드론 협동, 실제 비행 성능·안전성 검증은 범위 밖입니다.

실행 오류는 [사용 문제 해결](문제해결.md)을 참고하세요. 현재 구현과 향후 요구의 구분은 [MVP 명세](../../SPEC.md)에 있습니다.
