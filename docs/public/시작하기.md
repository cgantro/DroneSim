# 실행하고 기본 조작하기

이 안내는 Windows Release 빌드에서 시뮬레이터를 실행하는 순서입니다. 첫 구성에는 인터넷 연결이 필요할 수 있습니다. 현재 훈련장은 실제 도시 지도가 아니라 산업시설과 자연물 에셋으로 구성한 가상 공간입니다.

## 실행

1. Visual Studio에서 저장소 폴더를 엽니다.
2. CMake 구성에서 `ninja-release`를 고릅니다.
3. `aerosimlab_simulator` 대상을 빌드하고 실행합니다.
4. 장면과 비행 상태가 표시되는지 확인합니다.

## 화면

- **장면:** 훈련장과 드론을 보여 줍니다.
- **카메라:** 주 드론에 설정된 EO 카메라 화면을 보여 줍니다.
- **비행 상태:** 비행 모드, 위치, 모의 시간, 임무 상태를 보여 줍니다.
- **통신 사건:** 메시지 전달·중계·폐기 수와 최근 통신 사건을 보여 줍니다. 최근 사건은 실행 중 메모리에 남고 파일로 저장되지는 않습니다.

패널 제목을 끌어 옮기고 패널 사이 경계를 움직여 크기를 바꿀 수 있습니다. 현재 자동 화면 시험은 프로그램이 시작되는지 확인하며, 패널을 옮기거나 링크 장애를 눌러 보는 수동 확인은 포함하지 않았습니다.

## 직접 조종

게임패드를 연결한 뒤 실행합니다.

| 입력 | 동작 |
| --- | --- |
| A 버튼 | 이륙 |
| B 버튼 | 착륙 |
| 왼쪽 스틱 | 앞·뒤·좌·우 이동 |
| 오른쪽 스틱 가로축 | 좌우 회전 |
| 왼쪽·오른쪽 트리거 | 하강·상승 |

처음에는 스틱을 조금씩 움직여 기체 반응을 확인하세요. Windows에서 장치를 확인하려면 `Win + R`을 누르고 `joy.cpl`을 입력합니다.

## 편대와 링크 장애 시험

1. 비행 상태 패널에서 V자·일렬·횡대 중 하나를 고릅니다.
2. **편대 이동 시작**을 누릅니다. 모든 드론이 지상에 있을 때 시작할 수 있습니다.
3. 편대가 움직이면 **송신 드론**과 **상대 드론**을 고릅니다.
4. **링크 끊기**를 눌러 연결을 끊고, 최근 사건에서 경로 탐색과 메시지 전달·폐기를 살펴봅니다.
5. **링크 복구**를 눌러 연결을 되살립니다.

이 기능은 드론 사이의 가상 통신 링크를 시험합니다. 실제 무선 장비를 끄거나 전파 상태를 재현하지 않습니다. 통신 모델과 남은 기능은 [기능 현황](../../SPEC.md), 작동 방식과 제한은 [기술 구조](기술구조.md)에서 확인할 수 있습니다.

## 여러 드론 정찰

모든 드론이 지상에 있고 다른 임무가 없으면 비행 상태 패널에서 **여러 드론 정찰 시작**을 누릅니다. 시뮬레이터는 훈련장에 등록된 정찰 지점을 드론 순서대로 나눠 주고, 각 기체가 맡은 지점으로 이동한 뒤 착륙합니다. 패널에는 드론별 목표와 진행 상태가 표시됩니다.

현재 이 기능은 목표 방문과 착륙까지 확인합니다. 각 드론의 카메라 영상을 따로 저장·전달하거나, 목표를 다시 나누는 기능은 아직 없습니다.

모든 드론이 정찰을 마치고 착륙하면 **출발 지점으로 복귀**를 눌러 각 기체를 처음 출발한 자리로 보낼 수 있습니다. 복귀 경로를 찾지 못하면 임무를 시작하지 않습니다. 현재는 한곳에 모이는 공통 집결 단계가 없고, 편대 이동·정찰·복귀도 사용자가 각각 시작해야 합니다.

## 알아둘 점

- 네이티브 Windows 실행은 AirSim 강체 물리를 사용합니다. 웹 실행은 단순화한 운동학 계산을 사용하므로 비행 결과가 같지 않습니다.
- 현재 편대 목표는 가상 통신망으로 전달됩니다. 기체 고장, 패킷 손실·지연 주입, 장애 뒤 임무 자동 재배정은 아직 GUI에서 조작할 수 없습니다.
- 정찰은 사람이 정한 시험 지점을 방문하는 기존 시연입니다. 영상만으로 파손을 판정하거나 새 점검 지점을 찾지 않습니다.
