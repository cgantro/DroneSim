# 실행하고 조작하기

이 안내는 Windows에서 시뮬레이터를 빌드하고, 편대·정찰·통신 기능을 확인하는 순서를 설명합니다.

## 빌드하고 실행하기

1. Visual Studio에서 저장소를 엽니다.
2. CMake 구성으로 `ninja-release`를 선택합니다.
3. `aerosimlab_simulator` 대상을 빌드하고 실행합니다.
4. 장면, 비행 상태, 카메라 패널이 표시되는지 확인합니다.

첫 구성에는 라이브러리를 내려받기 위한 인터넷 연결이 필요할 수 있습니다.

## 화면에서 볼 수 있는 정보

- **장면:** 훈련장과 드론의 위치를 보여 줍니다.
- **카메라:** 드론별 EO 시점을 2열 격자로 보여 줍니다. 각 화면은 해당 카메라 모델의 해상도와 비율을 사용합니다.
- **비행 상태:** 비행 모드, 위치, 모의 시간, 임무 진행을 보여 줍니다.
- **통신 사건:** 최근 메시지 중계·전달과 경로 상태를 보여 줍니다. 실행 중 최근 사건 64개를 보관하며 파일로 저장하지 않습니다.

장면과 카메라 패널은 제목을 끌어 옮기거나 경계를 끌어 크기를 바꿀 수 있습니다. Viewer 스모크 시험은 프로그램 시작만 확인하므로 패널 배치와 실제 조작은 직접 확인해야 합니다.

현재 영상 녹화와 품질 분석은 주 드론 카메라에서만 수행합니다. 다른 드론의 화면은 관찰용이며, 개별 영상 녹화·전송은 아직 지원하지 않습니다.

## 게임패드로 조종하기

게임패드를 연결한 다음 실행합니다.

| 입력 | 동작 |
| --- | --- |
| A 버튼 | 이륙 |
| B 버튼 | 착륙 |
| 왼쪽 스틱 | 앞·뒤·좌·우 이동 |
| 오른쪽 스틱 가로축 | 좌우 회전 |
| 왼쪽·오른쪽 트리거 | 하강·상승 |

Windows에서 게임패드 인식 여부는 `Win + R`을 누르고 `joy.cpl`을 실행해 확인할 수 있습니다. 처음에는 스틱과 트리거를 작게 움직여 기체 반응을 살펴보세요.

## 편대 이동과 링크 장애 확인하기

1. 비행 상태 패널에서 V자·일렬·횡대 중 대형을 고릅니다.
2. 모든 드론이 지상에 있을 때 **편대 이동 시작**을 누릅니다.
3. 이동 중 통신 장애 설정에서 송신 드론과 상대 드론을 고른 뒤 **링크 끊기**를 누릅니다.
4. 통신 사건에서 경로 탐색과 메시지 전달이 바뀌는지 확인합니다.
5. **패킷 손실률**을 0%보다 높여 메시지 폐기를 발생시킵니다. 전달·중계·폐기 횟수와 통신 사건이 달라지는지 확인합니다.
6. **링크 복구**를 눌러 연결을 되돌리고, 패킷 손실률을 0%로 돌립니다.

이 기능은 거리, 건물 가림, 설정한 지연·손실을 사용하는 가상 통신 시험입니다. 패킷 손실률은 임무 중 바꿀 수 있으며, 모든 종류의 가상 통신 패킷에 적용됩니다. 손실 뒤 임무 명령을 다시 보내는 기능은 아직 없습니다. 실제 무선 장비나 전파 환경을 시험하지 않습니다.

## 정찰과 복귀 실행하기

**여러 드론 정찰 시작**은 미리 정한 지점을 드론에 나누고, 리더가 각 추종 드론에 경로 메시지를 전달하도록 연결되어 있습니다. 추종 드론은 메시지를 받기 전에는 경로를 따라가지 않습니다. 경로 메시지가 600 Tick 안에 도착하지 않으면 오류로 표시됩니다. 현재 임무 수준의 확인 응답과 재전송은 구현되지 않았습니다.

**전체 임무 시작 (M01 → M02 → M03)**을 누르면 편대 이동, 분산 정찰, 재집결과 복귀를 순서대로 진행하도록 연결되어 있습니다. 코드와 빌드는 확인했지만, 실제 창에서 처음부터 끝까지 수행하는 과정은 아직 검증하지 않았습니다. 기능별 상태와 시험 범위는 [기능 현황](../../SPEC.md)을 확인하세요.

정찰은 사람이 지정한 지점을 방문하는 과정입니다. 드론은 영상과 위치 정보를 확보하고, 파손 여부는 사람이 영상으로 판단합니다. 정찰 자료를 임무별로 저장·전달하는 기능은 아직 전체 경로에 연결되지 않았습니다.

## 실행 환경의 차이

- Windows 네이티브는 AirSim 강체 물리를 사용합니다.
- 웹은 단순화한 운동학 계산을 사용합니다.
- 두 환경은 비행 결과를 같은 물리 모델로 재현하지 않습니다.
- 가상 통신망은 실제 무선 전파, 안테나, 장비 성능을 계산하지 않습니다.

프로젝트 목적은 [개발 목표](../../GOAL.md), 내부 흐름은 [기술 구조](기술구조.md)에서 볼 수 있습니다.
