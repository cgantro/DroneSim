# 픽앤플레이스 반복 실행

반복 실행 모드는 화면을 그리지 않고도 실제 시뮬레이터의 작업 흐름을 여러 번 확인할 때 쓴다. 가짜 제어기만 쓰는 단위 검사와 달리 Viewer가 조립하는 임무, 로봇 제어, Jolt 물리, 충돌 검사와 그리퍼가 함께 동작한다.

실행 파일이 있는 폴더에서 횟수와 난수 seed를 지정한다.

```powershell
.\grasplink_simulator.exe --pick-place-stress 100 --seed 1
```

현재 무작위로 바꾸는 값은 상자와 놓을 위치의 좌표, 그리고 두 물체의 수평 회전이다. 위치는 로봇 작업 반경 안에서 고른다. 로봇의 시작 관절각과 주변 장애물 배치는 바꾸지 않는다. 그러므로 이 실행은 여러 집기·놓기 위치에서 임무가 이어지는지 확인하지만, 임의의 장애물 배치나 모든 시작 자세에 대한 검증은 아니다.

seed와 같은 실행 파일을 사용하면 같은 순서의 조건을 다시 만들 수 있다. 실패한 사례는 기본으로 `pick_place_failures.jsonl`에 한 줄씩 추가한다. 다른 파일에 기록하려면 `--failure-log 경로`를 지정한다. 기록에는 seed, 실패 순번, 상자와 목표의 전체 위치·방향, 시작 관절각, 실패 메시지, 실행 시간과 반복 횟수가 들어간다. JSON Lines 형식이라 파일을 지우지 않고 여러 실행 결과를 이어 쓸 수 있다.

저장한 조건은 같은 빌드와 seed로 다시 실행해 실패 순번까지 진행하면 재현할 수 있다. 장면 구성이나 난수 생성 코드가 바뀌면 같은 seed가 같은 조건을 만든다고 보장할 수 없으므로, 비교할 때 실행 파일 또는 소스 변경도 함께 기록한다. 저장된 위치와 방향은 당시 조건을 확인하고 별도 재현 도구를 만드는 데 쓸 수 있지만, 현재 실행 파일에는 기록 한 줄을 직접 불러오는 재생 기능은 없다.

각 시도는 성공, 실패, 시간 초과 중 하나로 집계한다. 시간 초과는 한 시나리오에서 고정 tick 100,000회를 진행해도 임무가 끝나지 않은 경우다. 모든 시도가 성공하면 종료 코드는 `0`, 임무 실패나 시간 초과가 있으면 `1`, 초기화·복구 또는 실패 기록 저장에 문제가 있으면 `2`다. 자동화에서는 종료 코드와 마지막 요약을 함께 확인한다.

실행 시간은 빌드 종류, 컴퓨터, 창 표시 여부와 실행 환경에 따라 달라진다. 이 모드는 임무 실패를 찾는 데 쓰며, 장비가 정해진 주기로 반응한다거나 실제 로봇에서 안전하다는 증거로 사용하지 않는다.
