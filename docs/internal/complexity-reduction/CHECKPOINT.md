- 다음에는 앱 임무와 JSON Runner가 각각 어떤 M01–M03 동작을 수행하는지 다시 대조하고, 실제 중복 동작을 확인한 뒤에만 공통 규칙을 정한다. Runner와 앱의 임무 코드는 서로 다른 실행 경로다.

## 시나리오 실행 경로 재검토 — 2026-10-29

- 현재 시나리오 JSON은 리더 추종 링크 사례를 제거해 8개다. CMake headless 연기 시험 4개 외에 물성 덮어쓰기·4대 조사 장애·저배터리 자료는 GoogleTest fixture로도 읽힌다. `normal-flight.json`은 코드 검색에서 참조를 찾지 못했다.
- `ScenarioDefinition.cpp`는 JSON을 검증해 실행 설정을 만들고, `ScenarioRunner.cpp`는 Tick 실행·임무·통신 장애·배터리·카메라·결과 판정을 함께 수행한다. 둘은 파일이 나뉘어 있어도 실행기 책임이 넓다.
- `RunScenario`는 headless와 시나리오 시험에서 호출된다. 시뮬레이터 앱은 별도 M01–M03 임무와 가상 통신 경로를 사용한다. 동작이 다르므로 지금 공통 엔진으로 합치지 않는다.
- 시나리오 테스트 파일에는 GoogleTest `TEST`가 `CoreScenarios` 하나뿐이다. 여러 검증 함수를 한 테스트에서 순차 실행해 실패한 영역을 바로 구분하기 어렵다.
- `formation_links`의 leader 추종·단절 모형, parser/runtime 코드와 전용 fixture·연기 시험을 제거했다. 직접 통신 장애 모델과 V자 편대 계획은 유지했다.
- Release `aerosimlab_headless` 및 `aerosimlab_scenario_tests` 빌드 성공. 최신 전체 CTest 28/28 통과.
- 이번 사실 수집은 Sol이 직접 했으며, 사용자 지정 Luna 수집자는 세션 작업자 한도 때문에 시작하지 못했다.

## 임무 시작 조건 통합 — 2026-10-29

- 개별 정찰과 전체 임무가 진행 중인 단계, 정찰 지점 유무, 지상 상태를 각각 검사하던 코드를 `FleetIsReadyForMission`에 모았다. 전체 임무의 네 대 조건은 별도로 유지한다.
- 전체 임무가 개별 정찰 중 시작될 수 없도록 공통 조건에서 진행 중인 정찰도 확인한다. 복귀 가능 여부에서는 전체 임무의 진행 단계를 따로 다시 나열하던 검사를 제거하고 기존 `CompleteFleetMissionIsActive`만 사용한다.
- 기존 임무 시작 시험에 진행 중 정찰 상태를 둔 경우 새 정찰과 전체 임무가 모두 막히는 확인을 추가했다. Release 전체 빌드와 CTest 29/29 통과.

## Flecs 컴포넌트 사용 구조 확인 — 2026-10-29

- 드론별 `DroneState`, `DroneControlState`, `CameraState`, 선택형 `BatteryModel`은 Flecs 엔티티에 붙는 실제 컴포넌트다. `PhysicsBody`도 강체 모드에서만 붙인다. 새 동작을 추가할 때는 상태를 나타내는 구조체를 필요한 엔티티에 붙이고, 시스템이 필요한 컴포넌트 조합을 조회해 계산하는 방식이 맞다. 모든 객체를 컴포넌트로 만들 필요는 없다.
- 현재 훈련장 장면은 `TrainingRangeScene`과 앱 렌더러가 관리하고, 고정 장애물·지형은 Simulation Core가 저장한다. 정적 환경을 Flecs 엔티티로 옮기면 현재 목표의 단순화에 도움이 되지 않으므로 유지한다.
- `DroneIds()`는 맵의 키만 복사하면 되는데 사용하지 않는 엔티티 값까지 구조화 바인딩하고 버렸다. 키만 읽도록 단순화했다. Release 전체 빌드와 CTest 29/29 통과.

## 직접 통신 검사의 노드 조회 중복 제거 — 2026-10-29

- 기존 가상 통신 시험에 없는 노드 ID로 좌표 교환 가능성을 물어 계약을 확인하는 검사를 추가했다.

## 카메라 목록에서 장면 시점 바꾸기 — 2026-10-29

- 장면 패널에는 이미 시점 드론 선택 메뉴가 있었지만, 카메라 패널의 영상과 기체 시점이 연결되어 보이지 않았다. 각 영상의 드론 이름도 선택할 수 있게 하고 현재 시점 기체를 `>`로 표시했다.
- 선택된 ID는 기존 추적 카메라가 사용한다. 카메라 추적 계산이나 드론별 영상 생성 방식은 새로 만들지 않았다.
- Windows Release 전체 빌드 성공, CTest 29/29 통과. 실제 마우스 조작은 이번 검증에서 직접 확인하지 않았다.

## 드론 ID 순서 관리 통합 — 2026-10-29

## 자동 임무 재배정 제거 — 2026-10-29

- 각 작업은 시나리오에서 지정한 드론에 고정된다. 통신이 끊기면 해당 드론은 받은 경로를 계속 따라가고, 관제와 시나리오에는 마지막 수신 상태와 미확정 작업을 남긴다. 다른 드론으로 자동 이동하지 않는다.
- 저전력으로 귀환하는 드론의 진행 중 작업은 미완료 실패로 표시한다. 작업을 대기열에 돌려 다른 드론에게 주던 처리를 제거했다.
- 작업 결과에서 초기 담당자·배정 이력·재배정 횟수 필드를 삭제했다. 대규모 재할당 시험과 전용 시나리오 두 개를 제거하고, 배터리 귀환 입력은 단일 드론 미완료 시험으로 바꿨다.
- Release 전체 빌드 성공, 전체 CTest 29/29 통과. `HeadlessCooperativeMissionSmoke`는 재할당에 기대지 않는 두 지점 임무로 확인했다.
- 사용자가 삭제한 X500 안내 파일은 이번 변경에 포함하지 않는다.
