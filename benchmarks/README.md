# 성능 측정 요약

2026년 10월 21일 같은 Windows 컴퓨터에서 Release 빌드로 250 Hz 제어·물리 계산을 10회 측정했습니다. 이번 실행은 회당 1,876 tick을 처리했습니다.

| 항목 | 중앙값 |
| --- | ---: |
| tick p50 | 387.30 μs |
| tick p95 | 508.00 μs |
| tick p99 | 591.00 μs |
| 4 ms 초과 tick | 0회 |

250 Hz 한 주기는 4 ms입니다. 이번 측정에서는 4 ms를 넘긴 계산이 없었습니다. 기존 요약은 p50 316.30 μs, p95 393.85 μs, p99 453.00 μs였습니다. 두 차례 후속 측정의 p50은 339.35~387.30 μs, p95는 503.85~508.00 μs, p99는 591.00~591.80 μs였습니다. 반복별 전체 실행 시간 변동계수도 5.67~11.04%로 높았습니다. tick 수와 측정값이 달라 코드 변경이 원인이라고 단정하지 않습니다.

경로 계획 벤치마크는 현재 10회 반복에서 한 경로를 만드는 데 일반 계획기는 중앙값 50.00 μs, 증분 계획기는 65.63 μs가 걸렸습니다. 두 방식 모두 반복마다 관절 경로 검사 6회를 했고 증분 계획은 모든 반복에서 성공했습니다. 기존 값은 각각 한 번만 측정한 47.08 μs와 62.00 μs이므로, 반복 수가 달라 직접적인 성능 변화로 해석하지 않습니다.

HCR 예제의 URDF·GLB 불러오기는 Release에서 22회씩 10번 측정해 중앙값 25.52 ms, 변동계수 8.58%였습니다. 직전 비교값은 중앙값 24.82 ms, 변동계수 6.83%로, 측정 흔들림이 커서 재질 입력 검사의 성능 영향은 판단하지 않습니다.

결과는 현재 컴퓨터와 HCR 예제 장면에 한정됩니다. 원본 측정값은 날짜별 보관 자료에 남아 있습니다. 다른 입력이나 시나리오의 수치는 직접 비교하지 않습니다.
