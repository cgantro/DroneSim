# 성능 측정 요약

2026년 10월 21일, 같은 Windows 컴퓨터의 Release 빌드에서 Scene 수명 수정 뒤 250 Hz 제어·물리 계산을 10회씩 두 번 측정했습니다.

| 측정 | 회당 tick 수 | tick p50 | tick p95 | tick p99 | 4 ms 초과 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 첫 측정 | 2,198 | 295.45 μs | 346.75 μs | 416.90 μs | 1회 |
| 재측정 | 2,225 | 298.45 μs | 354.40 μs | 414.80 μs | 0회 |

250 Hz 한 주기는 4 ms입니다. 두 번의 측정을 합해 44,230 tick을 확인했고, 첫 측정에서 한 tick이 7.29 ms 걸렸습니다. 그 tick의 물리 계산 구간은 6.89 ms였습니다. 바로 이어 한 재측정에서는 초과가 없었습니다. 한 번의 초과만으로 코드 회귀나 운영체제 지연 중 어느 쪽인지 판단할 수 없으며, 250 Hz 마감 시간을 항상 지킨다고 주장하지 않습니다.

경로 계획 벤치마크는 10회 반복에서 한 경로를 만드는 데 일반 계획기는 중앙값 49.28 μs, 증분 계획기는 65.27 μs가 걸렸습니다. 두 방식 모두 경로마다 관절 상태를 6회 검사했고 증분 계획은 모든 반복에서 성공했습니다. 앞선 요약의 값은 각각 50.00 μs와 65.63 μs였습니다. 측정값의 작은 차이를 코드 변경에 따른 성능 변화라고 단정하지 않습니다.

HCR 예제의 URDF·GLB 불러오기는 Release에서 22회씩 10번 측정해 중앙값 25.52 ms, 변동계수 8.58%였습니다. 직전 비교값은 중앙값 24.82 ms, 변동계수 6.83%로, 측정 흔들림이 커서 재질 입력 검사의 성능 영향은 판단하지 않습니다.

결과는 현재 컴퓨터와 HCR 예제 장면에 한정됩니다. 원본 측정값은 날짜별 보관 자료에 남아 있습니다. 다른 입력이나 시나리오의 수치는 직접 비교하지 않습니다.
