# 성능 측정 요약

2026년 10월 21일 Windows Release 빌드에서 HCR-12A 예제로 측정했습니다. 벤치마크마다 최소 측정 시간은 0.5초, 반복 횟수는 5회입니다. CPU는 20개 논리 프로세서, 3.494 GHz로 표시됐습니다.

| 확인한 작업 | 대표 결과 | 참고 |
| --- | --- | --- |
| 250 Hz 로봇·그리퍼 제어·충돌·물리 계산 | tick p50/p95/p99 중앙값 267.7/315.2/377.8 μs, 최대 tick 중앙값 542.7 μs | 전체 최댓값 1,400.4 μs, 12,815 tick에서 4 ms 초과 0회 |
| URDF·GLB 모델 불러오기 | 중앙값 23.67 ms, 변동계수 7.70% | HCR-12A 모델을 회당 24번씩 5회 불러옴 |
| LM 역기구학 | 중앙값 4.861 μs, 변동계수 0.38% | HCR-12A의 고정 목표와 시작 자세 |
| 실제 충돌 검사를 포함한 경로 계획, 목표 16개 | 전체 중앙값 126.71 ms, 프레임 p95/p99 중앙값 1,532.4/1,576.5 μs | 5개 완료, 프레임당 1.5 ms 초과 중앙값 75회 |
| 실제 충돌 검사를 포함한 경로 계획, 목표 64개 | 전체 중앙값 558.50 ms, 프레임 p95/p99 중앙값 1,517.3/1,567.7 μs | 19개 완료, 프레임당 1.5 ms 초과 중앙값 336회 |

250 Hz 한 tick의 제한 시간은 4 ms입니다. 이번 시험은 한 컴퓨터에서 HCR-12A와 2F-85를 사용했고, 12,815 tick에서 제한을 넘지 않았습니다. 로봇 팔과 그리퍼 제어, 두 충돌 검사, 물리 계산, 계층 변환을 포함합니다. 단계별 시간을 기록하는 타이머는 매 tick 실행하며 화면 그리기와 GUI는 측정하지 않습니다. 따라서 이 결과만으로 다른 컴퓨터나 로봇에서도 항상 4 ms 안에 든다고 보장할 수는 없습니다. 그리퍼를 빼고 측정한 이전 결과와는 범위가 달라 직접 비교하지 않습니다. [이번 측정 원본](archive/2026-10-21/250hz-full-gripper-validation.json)

베이스 충돌 프록시 누락 검사를 추가한 뒤 같은 컴퓨터와 Release 설정, 같은 팔·그리퍼 입력으로 다시 5회 측정했습니다. 총 12,360 tick에서 p50·p95·p99의 회차 중앙값은 265.5·312.0·374.5 μs였고, 최대 tick은 1,237.9 μs였습니다. 4 ms를 넘긴 tick은 없었습니다. 앞선 측정은 총 12,815 tick에서 267.7·315.2·377.8 μs, 최대 1,400.4 μs였습니다. 차이가 작고 실행 시점도 달라 코드 변경으로 인한 성능 향상이라고 단정하지 않습니다. [재측정 원본](archive/2026-10-21/250hz-after-base-proxy-check.json)

모델 불러오기는 GLB 메시 변환 정리 뒤 다시 측정했습니다. 앞선 기준 측정은 회당 22번, 이번 측정은 24번 불러왔습니다. 중앙값은 24.53 ms에서 23.67 ms로 바뀌었지만 반복 횟수가 달라 정확히 같은 조건으로 볼 수 없습니다. 변동계수도 7% 안팎이므로 이번 코드 정리로 불러오기가 빨라졌다고 판단하지 않습니다. 원본 측정은 [보관 자료](archive/2026-10-21/glb-refactor-validation.json)에서 확인할 수 있습니다.

경로 계획은 목표를 찾는 도중 정한 1.5 ms 프레임 예산을 여러 번 넘겼습니다. 충돌로 거부된 목표가 있으므로 완료 개수만으로 도달률을 판단하지 않습니다.

이번 측정은 변경 전과 조건을 맞춘 비교가 아닙니다. 따라서 성능이 개선됐다고 결론 내리지 않습니다. 이전 측정과 상세 결과는 날짜별 보관 자료에 유지합니다.

프레임 예산 초과 원인을 살피려고 별도 진단 측정을 10회 반복했습니다. 1.5 ms를 넘은 프레임은 있었지만, 한 번의 계획 호출이 1.5 ms를 넘지는 않았습니다. 측정한 호출 중 500 μs를 넘은 경우는 목표 16개와 64개에서 각각 한 번이었고, 최댓값은 731 μs와 1,035 μs였습니다. 이 진단은 각 호출에 타이머를 추가하므로 프레임 시간은 기존 표와 직접 비교할 수 없습니다. 자세한 값은 날짜별 보관 자료에 기록했습니다.
