# 성능 측정 요약

2026년 10월 21일, 같은 Windows 컴퓨터의 Release 빌드에서 Scene 수명 수정 뒤 250 Hz 제어·물리 계산을 10회씩 두 번 측정했습니다.

| 측정 | 회당 tick 수 | tick p50 | tick p95 | tick p99 | 4 ms 초과 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 첫 측정 | 2,198 | 295.45 μs | 346.75 μs | 416.90 μs | 1회 |
| 재측정 | 2,225 | 298.45 μs | 354.40 μs | 414.80 μs | 0회 |
| 배치 검사 정리 뒤 | 2,308 | 293.15 μs | 342.15 μs | 401.75 μs | 0회 |

250 Hz 한 주기는 4 ms입니다. 앞의 두 측정은 합해 44,230 tick을 확인했고, 첫 측정에서 한 tick이 7.29 ms 걸렸습니다. 그 tick의 물리 계산 구간은 6.89 ms였습니다. 바로 이어 한 재측정에서는 초과가 없었습니다. 이후 물리 배치 조건을 한 함수로 모은 변경 뒤 10회 측정에서는 회당 중앙값 기준 2,308 tick을 확인했고, p99는 401.75 μs, 최대 tick은 545.55 μs였습니다. 이 측정은 변경 전후를 바로 붙여 비교한 실험이 아니므로 성능이 개선됐다고 판단하지 않습니다. 한 번의 초과만으로 코드 회귀나 운영체제 지연 중 어느 쪽인지 판단할 수 없으며, 250 Hz 마감 시간을 항상 지킨다고 주장하지 않습니다.

같은 Windows PC에서 HCR-12A 예제로 250 Hz Release 측정을 조건마다 10회씩 반복했습니다. 변환 갱신 코드를 바꾸기 전 tick p50/p95/p99는 281.8/331.8/400.5 μs였습니다. 바꾼 뒤 첫 측정은 159.2/187.4/247.5 μs, 재측정은 158.3/188.1/245.5 μs였습니다. 두 변환 갱신 구간의 p95는 기존 131.6/123.1 μs에서 첫 측정 50.1/54.2 μs, 재측정 51.6/53.7 μs로 줄었습니다. 두 값은 각각 충돌 검사 전과 물리 계산 뒤 구간입니다. 세 번의 측정 모두 4 ms를 넘긴 tick은 없었습니다. 이 결과는 해당 PC의 HCR-12A 예제에 한정되며, 다른 모델이나 실제 장비의 성능을 보장하지 않습니다.

경로 계획 벤치마크는 10회 반복에서 한 경로를 만드는 데 일반 계획기는 중앙값 49.28 μs, 증분 계획기는 65.27 μs가 걸렸습니다. 두 방식 모두 경로마다 관절 상태를 6회 검사했고 증분 계획은 모든 반복에서 성공했습니다. 앞선 요약의 값은 각각 50.00 μs와 65.63 μs였습니다. 측정값의 작은 차이를 코드 변경에 따른 성능 변화라고 단정하지 않습니다.

검사 완료 처리를 두 경로로 나눈 뒤 Release 벤치마크를 같은 조건에서 10회 측정했습니다. 일반 경로의 중앙값은 변경 전 49.58 μs, 변경 뒤 50.10 μs였습니다. 증분 경로는 65.30 μs에서 65.33 μs로 측정됐습니다. 두 측정 모두 10회 전부 경로가 생성됐고, 관절 상태 검사 횟수와 FK 오차도 같았습니다. 차이는 측정 흔들림 범위에 있어 속도가 달라졌다고 판단하지 않습니다. 원본 측정값은 날짜별 보관 자료에 남겼습니다.

증분 계획 작업이 끝날 때 임시 자료와 참조를 정리한 뒤에도 같은 Release 입력으로 10회 측정했습니다. 경로당 중앙값은 66.72 μs였고, 한 작업 조각의 p50/p95/p99는 48.30/53.20/85.00 μs였습니다. 앞선 원본 측정은 각각 67.19 μs와 48.30/51.45/98.85 μs였습니다. 전체 시간과 작업 조각 결과가 엇갈려 이번 변경의 성능 효과를 판단할 수 없으며, 10회 모두 경로를 완성했습니다. 원본 측정값은 날짜별 보관 자료에 추가했습니다.

HCR 예제의 URDF·GLB 불러오기는 Release에서 22회씩 10번 측정해 중앙값 25.52 ms, 변동계수 8.58%였습니다. 직전 비교값은 중앙값 24.82 ms, 변동계수 6.83%로, 측정 흔들림이 커서 재질 입력 검사의 성능 영향은 판단하지 않습니다.

HCR-12A 예제의 고정 목표와 시작 자세로 Release에서 LM 역기구학을 10회씩 측정했습니다. 조건수 계산을 Eigen으로 바꾸기 전 중앙값은 4.829 μs, 바꾼 뒤는 4.808 μs였습니다. 변동계수는 각각 1.17%, 0.39%였습니다. 이 성공 경로는 실패 진단용 조건수 계산을 실행하지 않으므로 변경한 계산의 속도를 비교한 결과는 아닙니다. 두 수치는 일반적인 성공 경로의 기준값이며, 차이만으로 성능 개선을 판단하지 않습니다.

실제 URDF 충돌 형상과 Jolt 검사를 포함해 Release 포즈 계획을 10회 측정했습니다. 목표 16개 묶음은 중앙값 129.60 ms였고, 그중 5개가 완료됐습니다. 환경 충돌 6개, 자가 충돌 1개, 기타 실패 4개가 나왔습니다. 목표 64개 묶음은 569.60 ms였고, 19개가 완료됐습니다. 환경 충돌 23개, 자가 충돌 4개, 기타 실패 18개였습니다. 계획 한 프레임에 쓴 시간 p50/p95/p99는 16개 묶음에서 1501.7/1515.7/1590.5 μs, 64개 묶음에서 1501.9/1520.5/1582.0 μs였습니다. 마지막 계산 단위가 끝난 뒤 시간을 확인해 1.5 ms를 넘긴 구간이 나왔습니다. 목표 16개 묶음에서는 매회 75~80회, 64개 묶음에서는 339~344회 초과했습니다. 측정은 이 PC의 HCR-12A 예제와 생성한 목표 묶음에 한정됩니다. 충돌 검사에서 거부된 목표가 있어 완료 건수만으로 도달률을 해석하지 않았습니다.

결과는 현재 컴퓨터와 HCR 예제 장면에 한정됩니다. 원본 측정값은 날짜별 보관 자료에 남아 있습니다. 다른 입력이나 시나리오의 수치는 직접 비교하지 않습니다.
