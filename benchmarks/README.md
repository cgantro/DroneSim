# 성능 측정 요약

2026년 10월 21일 Windows Release 빌드에서 HCR-12A와 2F-85를 측정했습니다. 컴퓨터는 20개 논리 프로세서, 3.494 GHz로 표시됐습니다. 벤치마크별 측정 시간은 0.5초, 반복 횟수는 5회였습니다.

| 작업 | 측정 결과 |
| --- | --- |
| 250 Hz 제어·충돌·물리 계산 | 12,815 tick의 p50/p95/p99 중앙값은 267.7/315.2/377.8 μs였습니다. 가장 긴 tick의 회차 중앙값은 542.7 μs, 전체 최댓값은 1,400.4 μs였고 4 ms 초과는 없었습니다. |
| URDF·GLB 불러오기 | HCR-12A를 회당 24번씩 불러온 중앙값은 25.03 ms였습니다. |
| LM 역기구학 | 고정 목표와 시작 자세에서 중앙값은 4.861 μs였습니다. |
| 충돌을 포함한 경로 계획, 목표 16개 | 전체 시간 중앙값은 126.71 ms였습니다. 프레임 p95/p99 중앙값은 1,532.4/1,576.5 μs였고, 1.5 ms를 넘긴 프레임은 회차 중앙값 75회였습니다. |
| 충돌을 포함한 경로 계획, 목표 64개 | 전체 시간 중앙값은 558.50 ms였습니다. 프레임 p95/p99 중앙값은 1,517.3/1,567.7 μs였고, 1.5 ms를 넘긴 프레임은 회차 중앙값 336회였습니다. |

## 확인된 제한

250 Hz 제어 tick은 이번 측정에서 4 ms 제한을 넘지 않았습니다. 다만 이 결과는 한 컴퓨터에서 특정 모델로 얻은 값이며, 화면 그리기와 GUI 시간은 포함하지 않습니다. 다른 컴퓨터나 로봇에서도 같은 결과가 난다고 보장하지 않습니다.

경로 계획은 프레임당 1.5 ms 예산을 여러 번 넘었습니다. 별도 진단에서는 목표 16개와 64개 모두 단일 계획 호출이 1.5 ms를 넘지 않았지만, 계획 작업을 끝내는 프레임은 예산을 초과했습니다. 계획 작업은 중간에 끊을 수 없어 마지막 작업 단위가 프레임 예산을 넘길 수 있습니다. 진단 타이머가 호출마다 추가되어 프레임 시간은 위 표와 직접 비교할 수 없습니다.

후속 제어 측정은 4,970 tick에서 p50/p95/p99 중앙값 271.6/344.2/397.5 μs, 최장 tick 중앙값 608.6 μs를 기록했고 4 ms 초과는 없었습니다. 측정 조건이 달라 위 결과와 성능 개선 여부를 비교하지 않습니다.

표에 싣지 않은 변경별 측정값과 원본 결과는 날짜별 보관 자료에 남겨 두었습니다. 반복 조건이 다르거나 편차가 측정 차이와 비슷한 결과로는 성능 향상이나 저하를 단정하지 않습니다.
